## 8. Coverage — measured, **and it has a band**

```
$ make coverage
Required test coverage of 85.0% reached. Total coverage: 96.21%
1196 passed in 473.58s (0:07:53)

$ make coverage          # the same command, the same tree, again
Required test coverage of 85.0% reached. Total coverage: 96.10%
1196 passed in 508.42s (0:08:28)
```

**96.21 % and 96.10 % on the same tree.** Pinning the command was necessary and **not sufficient**,
and this is the rest of A3.

### 8.1 The cause, and one module carries all of it

```
 d(unc) module                          run1  run2
     +9 receiver.py                       24    33

total drift between two runs of the SAME tree: +9 uncovered units = 0.11 points
```

`tests/test_receiver.py` carries two `@given(st.binary(min_size=0, max_size=300))` properties
feeding random byte strings to the BER trap decoder. **Hypothesis generates different examples on
every run** — no `derandomize`, no seeded profile — so which malformed-datagram branches in
`receiver.py` get exercised varies. **Nothing else in the suite drifts at all.**

**Not fixed, and DECISIONS #159 records why**: derandomising trades a real fuzzer for a stable
number, and the value of `st.binary` against a BER decoder is that it tries inputs nobody thought
of. That is A3's own instruction — *do not write tests to buy the number back* — one register up.

### 8.2 The movement, attributed exactly

```
v0.9.2    units  7592  uncovered  289  -> 96.19%
v0.10.0   units  8128  uncovered  329  -> 95.95%
v0.10.1   units  8173  uncovered  310  -> 96.21%   (96.10% on the second run)

 d(unc) module                             units  unc    cov%
    -14 census.py                             69    1   98.6%
     -9 receiver.py                          259   24   90.7%
     +0 agreement_bags.py                     87    0  100.0%
     +2 incidents.py                          89    2   97.8%
     +2 shadow_cv.py                          88    4   95.5%
```

* **`census.py` 78.6 % → 98.6 %** is the release's largest single coverage movement, and it was not
  bought: the three tests closing mutation survivors A8/A9/A10 exercise `resolve_identity` and
  `first_label_per_incident` on merged corpora that nothing had exercised, and `_ = identity` is
  gone.
* **`receiver.py`'s −9 is the band**, not a change — §8.1. Nothing in this release touches it.
* `incidents.py` and `shadow_cv.py` each gained 2 uncovered units against substantially more code:
  `incidents.py` 89 units at 97.8 %, `shadow_cv.py` 88 at 95.5 %.

**Against v0.9.2's like-for-like 96.19 %, this release measures 96.21 % / 96.10 % — at or about the
baseline, inside the band.** The v0.10.0 dip to 95.95 % is 0.24 points, about two bands: **probably
real and not established on one measurement per release.** Stated that way rather than as a
regression, because one sample does not support more.
