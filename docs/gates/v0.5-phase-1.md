## Gate 1 criteria

- **Scope and deferred list complete and consistent.** `docs/SCOPE-0.5.md` states the theme
  (structure/organization/growth-readiness, no engine change), the delivery model (no push/CI/
  account dependency), the exactly-five workstreams, and the seven deferred items **in the §3
  order** (v0.6.0 features → SNMPv3 → `/metrics` → pcap/webhook → typed relations/subsumption/
  device_id cutover → `OPTICORR_*` removal → publishing/signing), each a ROADMAP line. The hard
  constraints (zero new runtime deps, one process/file/UI, no over-split, `git mv` history, no
  ADR renumbering) are restated.
- **The alias-window decision is recorded.** DECISIONS #39 documents the extension of the
  `OPTICORR_*` deprecation window from v0.5.0 to v0.6.0 as the release's only behaviour-adjacent
  decision — a *non-removal*. The warning strings in `main.py` and `__main__.py` and the
  `MIGRATION.md`/`README.md`/`ROADMAP.md` prose now say "v0.6.0". The alias regression tests
  (`test_settings_legacy_env_alias_still_works`, `test_audit_export_cli`,
  `test_settings_new_env_takes_precedence_over_legacy`) pass — they assert the warning's presence
  and the variable names, not the version string.
- **The v0.6.0 draft names the three surfaces and gives each its security framing.**
  `EXTENSIBILITY-0.6-DRAFT.md` names `rbac.py` (RBAC map), `shaping.py` (visibility serializer),
  and `correlate.py` (`W_T`/`W_A`/`W_E`/`TAU_S`/`LINK_THRESHOLD`, with `tau`/`threshold` already
  instance fields), marks every element `v0.6.0: planned`, and specifies: admin-configurable RBAC
  within a fixed role ceiling (single source, deny-by-default, 401/403/404, audited, sessions
  re-evaluate, role changes revoke sessions); per-role/per-principal visibility scoping (fail
  closed, audited, 404-not-403, no existence oracle); and a configurable/pluggable match formula
  (built-in default = safe fallback; bounded/validated parameters read off the hot path; the
  external criterion API as opt-in, allowlisted, hard-timeout, bounded-contract, fail-safe, never
  in `datagram_received`, fully audited — flagged as the riskiest roadmap idea). Each section lists
  the threat-model entries v0.6.0 must add.
