# Gate 2 — v0.7.5 F42: the gate refuses what it cannot check

**Status: passed.**

## 1. The change

`src/netcorenoc/api/declare.py`, +79 lines. Three parts, no new abstraction:

1. **`KNOWN_ROUTE_SHAPES: tuple[type, ...] = (APIRoute, Route)`** — the route classes the traversal
   knows how to check.
2. **A refusal.** Any object on `app.routes` whose type is not exactly one of them raises
   `UndeclaredRouteError` naming `type(route).__module__`, `type(route).__name__`, and where
   registration belongs.
3. **The narrowed verb exemption.** `HEAD` is skipped **only when `GET` is present on the same
   route**; the `OPTIONS` exemption is **removed outright**.

Matched on **exact type**, not `isinstance`. `APIRoute` subclasses `Route`, so an `isinstance` test
would silently admit any future subclass of either — the same fail-open-on-the-unknown this finding
is about, one inheritance level down. DECISIONS #98.

`create_app` is **not** edited: the assertion is still its last statement before `return app`, and
`test_f40_the_assertion_runs_before_create_app_returns` still parses the source to prove it.

One typing note, recorded because it is the only place the diff is not self-evident: `mypy --strict`
rejects `route.path` on `app.routes` (typed `list[BaseRoute]`). The narrowing is a `cast(Route, ...)`
rather than an `assert isinstance(...)` — zero runtime cost, and no `python -O` question inside a
security guard. The comment beside it notes that being able to read `.path` and `.methods` as
declared attributes rather than `getattr` guesses is precisely what the allowlist buys.

## 3. The reproduction re-run against the fixed gate

The Phase 0 script, unchanged, on the repaired tree:

```
[CONTROL] an untouched app -- the gate must raise nothing
  gate: returned cleanly (NO REFUSAL)
[SHAPE 1] app.include_router(...)
  gate: REFUSED -- fastapi.routing._IncludedRouter is a route shape this gate cannot check, so it
        is refused rather than skipped (F42). Registration goes through
        netcorenoc.api.declare.DeclaredRoutes, which produces a fastapi.routing.APIRoute. …
[SHAPE 2] app.mount() with a sub-application
  gate: REFUSED -- starlette.routing.Mount is a route shape this gate cannot check …
[SHAPE 3] app.mount() with StaticFiles
  gate: REFUSED -- starlette.routing.Mount is a route shape this gate cannot check …
[SHAPE 4] app.add_api_websocket_route(...)
  gate: REFUSED -- fastapi.routing.APIWebSocketRoute is a route shape this gate cannot check …
[SHAPE 5] an explicitly-registered HEAD-only route
  gate: REFUSED -- HEAD /api/undeclared-head is not declared in rbac.ROUTE_PERMISSIONS and
        rbac.ROUTE_SCOPE. …
```

Note the difference in shape 5's message, which is not cosmetic: shapes 1–4 are refused **by the
shape allowlist** and shape 5 by **`require_declaration` itself**, because a `HEAD`-only route is a
perfectly ordinary `APIRoute` — a known shape whose verb the old exemption waved through. The two
halves of the fix are visible in the two messages.

## 4. The live app's shape set equals the allowlist

`test_f42_the_live_app_produces_exactly_the_known_shapes` builds a **real** `create_app` and asserts
`{type(route) for route in app.routes} == set(KNOWN_ROUTE_SHAPES)`:

```
fastapi.routing.APIRoute      (every route DeclaredRoutes registers)
starlette.routing.Route       (/openapi.json, registered by FastAPI itself)
```

Exactly two shapes, 48 method/path pairs, all passing. This is §4.4's half — the one that
generalises. Its failure message tells a future maintainer **not** to widen the tuple until the
traversal can check every path and method the new shape carries, because widening it without that is
how the hole reopens.

**Its limit is stated in its own docstring and on `docs/ROADMAP.md`:** it detects a **new shape**,
not a **changed meaning**. If a future `APIRoute` carried its verbs somewhere other than `.methods`,
the shape set would be unchanged and the gate would quietly check nothing. No test in this release
closes that.

## 6. `MODULE-ARCHITECTURE.md` §10.1, superseded in place

§10.1 specified F40's fix and called it *"complete by construction"*. That claim is what F42
corrects, and leaving it standing would have left the binding architectural authority asserting
something the security review now denies. A dated correction note is appended **without rewriting
the original paragraph** — the project's "supersede in place, never rewrite" rule, the same
treatment §10.2 received in v0.7.4.

`SECURITY-REVIEW-0.7.4.md` is **not** edited. It is the record of what was believed then; the
correction belongs in `SECURITY-REVIEW-0.7.5.md` (Phase 6).
