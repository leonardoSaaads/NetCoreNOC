Union → **`AppContext` carries exactly**: `engine`, `store`, `perimeter`, `security`, `guarded`,
`audit_row`, `scope_for`, `all_warnings`, `write_txn`, `governance`, `preview_limiter`,
`throttle`, `extra_stats`, `runtime`, `tls_enabled` — the fifteen fields the build prompt names,
confirmed empirically rather than adopted on trust. `situation_in_scope` and `audit_scope_denial`
are reached as `ctx.perimeter.<name>`, which is why the field list needs no sixteenth entry.

Two dependencies the AST scan does **not** show, because they live in argument defaults rather
than in bodies, and which matter more than any of the above:

* `principal: auth.Principal = Depends(security)` — **31 handlers**. This is why `security` must
  be rebindable to a local name of exactly that spelling in every route module.
* `dependencies=guarded` — **8 handlers** (`classes`, `state_clears`, `list_users`, `list_tokens`,
  `get_config`, `get_scorer`, `get_rbac_policy`, `get_scope_policy`).

Module-level `_client_ip` is called by `audit_row`, `security`, `login` and `preview_scorer`; it
lives in `perimeter.py` and `routes_auth`/`routes_scorer` import it by name, so those two handler
bodies stay textually identical.

### 5.2 Addendum (added during Phase 3) — the **body** hash table, the baseline Phase 5 uses

The table in §5 hashes what `inspect.getsource(endpoint)` returns, which **includes the decorator
line**. Workstream 3 replaces `@app.get("/api/x")` with `@route.get("/api/x")` on every handler, so
that table cannot survive this release by construction — and a proof that changes for the intended
reason cannot distinguish the intended reason from an unintended one.

* **body hash** (below) — `sha256` of the handler from its `def`/`async def` line to its last line:

## 7. The route/permission join as it stands today

* **Where it is consulted.** `api.py:484` — `permission = rbac.permission_for(method, path)` inside
  the `security` dependency, using `_route_path(request)` (the **templated** path from
  `request.scope["route"]`, not the concrete URL).
* **How a missing entry fails today.** At **runtime, per request**: `permission_for` returns `None`,
  `None not in capabilities` is true, and line 498 raises `403 insufficient role`. Fail-closed but
  invisible until someone calls the route. `AUDITED_DENIED_PERMISSIONS` does not contain `None`, so
  an undeclared route's denial is not even audited.
* **Which test enforces completeness.** `tests/test_rbac.py::test_every_api_route_is_in_the_permission_map`
  — walks `app.routes`, skips `HEAD`/`OPTIONS` and `PUBLIC_ROUTES`, and fails CI on an unmapped
  `/api` route. Second-line defence: `tests/test_rbac.py::test_authorization_matrix` generates the
  whole matrix from `ROUTE_PERMISSIONS`.

Workstream 3 changes the **timing** of the first failure (runtime → app construction, i.e. before
the process can serve) and adds a second declaration (`ROUTE_SCOPE`) that does not exist at all
today. It changes neither the authority (`rbac.py`) nor the completeness tests, which are
**extended with a sibling, not replaced**.

Derived from the closure graph (§4): a route is `scoped` iff its handler reaches `scope_for`.
Twelve do; five viewer/editor routes do not; the remaining twenty-two are `admin_only` because
their capability's minimum role is `admin` in `PERMISSIONS` and **admin is never scoped**
(DECISIONS #58). This is the table Phase 3 writes and the posture test proves.
