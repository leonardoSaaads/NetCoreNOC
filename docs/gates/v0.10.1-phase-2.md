# v0.10.1 — Gate 2: the three consolidations

Each of these closes a **class** rather than an instance. B1 fixes the last two consumers; B2 makes
a third one unwritable; B3 ties a pin to the thing it pins and makes a probe live that was inert.

---

## 1. B1 — the last two consumers of incident identity

### 1.1 What changed

`agreement.py:277` and `bias.py:140` computed identity with `COALESCE(s.merged_into,
f.situation_id)` — **one hop**. v0.10.0 named them rather than fixing them, correctly: Workstream 1
scoped `store/shadow.py`, and a fix inside a move is forbidden. This release is the scope.

**`agreement.py`** — the bag query returned `AS incident`; it now returns `situation_id`, the
`situation` join is gone with it, and `load_bags` reads the merge **edges** and resolves them:

```diff
-       COALESCE(s.merged_into, f.situation_id)     AS incident,
+       f.situation_id                              AS situation_id,
        COUNT(p.id)                                 AS pairs,
 FROM feedback f
-LEFT JOIN situation s ON s.id = f.situation_id
 LEFT JOIN dataset_pair p
```
```diff
+    rows = [dict(r) for r in await cur.fetchall()]
+    edges = await store.merge_edges()
+    identity = resolve_all(sorted({int(r["situation_id"]) for r in rows}), edges)
+    stamp(rows, identity)
```

**`bias.py`** — `distinct_incidents` was a `COUNT(DISTINCT COALESCE(...))`; it is now
`(await _incident_map(store)).incidents`, over the labelled situations and the same edges.

**Four consumers, one implementation.** `store/shadow.py` exposes the edges and decides nothing;
`census.py`, `bias.py` and `agreement_bags.py` each resolve through
`netcorenoc.incidents.resolve_all`. `incidents.stamp` is still the only step that produces an
`incident` key, so a consumer that forgets has **no key at all** and fails loudly rather than
reading a quietly one-hop one.

### 1.2 Both frozen reports are byte-identical

```
$ .venv/bin/python -m pytest -q tests/test_agreement.py tests/test_bias.py
....................                                                     [100%]
20 passed in 2.32s
```

**No number moved**, which on this corpus is the expected result and not a reassurance: every merge
chain in it is exactly one hop (`v0.10.0-phase-1.md` §5.1: four edges, all one hop), so the one-hop
and transitive answers coincide at 37 incidents. The byte-for-byte expectations were re-read before
the run rather than after, as DECISIONS #139 requires; there was nothing to re-freeze because
nothing changed.

**That coincidence is the hazard, not the comfort.** A corpus with a two-hop chain makes the four
consumers disagree with **nothing going red** — the frozen reports would each be internally
consistent, and two of the four are the estimator and the seal. Which is exactly why B2 exists.

### 1.3 `agreement.py` was split, and the ceiling was not raised

Routing identity through `incidents` took `agreement.py` to **402 lines of a 400-line ceiling**.
Raising a guard to fit a corrective release is a thing this project has never done, so the module
was split.

| module | lines | owns |
|---|---:|---|
| `agreement.py` | **265** | what is *measured over* a set of bags — rates, the cluster bootstrap, the six cuts, operator anonymisation |
| `agreement_bags.py` | **178** | what a bag *is* and where one comes from — the row shape, the size bucketing, the query, and the incident resolution reading one now requires |

The seam is real rather than arithmetic, and **B1 is what made it load-bearing**: before this
release the second half was a `COALESCE` in a select list and there was nothing to own. It is the
third time the project has split on this seam — `bias.py`/`bias_labels.py`,
`shadow.py`/`census.py` — and `agreement.py` re-exports `Bag`, `size_bucket` and `SIZE_ORDER`
because `agreement_report.py` and `tests/test_agreement.py` have imported them from there since
v0.9.0. **A split is not a reason to move a caller's import** (DECISIONS #155).

`DEBT_ALLOWLIST` is still empty; `COHESION_EXEMPT` is still `engine.py` alone at 580; `engine.py` is
still 569.

## 2. B2 — the expression is forbidden, not merely fixed where it was found

### 2.1 The guard

`tests/test_incidents.py::test_no_module_computes_incident_identity_in_sql` parses every module in
the package and asserts that **no non-docstring string constant contains both `COALESCE` and
`merged_into`**. Not "the four known consumers are fixed" — *the expression cannot be written*, so a
fifth consumer fails here rather than having to be found.

**`ast`, not `grep`, and this is Appendix B's trap in its purest form.** Six prose mentions of the
exact expression exist in the package right now:

| module | form |
|---|---|
| `bias.py:159` | `#` comment |
| `census.py:43` | `#` comment |
| `census.py:82` | docstring |
| `store/shadow.py:37` | docstring |
| `incidents.py:8`, `incidents.py:149` | docstrings — in the module that exists to replace it |
| `shadow_render.py:184` | `#` comment |
| `agreement_bags.py:147` | docstring |

A grep reports eight offenders and gets switched off. The extractor subtracts docstrings **by object
identity** rather than by keyword — `incidents.py`'s own docstring quotes the expression while being
its replacement — and `#` comments never reach the tree at all, which handles three of them for
free. `tests/test_seal.py::test_the_store_exposes_the_membership_through_exactly_one_expression` is
the model and its discipline is inherited exactly.

### 2.2 The vacuity check, which the guard cannot do for itself

`assert not offenders` passes just as happily when `offenders` is empty because nothing was scanned,
because the parse silently returned nothing, or because the substring test was inverted. **Without a
vacuity check a broken extractor reports every module clean.**

`test_the_expression_extractor_finds_the_expression_where_it_is_known_to_exist` runs **the same
extractor function** — not a second implementation, which would only prove that *some* extractor
works — over a fixture carrying the expression three times: in a module docstring, in a `#` comment,
and in a SQL literal. It must find **exactly one**, and it must be the SQL one.

### 2.3 The control the guard structurally cannot be

A package where every consumer had simply *stopped counting incidents* would pass §2.1 perfectly.
`test_all_four_consumers_resolve_identity_through_the_one_implementation` asserts the other side by
AST: `census.py`, `bias.py` and `agreement_bags.py` each call `resolve_all`, two of them also call
`stamp`, and `store/shadow.py` still exposes `merge_edges`.

### 2.4 What only this guard can catch

Restoring either one-hop `COALESCE` moves **no number on this corpus** — the frozen reports stay
byte-identical, the eval hash is untouched, and every other test stays green. B2's guard is the only
thing in the repository that goes red. That is the entire argument for it: *a guarantee whose
failure is invisible has to be structural.*

## 3. B3 / F49 — the pinned SQL, tied both ways

### 3.1 Repair 1 — the constant is tied to the file

`tests/test_evidence_boundary_f48.py` pins migration `0011`'s backfill expression as a Python
constant, because a migration cannot be re-run against an already-migrated database.
`test_the_pinned_expression_is_the_migrations_own` normalises whitespace and asserts the pinned text
is a substring of `0011_evidence_boundary.sql`.

Compared **up to the `WHERE`**, because that clause legitimately differs — the test binds a
parameter (`= ?`) where the migration correlates to the row it updates (`= feedback.id`). Everything
F49 is about, the join and its `AND m.source = 'server'` predicate, is inside the compared span, and
the test asserts that before it asserts the match.

**Its control had to be rewritten once, and the reason is worth recording.** The obvious control —
*"the predicate-free expression must not match"* — is **wrong**, and fails on a healthy tree:
deleting a trailing clause leaves a **prefix**, and every prefix is a substring. The question worth
asking is F49's own: *if the predicate is deleted from the migration, does the pin go red?* So
`test_the_tie_would_notice_a_predicate_deleted_from_the_migration` performs the deletion on an
in-memory copy and evaluates the tie's assertion against it, having first asserted the predicate
occurs **exactly once** in the file.

**Stated limitation**: a substring tie is directional. It detects a *deletion* from the migration,
which is the measured failure mode. It would not detect an *addition* elsewhere in the file that
changed the backfill's meaning without touching this span.

### 3.2 Repair 2 — the upgrade fixture gets a client fingerprint

`test_upgrade.py`'s v0.9.1 fixture wrote only the **server** side of `feedback_member`. With no
client rows the `AND m.source = 'server'` predicate had nothing to exclude, and an unfiltered join
returned the same answer — so the upgrade path was an **inert probe** whose docstring claimed a
boundary it was not exercising.

The fixture now writes the client's reported bag, **containing the ghost id**, through the same
v0.9.1 store method (`add_feedback_members(split.id, "client", …)`). That is the real case rather
than a contrived one: a browser whose view is stale reports a member the server's bag no longer
holds and marks it — F48's premise, and what the v0.7.5 SSE teardown produced routinely.

With the row present the predicate has work to do: **filtered, the ghost joins nothing and the
backfill writes 2; unfiltered, the ghost joins its own client row and writes 3.**

### 3.3 The injection — the predicate deleted from `0011_evidence_boundary.sql` itself

```
### INJECTION F49-a: the predicate deleted from 0011_evidence_boundary.sql
FAILED tests/test_evidence_boundary_f48.py::test_the_pinned_expression_is_the_migrations_own
FAILED tests/test_evidence_boundary_f48.py::test_the_tie_would_notice_a_predicate_deleted_from_the_migration
FAILED tests/test_upgrade.py::test_v092_upgrade_reconciles_and_leaves_tier_three_null
3 failed, 11 passed in 3.09s

### and against the WHOLE suite (v0.10.0 measured 1093 passing here):
3 failed, 1188 passed in 227.17s (0:03:47)
```

**Both repairs go red, independently and for different reasons** — the first because the constant no
longer matches the file, the third because the upgraded database now computes 3 where the fixture
asserts 2. Either alone would have caught it; shipping both means the tie survives a fixture change
and the probe survives a refactor of the constant.

The middle line is the control failing on its **precondition** (`count(...) == 1`, and the predicate
is gone), which is the honest thing for it to do: it is a statement about a healthy tree and says so
rather than passing vacuously on a broken one.

**v0.10.0 measured 1093 tests passing under this exact injection. Three fail now.**
