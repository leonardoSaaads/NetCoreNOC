## Load test — `make loadtest` (1000 traps/s × 60 s)

Synthetic burst (20 devices × 10 classes × 8 instances) against a running instance,
with the API polled every 3 s throughout:

- **Zero loss**: received = accepted = 60,001; dropped = 0; queue drained to 0.
- **Receiver stays responsive**: every API poll answered (12–786 ms) during the burst.
- **p95 trap→situation latency**: peaked at ~4.8 s during the initial 1600-alarm
  activation wave, converging to **0.02–0.6 s in steady state** (0.04 s at burst end).
- Memory: ~69 MB RSS after the burst. Situations remained correct (1600 active alarms,
  3 storm components, no false clears).

Two defects found by this test were fixed with regression tests:

1. **False raise/clear pairs under storm load** — random class interleavings looked
   like strict alternation and mass-cleared real alarms. Alternation learning now
   pauses while the window is in storm state (Decision 13).
2. **`cannot commit transaction - SQL statements in progress`** — an API cursor
   interleaving with the engine's batch commit killed the engine. All store access now
   serializes under one asyncio lock (Decision 12,
   `test_concurrent_api_reads_during_ingest`).

## Simulated soak — mixed replay with retention

120 s of repeated mixed waves (fiber cut + 120-alarm storm slice + background noise +
linkDown/linkUp flapping + malformed packets) at ~13 traps/s with
`OPTICORR_RETENTION_DAYS≈0.0007` (60 s) to exercise pruning:

| t (s) | RSS (KB) | alarms | situations | links | quarantine |
|------:|---------:|-------:|-----------:|------:|-----------:|
| 15 | 51,296 | 153 | 27 | 616 | 20 |
| 60 | 51,408 | 153 | 59 | 616 | 80 |
| 120 | 51,480 | 153 | 36 | 731 | 80 |

- **Stable memory**: +0.4% RSS over the run.
- **No unbounded growth**: alarm rows capped by fingerprints (dedup), situations and
  quarantine visibly pruned by the retention job, learned edges stable, links bounded
  by the 5-per-alarm cap. (An earlier 180 s run showed the same shape: situations
  75→9, quarantine 100→60 across prune passes.)

## Security pass (SCOPE baseline)

- **Allowlist enforced**: denied sources counted and dropped
  (`test_allowlist_denies_and_counts`); default allow-all is the zero-config choice
  (Decision 4).
- **Quarantine fuzz-tested**: hypothesis feeds random binaries to the parser and the
  datagram callback; everything either parses or quarantines with a reason.
- **API token required**: 401 without/with wrong token; token autogenerated and logged
  once when unset (verified in the quickstart check below); constant-time compare;
  per-client rate limiting returns 429.
- **Non-root container**: Dockerfile creates uid 10001 and sets `USER opticorr` before
  the entrypoint. A full image build could not be executed in this build sandbox — the
  network policy blocks the Docker registry (`registry-1.docker.io: Forbidden`); the
  Dockerfile is two stages of stock `python:3.12-slim` with `pip install .` and is
  exercised by CI-equivalent steps outside the image.
- **Zero secrets in code**: bandit clean (targeted `# nosec` with justifications;
  B101 skipped via config for internal invariant asserts); pip-audit clean.
