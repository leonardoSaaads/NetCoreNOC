## 8. Upgrade — a real v0.7.4 database opened by v0.7.5

Not a simulation: a **git worktree at commit `b2ea0f7`** (the v0.7.4 release) was checked out, and
the database was written by **that** code — real `TrapEvent`s through the real `Engine.run()` loop,
a real user and API token, and a chained audit row written with the project's own
`audit.write_event`.

```
$ PYTHONPATH=<v0.7.4>/src python upgrade_check.py write  upgrade.db     # processed=16
$ PYTHONPATH=<v0.7.5>/src python upgrade_check.py verify upgrade.db
$ diff v074.json v075.json
*** IDENTICAL ***
```

| Check | Result |
|---|---|
| Migrations applied on open | **none** — still 7, `Store.open()` finds nothing pending |
| Schema (every table, index and view, normalised SQL) | **identical** |
| Row counts, all 25 tables | **identical** — 16 alarms, 3 situations, 58 links, 4 NEs, 1 user, 1 token, 1 audit row |
| `PRAGMA integrity_check` | **ok** |
| Audit chain verified **by v0.7.4** (the writer) | `OK: 1 entries verified; final hash 405275083f09…` |
| Audit chain verified **by v0.7.5** (the reader) | `OK: 1 entries verified; final hash 405275083f09…` |
| Same final hash | **yes** |

**One correction to this harness, recorded because it nearly produced a false result.** The first
version computed the audit `entry_hash` with a hand-rolled formula and the v0.7.5 CLI duly reported
`audit chain BROKEN at id 1: entry_hash mismatch (row tampered)`. That was **the harness being
wrong, not the upgrade** — a hand-rolled hash proves nothing about whether v0.7.5 can verify what
v0.7.4 wrote. Rewritten to call `netcorenoc.audit.write_event`, the project's real chained-append
primitive, which is the only version of this check that means anything. Worth recording: a
verification script that fabricates the artefact it is verifying will report a failure that is not
there, and — more dangerously — could have reported a success that is not there.

Three things this establishes beyond "the files are present", which is why it is a fair substitute
rather than a weaker check:

* the package is imported from **`site-packages`**, not from `src/` — asserted, so a path accident
  cannot make it pass;
* `create_app` ran, and therefore **the F42 gate ran as its last statement** — the shape set of the
  real built app is `{APIRoute, Route}`, equal to the allowlist;
* the **shipped** `app.js` carries the v0.7.5 changes (`held while open`,
  `createDocumentFragment()`) and no `innerHTML` — so the wheel is not serving a stale or stub UI.

It does **not** establish that the container image builds, that the hardened runtime
(read-only rootfs, dropped capabilities, non-root uid) works, or that the healthcheck passes. Those
remain unverified in this build.
