## Decisions recorded (#53–#62)

| # | Decision | Why it matters this release |
|---|---|---|
| 53 | Stored capability policy is an **intersection** with the compiled ceiling, not a validated grant table | This is the escalation-impossibility proof. Departs from `GOVERNANCE-0.7-DRAFT.md` §1, which specified write-time rejection; the reason is written into the entry. |
| 54 | **Unset** policy ⇒ the whole ceiling (parity); **set-but-empty** ⇒ nothing | Makes empty-policy parity structural rather than a special case, and keeps "allow nothing" expressible. |
| 55 | Malformed **capability** policy ⇒ fall back to the ceiling; malformed **scope** policy ⇒ deny | "Fail closed" means opposite things for the two policies; getting either backwards is a brick or a leak. |
| 56 | The three roles stay compiled in; only their *restriction* is data-driven | A runtime-defined role has no compiled ceiling, so #53's first operand would become data. |
| 57 | Scope selectors resolve to NE ids **at read time**; the two layers **union** | NetCoreNOC discovers NEs continuously; a write-time snapshot would silently hide new NEs a CIDR plainly covers. |
| 58 | **Admin is never scoped** | The single rule that makes every fail-closed branch recoverable. |
| 59 | Out-of-scope situation members are **redacted to a count and type**, never silently omitted | Silent omission would make a scoped operator confidently mis-size a cross-boundary incident. |
| 60 | Out-of-scope ⇒ **404**, produced by filtering the lookup itself | A separate pre-check is a second decision site that can drift; filtering the query makes "absent" and "out of scope" indistinguishable by construction. |
| 61 | One shared candidate-selection helper; preview's bounds become **aliases** of the engine's constants | Closes the v0.6.0 debt at its actual cause — the duplicated numbers, not the duplicated loop. |
| 62 | Per-principal policy keys on `user:<id>` / `token:<id>`, not on the display name | `actor` is not unique across users and tokens; keying authorization on a cosmetic string is a cross-principal bug waiting for a name collision. |

**One deliberate departure from the specification I was handed**, recorded rather than silently
made: `GOVERNANCE-0.7-DRAFT.md` §1 specifies an `rbac_grant` table whose above-ceiling rows are
"**rejected at write time**". DECISIONS #53 keeps that rejection as a *usability* affordance and
moves the *security* guarantee to the intersection, because a write-time check protects only the
write paths it is on, while an intersection protects every path that will ever exist — including a
direct `sqlite3` write to a stolen or restored database. The build prompt's prime directive 2 asks
for escalation to be "structurally impossible, not merely forbidden", and those are the two options
in exactly those words. Every stricter clause of the draft survives: an undelegable capability is
one whose ceiling is `admin`, and no intersection can move it down.

## Threat-model additions

New assets **8** (capability policy), **9** (scope policy), **10** (the existence of a network
element — the first release where "does NE X exist?" is a question some authenticated principals
must not be able to answer).

Threats added, each with a control and a named check:

- **Capability policy**: escalation via a stored policy (→ intersection); a second decision site
  (→ one resolver + a source-level assertion); `rbac.write` as the escalation (→ admin-only,
  audited, and still ceiling-bounded); malformed policy locking the admin out (→ ceiling fallback +
  warning + audit); untraceable perimeter change (→ append-only + hash-chained
  `rbac.policy.update`); a policy change riding an open session (→ per-request resolution).
- **Scope policy and read paths**: existence oracle via a scoped resource (→ 404 from the filtered
  lookup); leakage through aggregates (→ counters over the in-scope set); leakage through a
  mixed-membership situation (→ count-and-type redaction, links withheld, root hint suppressed);
  the live stream forgetting the policy (→ per-event resolution); fail-open *or* lockout on a
  malformed scope (→ deny for viewer/editor, admin exempt); scope confused with authorization
  (→ independent resolvers, composed in one order).
- **Hot path**: a policy read reaching ingestion (→ HTTP-side only; F24's source assertions
  extended).
- **Migration**: an upgrade that changes behaviour (→ `0006` seeds zero rows).

**Rejected by design** (recorded as rejections, not controls): tenant isolation via scoping;
dynamic roles; write-time ceiling validation *as the control*.

## v0.8.0 spec refinement (specification only — nothing implemented)

`SCORER-PLUGINS-0.8-DRAFT.md` gains §R1–R5, every element still tagged `v0.8.0: planned`:

- **R1** — the shipped v0.6.0 contract re-checked element by element against the code (not against
  the v0.6.0 draft). Verdict: **no breaking change needed** for either path. One improvement over
  what was specified: `LinkFeatures` shipped as a `NamedTuple` (DECISIONS #52), so it is genuinely
  immutable and an adapter cannot mutate the features it was handed.
- **R2** — ⛔ **the worker-process preemption harness is a blocking prerequisite.** `SafeScorer`
  is a *post-hoc* guard: it measures a call after it returns and degrades the **next** one. Against
  five floating-point operations that is right; against untrusted code that never returns there is
  no next call, the batch loop blocks, and the ingest path starts dropping traps. `signal.alarm` is
  explicitly rejected as a fix (main-thread only; does not interrupt a C extension, which
  `onnxruntime` is). Recorded with the constraints the harness must satisfy so it does not become
  its own hazard: batch-oriented IPC (never per-pair — the seam costs ~4.2 µs per pair, a context
  switch would cost more), a parent that never blocks unboundedly, a dead worker treated as a
  fallback, bounded restart, determinism checked *in the worker*, and the ingest path still gaining
  nothing. And it still is **not** a sandbox — a plugin is as trusted as the operator who installed
  it.
- **R3** — reconciliation with governance: activating a customer scorer stays `scorer.write`,
  admin-only, and v0.7.0 makes that survive **structurally** (no `ceiling ∩ policy` result can move
  an admin-ceiling capability down). A customer scorer is a system-wide logic change and is
  therefore **never scoped and never delegated**; "this scorer applies to my NEs only" would be
  per-tenant correlation, i.e. the isolation v0.7.0 does not build. A scorer remains not an
  authorization input.
- **R4** — `onnxruntime` stays an optional extra. The base runtime dependency list has been
  **five** since v0.2.0 and ends v0.7.0 at five; v0.8.0 must not change it.
- **R5** — sequencing: harness first (nothing merges before it), then the attribution store, then
  the ONNX adapter, then the entry-point hatch. Its review opens at **F34**.
