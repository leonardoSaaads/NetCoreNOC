## The decisions, in one line each

- **#109** — reproduction found `feedback.situation_id` is a *restricting* FK, so "let it dangle"
  raises. Rejected a migration (forbidden) and retaining the whole situation subtree (unbounded);
  chose retaining **one row per label** while its operational satellites are still collected.
- **#110** — rejected leaving two tiers advisory, and rejected making training a background delete;
  chose **selection for training, deletion only at the audit bound**. A `DELETE` forecloses a
  decision v0.9.0–v0.13.0 have not made yet; a `WHERE` clause does not.
- **#111** — rejected four `meta` keys because the four values are *one policy with an invariant
  between them*, and a per-field fallback can synthesise a policy no operator ever set. Chose one
  JSON value so the unit of parsing is the unit of policy.
- **#112** — rejected clamping at 100% (hides it) and shrinking the numerator (discards evidence);
  chose the union population, where the numerator is a subset of the denominator **by
  construction**.

## Supersession — annotated in place, dated, never rewritten

`DECISIONS.md` holds **no** v0.8.0 entry describing the retention tiers; the tier semantics live in
the scope, design and migration documents. Those are where the supersession had to land, and it
follows DECISIONS #102's convention (strike through in place, correction beneath with the date and
the evidence) rather than editing the original text away:

| Document | Claim struck | Replaced by |
|---|---|---|
| `MIGRATION.md` §Retention | *"The background maintenance loop **never** deletes labelled data. It bounds the sink and nothing else."* | Correction naming F44, its default of 7 days, and the gate that reproduces it — plus the note that the sentence is now true for a different reason |
| `MIGRATION.md` tier table | — (extended, not struck) | A fourth column stating what each bound *does*: deletes / **selects** / deletes |
| `docs/architecture/DESIGN.md` | *"The dataset grows with labels, not with traffic … a 200 000-trap storm fills the sink and does not move the dataset."* | True per *situation*, false per *row*; the corpus is bounded by **labels × pairs evaluated within the labelled situation** |
| `docs/scope/SCOPE-0.8.0.md` | the same claim, in its own words | Short correction pointing at DESIGN.md, which carries the full restatement |

Both struck passages remain visible. A reader who cannot see the withdrawn sentence cannot judge
whether the correction is right, which is the whole reason DECISIONS #102 chose this convention.

`DESIGN.md` also gains the v0.8.0 fact the audit found stated only in a commit message — **the
sink's row cap, not its age limit, is what governs** (~62 rows/trap; the 2 000 000-row default is
exhausted in ~3.7 days at 0.1 traps/s and ~9 hours at 1 trap/s) — placed beside the tiers it
qualifies, which is Workstream 5's requirement discharged early because it is a documentation change
and this was the documentation phase.
