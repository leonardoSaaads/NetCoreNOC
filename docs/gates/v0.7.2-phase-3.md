## 2. The parity proof, and why it had to be sharpened

The Phase 0 table hashes `inspect.getsource(endpoint)`, which **includes the decorator line**.
Workstream 3 rewrites `@app.get("/api/x")` to `@route.get("/api/x")` on all 43 decorator-registered
handlers, so that table could not survive this release — and a proof that changes for the intended
reason cannot tell the intended reason from an unintended one.

The baseline was therefore split into two, both measured from the pristine v0.7.1 `api.py` at
commit `9cb2086` (recorded as §5.2 of `docs/gates/v0.7.2-phase-0.md`):

```
BODY PARITY OK      43/43 handler bodies hash identically to v0.7.1
DECORATOR PARITY OK 43/43 decorators differ only by @app. -> @route.
```

* **Body parity** — from `def`/`async def` to the last line: signature, docstring, body. Zero
  characters edited, as directive 2 requires.
* **Decorator parity** — the full text equals v0.7.1's with `@app.` replaced by `@route.` and
  nothing else. Forty-three identical substitutions, no exceptions.

Together these are strictly stronger than the single hash they replace.

### The proof earned its keep immediately

Deleting the `situation_in_scope` / `audit_scope_denial` block from `create_app` took one line too
many and removed `@app.post("/api/situations/{sid}/feedback")` — the decorator, not the handler.
The route silently vanished from the app. Nothing in the handler's own text had changed, so no
body hash could have caught it; **`test_route_table_order_is_unchanged` caught it on the next run**,
naming the exact index. That is the Phase 2 ordering guard doing the job it was installed for,
before anything moved.

## 3. The perimeter extraction (Workstream 2)

Thirteen module-level symbols and eleven closures left `create_app`. The closures became methods
of one `Perimeter` class under exactly **one** rule, applied by script to NAME *tokens* only — never
inside a string, a docstring, a comment, or an attribute position:

> a name that was a captured free variable of `create_app`'s scope becomes an attribute of `self`

`store` → `self._store`, `governance` → `self.governance`, `limiter` → `self._limiter`,
`warnings` → `self._warnings`, and a sibling closure → `self.<name>`. The sibling clause is the one
extension to the plan's four-name list, and it is the same rule: a closure calling a sibling closure
becomes a method calling a sibling method.

A first, regex-based pass substituted inside string literals and docstrings (`"no-store"` became
`"no-self._store"`, `"governance.fallback"` became `"self.governance.fallback"`). It was discarded
and rewritten with `tokenize`. Recorded because it is exactly the class of error a "mechanical"
transformation is assumed not to make.

### `Depends(bound_method)` — verified, not assumed

The plan required checking that FastAPI's signature introspection excludes `self` on the pinned
version, with a module-level factory as the fallback. Measured on FastAPI 0.141.1:

```
inspect.signature(perimeter.security)      -> (request: Request) -> str     # `self` excluded
Depends(p.security) as a default argument  -> resolves, honours query params
app.middleware("http")(m.mw)               -> the response header arrives
```

**No fallback was needed.** Handler signatures are untouched.

### One deliberate non-edit

`write_txn`'s docstring still carries its v0.7.1 note: *"Note for v0.7.2 (DECISIONS #74): this
belongs to the perimeter block and moves to `perimeter.py`…"* — inside `perimeter.py`. Directive 3
permits exactly two edits to moved code and this is neither, so it was left verbatim. The sentence
now reads as a record of the plan rather than a plan, which is a smaller cost than a diff hunk that
is not a move.

### One forced edit, recorded in S1

`UI_DIR` was `Path(__file__).parent / "ui"`. `app.py` sits one directory deeper than `api.py` did,
so it is now `Path(__file__).parent.parent / "ui"`. The **resolved path is byte-identical**
(`src/netcorenoc/ui`), asserted at runtime and by `tests/test_security_txt.py` and
`tests/test_deploy.py`. A location-relative constant must change when the location does; it is
called out here rather than left in the diff.

## 4. The declaration discipline (Workstream 3)

`rbac.py` keeps `PERMISSIONS`, `ROUTE_PERMISSIONS` and `PUBLIC_ROUTES` unchanged and gains
`ROUTE_SCOPE` — **39 entries, one per non-public route**:

| posture | count |
|---|---:|
| `scoped` | 12 |
| `unscoped` | 5 — each with a written justification, asserted by a test |
| `admin_only` | 22 |

Two **import-time** assertions in `rbac.py`, so the tables cannot disagree even before an app is
built:

1. `set(ROUTE_SCOPE) == set(ROUTE_PERMISSIONS)`.
2. a route is `admin_only` **if and only if** its capability's minimum role is `admin` in
   `PERMISSIONS` — so `admin_only` is a derived claim, never a second authority.

`api/declare.py` holds `DeclaredRoutes`, the only registration path. It consults
`ROUTE_PERMISSIONS` and `ROUTE_SCOPE` **as each route is registered** — that is, while `create_app`
is building the application, before the process can serve a request. Two exemptions, both by
explicit consultation: non-`/api` paths (no identity, no capability, nothing to declare) and
`rbac.PUBLIC_ROUTES`.

  table is missing;
* completeness from the **live app object**, both directions (2) — no undeclared route, no dead
  declaration;
* `admin_only` re-derived from `PERMISSIONS` in both directions (1);
* every `"unscoped"` entry preceded by a written justification (1);
* `add_api_route` confined to the single module that owns the static-asset allowlist (1);
* **the postures against observed behaviour** (41): 22 `admin_only` routes are 403 for viewer and
  editor; 5 `unscoped` routes return byte-identical status and body to a caller under a policy that
  hides half the estate and to one under no policy; 5 targeted `scoped` routes 404 an out-of-scope
  target; 7 collection `scoped` routes answer differently under a policy — including `/api/events`,
  whose first SSE frame is captured by driving the ASGI app directly, the technique
  `test_governance.py` and `test_shaping.py` already use because httpx's ASGITransport cannot
  deliver partial bodies of an infinite response.

`ROUTE_SCOPE` remains **descriptive**. Nothing reads it at request time. Injection is a ROADMAP
line (DECISIONS #80).

## 5. Deviations from the plan, each with its decision

| Deviation | Why | ADR |
|---|---|---|
| Sixteen modules, not fourteen — `governance_cache.py` and `declare.py` | `perimeter.py` measured 444 lines *before* the gate was written (~510 after). The plan's module table is explicitly indicative; the 400-line guard is a hard constraint and this release installs it. Each extraction is justified on the placement rule, not on arithmetic. `perimeter.py` lands at 361 with headroom. | #85 |
| `audit_row` reached via `ctx.perimeter`, not an `AppContext` field | Its five keyword-only parameters cannot be spelled in a `Callable[...]`; a field would be `Callable[..., Awaitable[None]]` and `mypy --strict` would stop checking the arguments at all 25 audit call sites. The other fourteen names are fields, typed exactly. | #86 |
| `rbac.py` joins `DEBT_ALLOWLIST` at 436 lines | `ROUTE_SCOPE` — the declaration whose absence *was* F34 — took it from 348 past the guard. The table belongs in the single source of authority, and every `"unscoped"` needs its justification, so neither could be traded away. Owner v0.7.4, seam recorded. | #87 |

The third one deserves saying plainly: **this release added debt.** The guard noticed on the run it
was meant to, and the response is a dated entry with an owner and a named split seam rather than a
quietly raised threshold. A guard that gets weakened the first time it says something inconvenient
is not a guard.

## 6. Test-side changes, in full

`git diff` over `tests/` for Phase 3 contains exactly:

1. **`tests/apisource.py` (new)** — `api_source()` concatenates the package in registration order,
   because `inspect.getsource()` on a package returns only `__init__.py` and would have left four
   v0.7.1 guards silently scanning almost nothing. It refuses a module it has not been told where to
   place and asserts a floor on the concatenated length. It refused `governance_cache.py` the moment
   that module appeared, which is the behaviour it was written for.

   `inspect.getsource(api.create_app)` → `apisource.api_source()` (×1). No assertion touched.
3. **Three scanned tokens**, each the literal spelling of a name that moved:
   `'@app.post("'` → `'@route.post("'`, `'@app.delete("'` → `'@route.delete("'`,
   `"\n    @app."` → `"\n    @route."`, and `"await store.rollback()"` →
   `"await self._store.rollback()"` (the §4.2 substitution, seen from the outside).
4. **One import** — `from netcorenoc import api, audit, …` loses `api`, which is no longer
   referenced.
5. **`tests/test_declaration.py` (new)** — 50 genuinely new structural tests.
6. **`DEBT_ALLOWLIST`** — `api/app.py` re-keyed after the `git mv`, `rbac.py` added.

No assertion's *meaning* changed anywhere. Every token rename is listed above rather than left to be
found in a large diff (DECISIONS #84).
