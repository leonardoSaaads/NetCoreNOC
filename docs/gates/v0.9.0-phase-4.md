# v0.9.0 — Gate 4: the challenger and the derivation policies

Five steps, in order: the challenger and its contract tests **before any training**; the training
path in the slow loop; both policies; partition-level evaluation; calibration.

## S1 — the challenger, and its contract asserted before a fit existed

`src/netcorenoc/challenger.py` (251 lines). It satisfies `LinkScorer` **structurally** — no base
class, no registry, and `scoring.py` gains nothing, asserted by
`test_scoring_py_gained_nothing`. `tests/test_challenger.py` was written and run against a scorer
whose coefficients were still zero, because these properties must hold whatever the fit turns out
to be; a test written after a model exists is a test shaped by that model.

### `score()` returns the pre-link score, and that is a decision

`AdditiveScorer` has the property that its terms sum exactly to its score, and this release keeps
it. That fixes what `score` must be: the **logit**, `b + Σ wᵢxᵢ`, with the intercept emitted as its
own term, and `threshold = 0.0` — which is exactly `p > 0.5` through the link. The probability is a
separate method, and is what calibration and the shadow table use. Two quantities, each where it is
correct, rather than one that is slightly wrong in both.

```

test_there_is_one_term_per_free_parameter_and_the_intercept_is_one_of_them PASSED
test_the_verdict_is_the_probability_verdict_expressed_in_logits            PASSED
```

The sum is asserted **exactly**, not within a tolerance: a tolerance would hide the term-reordering
bug the test exists to catch.

### The fourth feature the plan registered, and why it is not here

`docs/analysis/PREREGISTRATION-0.9.0.md` §2.3 registered four features. `same_oid_root` **is not
implemented**, and the reason is structural rather than convenient:

> `LinkFeatures` carries no trap OID, and neither does `correlate.WindowAlarm`. The online shadow
> path scores inside the engine from `LinkFeatures` alone, so `same_oid_root` is computable
> **offline and not online** — and a feature that cannot be served is a feature that *guarantees*
> training/serving skew, which is the exact defect §6 of the plan exists to detect. Building it
> would have required editing `correlate.py`, which this release may not touch.

So the model has **four free parameters, not five**. **The floor stays at fifty `split` bags**, the
number registered when the plan expected five: `resolved = the more demanding of` runs monotone
toward evidence (DECISIONS #114), and lowering a floor because the model got simpler is precisely
the move that rule forbids. The deviation is reported here and in the security review — **never by
editing the plan**, which §9 of the plan itself directs.

## S2 — the training path, in a slow loop this release had to create

Phase 0 §4 found that **no point in `maintenance()` runs outside `store.lock`**. The consequence,
decided in Phase 1 as DECISIONS #118 and built here:

```python
# maintenance.py
async def maintenance_loop(self, retention_provider):
    tick = 0
    while True:
        await asyncio.sleep(MAINT_INTERVAL_S)
        tick += 1
        await self.maintenance(time.time(), retention_provider(), tick)   # holds the lock
        if self.shadow.enabled and tick % TRAIN_EVERY_TICKS == 0:
            await self.shadow.train(self.store, time.time(), self.store.lock)
```

`maintenance()` has returned and released the lock before `train` is called. `train` then takes the
lock **only** to read its rows and, separately, to write its result; **the fit holds nothing**.

`maintenance_loop` moved from `engine.py` to `maintenance.py` (**DECISIONS #121**) because
`engine.py` sat at exactly 580 lines — its `COHESION_EXEMPT_CEILING`, with zero headroom.
`engine.py` is **still 580** and the ceiling is untouched at one entry.

### The fit is bounded, and its determinism outranks a deadline

| | |
|---|---|
| optimiser | batch gradient descent, `ITERATIONS = 200`, `LEARNING_RATE = 0.5`, `L2 = 1e-3` |
| bound | `MAX_PAIRS_PER_BAG = 256`, then `MAX_TRAINING_ROWS = 8000`, both deterministic |
| RNG | none |
| early stop | **none** — a stop on a timer would make the answer a property of the machine |
| event loop | `await asyncio.sleep(0)` **between** iterations, never inside one |

The last row is the one that matters for prime directive 1: the fit runs off the batch lock but in
the same event loop, so a multi-second fit that never yielded would stall ingestion by an indirect
route. A yield between iterations changes no arithmetic and therefore no result.

`L2` is not a flourish. Policy B's derived labels are all positive (see S3), and an unregularised
logistic fit on a single-class target has no finite optimum — the ridge gives it one, so the
degenerate case produces a *reportable* model instead of an overflow.

```

test_the_fit_is_byte_identical_across_two_processes                        PASSED
test_an_injected_training_failure_degrades_training_and_not_ingestion      PASSED
test_an_injected_scoring_failure_never_reaches_the_engine                  PASSED
```

The cross-process test fits the same corpus from the same file in a subprocess and compares each

## S3 — both policies, and a finding the draft did not have

**A** (`split` → every pair negative) and **B** (`confirm` only) are both derived, both fitted, both
reported. Weighting is the pre-registration's: `w_bag = 1/(rows kept for that bag)` so **every bag
contributes exactly one unit of mass**, then class balancing.

> ### Policy B derives only one class, and this release measured it
>
> The shadow-mode draft called B *"throws away the minority class"*. On bag-level labels it throws
> away **the only source of negatives**: a `confirm` bag asserts every pair in it is positive, so
> with `split` discarded the target is constant. The best achievable model predicts "link"
> unconditionally.
>
> `test_policy_b_derives_only_one_class_and_says_so` asserts it: `{row.y for row in rows_b} ==
> {1.0}` and `negative_mass == 0.0`. The report prints a `>>> DEGENERATE <<<` block rather than a
> coefficient table alone, because a policy whose failure is invisible is one a later release picks
> by default.

Over the sufficient fixture the contrast is stark, and it is exactly what the release exists to make
visible:

| | over_merge | under_merge | **split_bag_intact** | Brier |
|---|---:|---:|---:|---:|
| champion | 0.0000 | 0.5000 | 0.0000 | — |
| policy **A** | 0.0000 | 0.0000 | 0.0000 | 0.0052 |
| policy **B** | 0.0000 | 0.0000 | **1.0000** | 0.5932 |

Policy B scores perfectly on the two headline rates **and buries every single split bag** — two
incidents inside one situation, sixty times out of sixty. A release reporting only over-merge and
under-merge would have called B the better model.

*(Synthetic fixture. These numbers are about the machinery, never about operators.)*

## S4 — partition-level evaluation, and the third number

`over_merge_rate` and `under_merge_rate` **moved into the package** (`shadow_eval.py`) and
`eval/metrics.py` imports them back — DECISIONS #122, because `src/netcorenoc/` never imports
`eval/` and two copies of one metric agree until one is tuned. `make eval` is byte-identical:
`c2e8a0ced29d9edf986279d41089ddb68e18da65a46bdc7e9f04811e8b9b6f26`, unchanged.

The truth is the **human verdict at bag granularity**, never `incumbent_linked`:

* a **`confirm`** bag is a truth partition — splitting it is an under-merge, uniting two is an
  over-merge;
* a **`split`** bag supports **no** truth partition, so it is scored only by
  **`split_bag_intact_rate`**, named separately. Folding it into an over-merge rate would fabricate
  a denominator.

`test_split_bags_are_scored_separately_and_never_folded_in` asserts the two populations do not leak
into each other. The champion is measured the same way, on the same bags, because a challenger
number with no champion number beside it is not a comparison.

## S5 — calibration at bag level, and the admission filter

Bag level, because that is the granularity of the label. `P(bag is one situation)` is the
**minimum** over its pairs — a component holds together only as well as its weakest link.
Five equal-width bins, fixed edges, plus the Brier score.

The report states, in the section itself, that calibration is not implied by accuracy, and the half
that is a trap: **confidence may route what the operator is asked; it may never authorise autonomy.**

The **admission filter** was defined before the first model so it could not be written around
whatever won, and the **champion is measured against it too**:

```
                         median us      p99 us   terms   det   mem
  additive                   1.443       6.829       3  True  True
  logistic-shadow            2.351       9.315       4  True  True
  admitted                    True
```

The speed budget is a **ratio** of the champion's p99 measured in the same process
(`ADMISSION_BUDGET_RATIO = 10.0`), not a microsecond figure — Phase 0 §5 measured the champion's own
p99 moving 2.6× between two runs on one machine. `test_a_model_failing_any_check_does_not_compete`
drives each of the five checks to failure and asserts the model is refused.
