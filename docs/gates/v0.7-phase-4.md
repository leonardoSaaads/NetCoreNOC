## The twelve items

### 1. Empty-policy parity ✅

Asserted as an **equality**, not a spot check —
`test_empty_policy_resolves_exactly_to_the_v060_behaviour` compares, for every one of the 28
capabilities × 3 roles, `capability in resolve_capabilities(role, None, None)` against v0.6.0's
`role_allows(role, capability)`. `test_no_governance_rows_on_a_fresh_database` confirms a fresh
install carries no policy; `test_v070_upgrade_changes_no_behaviour` confirms an upgraded one does
not either. `make eval` byte-identical.

### 2. Ceiling inviolable ✅

`test_f27_no_generated_policy_resolves_above_the_ceiling` — hypothesis, **250 examples**, over
generated policies whose strategies deliberately include above-ceiling capabilities
(`users.manage`, `audit.read` offered to `viewer`), unknown roles (`root`, `ADMIN`, `""`), unknown
capabilities, and a wildcard-looking principal. None is special-cased anywhere: the intersection
makes them inert.

The case a write-time check structurally cannot cover is proven separately:
`test_f27_policy_written_directly_to_the_db_cannot_escalate` inserts and activates a policy through
`store` directly, **bypassing the API**, and the viewer still gets 403 on `/api/users`,
`/api/audit`, `/api/rbac`. `test_a_policy_never_makes_a_route_reachable_that_the_ceiling_forbids`
grants **every** role **every** capability and sweeps all 39 routes.

The resolver is the single decision site: `test_f28_no_role_comparison_outside_rbac` asserts over
`api.py`'s own source that it contains no `role == "admin"`, no `ROLE_RANK[`, and no
`role_allows(` — only `rbac.resolve_capabilities(`.

### 3. Capability restriction ✅

Removing works (`test_f27_a_policy_can_only_narrow`), re-enabling up to the ceiling works,
above-ceiling is inert. Denied attempts are audited
(`test_f27_denied_governance_attempts_are_audited`). The per-principal layer narrows and never
widens, and one principal's restriction does not touch another of the same role
(`test_per_principal_capability_restriction_never_widens`).

### 4. Scope filtering ✅

- Lists return only in-scope NEs/entities/alarms — `test_f32_every_ne_bearing_read_is_filtered`
  sweeps `/api/entities`, `/api/graph`, `/api/timeline`, `/api/situations` and asserts no
  out-of-scope address appears anywhere in the serialised body.
- A graph edge survives only when **both** ends are in scope, so the graph never draws a line to a
  node the caller cannot see.
- Mixed-membership situations redact to a count and alarm classes;
  `test_f32_redacted_members_disclose_no_identifier` asserts no out-of-scope address survives at
  any depth and that every returned link references only visible alarms.
- An entirely out-of-scope resource returns **404 indistinguishable from a missing one** — status,
  body **and** headers compared against a genuinely nonexistent id, for both
  `/api/situations/{sid}` and `/api/entities/{ne_id}`.
- No aggregate leaks volume — `test_f32_aggregates_are_computed_over_the_in_scope_set`.
- Admin is unscoped — `test_f32_admin_is_never_scoped`, including against a policy written directly
  to the database that names `admin`.
- Selector forms (`ne:<id>`, address, CIDR, glob) and the layer-composition rule are covered by
  `test_scope_selector_forms` (9 cases) and
  `test_scope_layers_union_and_an_unset_layer_expresses_no_opinion` (the 4 cases a literal reading
  of the specification would get wrong).

### 5. Fail-safe / lockout ✅

| Policy | Malformed behaviour | Warning | Audit |
|---|---|---|---|
| Capability | falls back to the compiled ceiling (v0.6.0 exactly) | ✅ | `governance.fallback` |
| Scope | denies viewer/editor; admin untouched | ✅ | `governance.fallback` |

11 malformed capability shapes and 6 malformed scope shapes are covered
(`test_malformed_capability_documents_never_raise_and_fall_back`,
`test_malformed_scope_documents_never_raise_and_deny`), each asserting the parser **never raises**
— it runs on the authorization path, where an exception would be an outage rather than a
degradation.

`test_f29_admin_cannot_be_locked_out_by_a_well_formed_policy` covers the case the malformed
fallback would never catch: a *valid* policy stripping the `admin` role. The admin retains exactly
`RECOVERY_CAPABILITIES` — enough to repair, and demonstrably **not** more (`/api/users` and
`/api/audit` are still 403, so the recovery set is a real restriction and not a special case that
ignores policy).

### 6. Session re-evaluation ✅

Capability and scope changes land on the **next request** of an already-open session, same cookie,
no re-login. SSE is covered properly rather than assumed: `test_f30_sse_reevaluates_scope_on_every_event`
drives the ASGI app directly (httpx's transport cannot deliver partial bodies of an infinite
response), captures one update, writes a scope **while the stream is open**, and asserts the very
next event is filtered. `test_f30_sse_ends_when_the_streaming_capability_is_revoked` proves the
stream stops rather than serving its connect-time grant.

> **This item found a real gap.** The Phase-1 review skeleton named an SSE re-evaluation test that
> did not exist — the control was implemented but unproven. Rather than adjust the claim to match
> the tests, the tests were written to match the claim.

### 8. Audit catalog ✅

`rbac.policy.update` and `scope.policy.update` are driven by `_drive_every_action` and required by
`EXPECTED_ACTIONS`. `governance.fallback` is a system action emitted only when a stored policy will
not parse, so it is driven and asserted in `test_f29_malformed_capability_policy_falls_back_to_the_ceiling`
instead — noted in the catalog test rather than left unexplained. Policy history is append-only
(`RAISE(ABORT)` proven on both UPDATE and DELETE), survives a clear, is attributable, and the
retention prune does not touch it.

headers unchanged and applied to the four new routes.
