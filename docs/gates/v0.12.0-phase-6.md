## 8. Coverage, against the band and against the baseline

| | figure |
|---|---|
| v0.11.0 baseline, measured in Phase 0 §5 | **96.02 %** |
| v0.12.0 | **96.13 %** |
| ADR #159's documented band | 96.10 – 96.21 % |

The post-release figure is **inside the band**; the pre-release baseline was 0.08 below it.

**What that movement is not evidence of.** The gap is 0.11 points, which is *exactly* the drift
magnitude ADR #159 attributes to the two underandomised `@given(st.binary(...))` properties in
`tests/test_receiver.py`. So the honest statement is: **the change is within the noise the band
exists to describe, and cannot be attributed to this release's tests.** There is a plausible real
contribution — `uifixtures` drives the real engine, the real API and the real label route to build
its captures, which exercises source code — but nothing here separates it from the drift, and a
0.11-point move is not the place to start claiming one.

Not done, deliberately: derandomising the properties (ADR #159 records why not), widening the band
to fit, or quoting the band in place of the measurement.
