## 1. The shape, and why it is three modules

`MODULE-ARCHITECTURE.md` §10.2 recorded two axes. Phase 0 classified every top-level symbol from the
AST and found **three parts** (§4.1); DECISIONS #95 records the correction and §10.2 is superseded
in place, not rewritten.

| Module | Lines | Owns |
|---|--:|---|
| `shaping/__init__.py` | 110 | the compatibility surface: every name `shaping.py` exported, re-exported |
| `shaping/fields.py` | 88 | **which fields** — `FIELD_RULES`, `coarsen_ip`, `shape` and its three overloads |
| `shaping/scope.py` | 302 | **which rows** — `ScopePolicy`, `Scope`, `visible_nes`, the selector matching, the policy parser and its operator-facing errors |
| `shaping/project.py` | 110 | **applying a resolved scope to a body** — `filter_rows`, `project_graph`, `project_situation_detail` |

The projections are not a third *axis*. Each takes a `Scope` produced by the scope axis and returns
a response body, which is the field axis's subject — they are the **consumer** of the other two.
Forcing them into `scope.py` would put response-body construction in the module that owns the scope
decision; forcing them into `fields.py` would put `Scope` handling in the module that owns field
rules. A two-way framing is exactly what makes one of those look necessary.

`shaping.py` was **476** lines; the four modules total 610, and the difference is the three new
module docstrings plus the re-export block. No function body accounts for any of it — see §2.

## 3. The F35 invariant travelled with `scope.py`

v0.7.1 established that **no input to `visible_nes()` may be writable by a scopable role**. Two
comment blocks carry that reasoning and both moved verbatim with the code that depends on them:

* `visible_nes`'s — *"Every input to this function is admin-written or engine-written, and that is a
  release invariant, not an accident"*, including the instruction that anything added to the
  signature must satisfy the same test;
* `_matches`'s — why the operator label is **not** read, the v0.7.0 escalation it prevents, and the
  deliberate cost that a label glob now matches by address or not at all.

`scope.py`'s module docstring states where the invariant lives and why it lives with the code.

```

```

**Unedited.** So is `test_f35_an_editor_cannot_widen_their_own_scope_with_a_label`, the behavioural
half.

### One note on the sequencing

The build prompt's Phase 3 lists the `git mv`, the `__init__.py` and each extraction as separate
steps ending in `make qa`. The `git mv` was combined with the first extraction in a single commit,
because `shaping/_all.py` at 476 lines would otherwise have sat over the size guard in a committed
state — and v0.7.3 handled the same transition by temporarily allowlisting `store/_all.py`, which
would mean **growing** `ALLOWLIST_MEMBERSHIP_CEILING`, a set whose whole contract is that it only
shrinks. Extracting `scope.py` (264 lines) in the same step takes `_all.py` to 212 immediately, so
no commit ever carries an oversized transitional module and no allowlist entry is ever added. The
rename is still recorded by git (`R src/netcorenoc/shaping.py -> src/netcorenoc/shaping/_all.py`),
so history is preserved exactly as the prompt intends.
