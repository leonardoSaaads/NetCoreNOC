# Gate v0.5 — Phase 4 (Self-contained deployment)

"Start using it" is now `docker compose up`, using only what a maintainer already has locally.
Every artifact wraps the existing single process; none changes it.

## Deliverables

| File | What it is |
|---|---|
| `docker-compose.yml` | one-command hardened run: `build: .`, `read_only: true`, `cap_drop: [ALL]` + `cap_add: [CAP_NET_BIND_SERVICE]`, `security_opt: [no-new-privileges:true]`, `tmpfs: /tmp`, named `netcorenoc-data` volume for the DB, trap (162/udp) + HTTP (8080) ports, `/healthz` healthcheck, `restart: unless-stopped`; a commented TLS/allowlist profile |

## Gate 4 criteria

- **`docker compose config` validates** — daemon-free: `docker compose config` exits 0 (Compose
  v5.1.1). The file interpolates cleanly with or without a `.env` (defaults via `${VAR:-…}`).
- **The Dockerfile still builds an image that serves the full UI.** The Docker daemon is not
  available in this build sandbox, so the image is not built here — but the Dockerfile does
  `COPY src ./src` + `pip install .`, i.e. it installs the exact wheel proven in Phases 2–3. The
  freshly built wheel, installed into a clean venv, resolves `netcorenoc` and ships the full UI
  (`index.html`, `app.js`, `style.css`, `vendor/d3.*`, `.well-known/security.txt`), all four
  migrations, and `py.typed`, with the d3 checksum intact and `.well-known/security.txt` in
  `STATIC_ASSETS`. Actually building the image and `docker compose up` is the maintainer's
  reproducible step (per the delivery model), and needs no change beyond a running daemon.
- **`make dist` produces an installable wheel/sdist locally.** `python -m build` builds both; the
  wheel installs into a clean venv and imports; the **sdist excludes** `tests/`/`eval/`/`tools/`/
  `docs/` and any `.env`/`*.db` (F18) while keeping `src/` (UI, `.well-known`, migrations,
  `d3.LICENSE`), `pyproject.toml`, `LICENSE`, `NOTICE`, `README.md`.
- **Committed workflows are SHA-pinned, least-privilege, and cannot publish by accident.** Every
  active `uses:` is a 40-char commit SHA (`actions/checkout` v4.2.2, `actions/setup-python`
  v5.6.0, `softprops/action-gh-release` v2.2.1); both workflows declare `permissions:`;
  `release.yml`'s PyPI/registry/signing steps are commented. `tests/test_workflows.py` (7 tests)
  fails on any floating tag, missing `permissions:`, or active publishing step.
- **`make release-check` passes** — all three version sources agree (currently `0.4.0`; Phase 5
  bumps them to `0.5.0` together).
