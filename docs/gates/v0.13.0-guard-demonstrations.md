# v0.13.0 — the demonstrated guards

**A guard nobody has watched fail is not a guard.** Every guard this release adds, and every guard
it inherited and rewrote, is shown red under an injected defect, then green on restore, with a
**control that had to pass in both** — so a red that came from breaking the suite generally is
distinguishable from a red the guard actually caught.

The shape is `v0.12.0-guard-demonstrations.md`'s, inherited exactly: the guard named with its test
id, the defect as a diff against the corrected tree, the command, the verbatim RED, the verbatim
GREEN, and the control.

Command, for every entry:

```sh
python -m pytest -q --no-header -p no:cacheprovider <test id>
```

**The control**, for every entry:
`tests/test_ui_invariants.py::test_a_confirm_never_carries_exclusions` — a DOM test that drives the
real console through the real harness and is unrelated to every defect below. It read
`1 passed in 1.26s` on the corrected tree and **`1 passed` under all fifteen injections**, so no
red below is a red the harness produced by falling over.

**Every injection was applied, measured and reverted in one run**
(`python tools/evidence/guard_demonstrations.py`), and the tree was verified afterwards:

```
git status after all injections: (clean)
ui/ tree digest: a57fbab35d2a9a9950adb558871aa0b12c06339994b936974fd53a75eddcd2ce
15/15 demonstrated red, restored green, control held in both.
```

The status line read *"(only the untracked probe directory `.demos/`)"* until the tool was
corrected: it ran `git status --porcelain` unscoped, so it reported **its own output directory**
and the script's exit code was `1` on every run, including a perfect one. An exit code that cannot
be zero carries no information. The check is now scoped to `src` and `tests`, which is the question
it was always trying to ask, and the run above exits `0`.

The digest is printed so the claim "every injection was reverted" can be checked against the tree
afterwards rather than taken on trust; it matches
`sha256` over `src/netcorenoc/ui/` computed independently, and
`tests/test_build_step.py::test_the_shipped_ui_is_exactly_what_this_release_pinned` passes.

Nine of the fifteen injections are edits to `src/netcorenoc/ui/` — the tree this release rewrites —
and `tests/test_build_step.py::test_the_shipped_ui_is_exactly_what_this_release_pinned` passes
after the run, which is what proves the reverts were complete.

**Fifteen of fifteen.** Four entries are worth reading beyond the tick.

### §5 is F53, and the assertion that catches it is the one that inverted

v0.12.0's version of `test_a_panel_reached_without_its_capability_still_issues_no_request` asserted
the absent request **and the `TypeError`**, because the `TypeError` was the mechanism. This release's
version asserts the absent request **and that nothing threw**. Reverting the repair (§5) produces a
mounted component and a real request, and all three guards go red — but the one that would catch a
*regression to the accident* rather than to the leak is `assert outcome["threw"] is None`, and no
injection here exercises that direction. Stated because it is the honest limit of §5: it demonstrates
the guard catches the leak, not that it catches a return to the `TypeError`.

### §12: one of the two guards did not catch it, and that is the useful part

Relaxing the CSP to `'unsafe-inline'` reads `1 failed, 5 passed`.
`test_csp_is_unchanged_and_forbids_inline` caught it. **`test_security_headers_on_every_route_class`
did not, and could not**: it asserts `response.headers["content-security-policy"] == CSP` — the same
constant the injection edited. It is a guard that the middleware *ships* the policy, not that the
policy is *right*, and against a change to the constant it is unfalsifiable by construction. That is
Appendix B's "an identity that cannot fail", found by looking. It is kept, because the property it
does cover is real; it is recorded here so nobody reads its green as covering the other one.

### §2 and §7 each have one guard that fires and one that does not

Both are source-level tripwires beside behavioural assertions, and in each case only one of the
pair was in a position to see that particular defect. The pairs are deliberate (ADR #168's
reasoning) and their asymmetry is expected; a reader should not infer from `1 failed, 1 passed`
that half the guard is broken.

### Every injection here is a defect a reviewer could plausibly write

None of them is a syntax error or a deleted function. Each is a small, readable edit of the kind
that arrives in a diff titled "simplify" — a capability lowered by one line, a `false` where a
comparison was, a `tabindex` made constant, a validator that returns its input. That is the
standard these demonstrations are held to: a guard that only catches vandalism is not a guard.
