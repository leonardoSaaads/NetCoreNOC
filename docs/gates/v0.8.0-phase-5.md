# Gate 5 — v0.8.0 the bias report

**Status: PASSED.** The release's deliverable: a deterministic CLI report that measures the
dataset's bias, emits aggregates only, and — the property that matters more than any single figure
— **doubles as a gate that goes red the day capture changes shape.**

> A dataset whose bias nobody has measured is not an asset; it is a liability with a schema.

---

## 1. Deterministic — proven across processes, not only within one

Two `collect` + `render` passes over the same database are byte-identical
(`test_the_report_is_deterministic_across_two_runs`), and so are two **separate CLI invocations**:

```
$ NETCORENOC_DB=/tmp/bias_cli.db .venv/bin/python -m netcorenoc dataset bias | sha256sum
6ec8c3a3502300db69ab1b72c4ffec43cadca1d34e89c344dfbc4d19e3cddd4f  -

$ NETCORENOC_DB=/tmp/bias_cli.db .venv/bin/python -m netcorenoc dataset bias | sha256sum
6ec8c3a3502300db69ab1b72c4ffec43cadca1d34e89c344dfbc4d19e3cddd4f  -

$ sha256sum tests/fixtures/bias-report.txt
6ec8c3a3502300db69ab1b72c4ffec43cadca1d34e89c344dfbc4d19e3cddd4f  tests/fixtures/bias-report.txt
```

**The same hash three times**, and the third is the checked-in expectation the suite compares
against. The cross-process run is the one that matters: an in-process repeat would still pass if the
report read a clock once and cached it.

What determinism cost, and it is deliberate: every query is `ORDER BY`-stable, every float is
formatted at fixed precision, and **no wall clock is read anywhere** — the label-span figure is
computed against the newest row in the dataset, not against `time.time()`. A report that differed
between two runs could not be a gate.

---

## 2. It is a gate, and the gate fires

`tests/test_bias.py` compares the rendered report **byte for byte** against
`tests/fixtures/bias-report.txt`, built from a fixture constructed in code rather than checked in as
a database — so a schema change surfaces as a *diff in the report* rather than as an unreadable
binary.

**Guard the guard.** `test_the_gate_goes_red_when_capture_shape_changes` injects the smallest
realistic change — **one more evaluated pair**, exactly what a changed `MAX_CANDIDATES` or a new
capture call site would produce — and asserts the output moves:

```
assert after != before, "the bias-report gate did not notice a new captured pair"
assert EXPECTED.read_text() != after, "the frozen expectation went stale"
```

Demonstrated red, then green. A gate that stayed green through one extra row would be measuring
nothing.

The fixture deliberately carries the **awkward** cases rather than a clean corpus — a scoped label,
a zero-member bag, a `legacy_capture` row, a client report that diverges from the server's, and a
bag whose pairs were only partly evaluated. A gate built on the happy path would not notice most of
what this release added.

## 3. Every §8.2 item, and where it is in the output

| Required | In the report | Fixture value |
|---|---|---|
| Confirms versus splits | `-- human labels` | confirm 2, split 2 |
| **Effective sample size, stated as such** | `-- EFFECTIVE SAMPLE SIZE` | bags 4, operators 2, incidents 3 |
| Bag-size distribution **with its interpretation** | `-- bag sizes` | n=3 min=0 med=2 max=3 mean=1.7 |
| Operator concentration | `-- operator concentration` | top 66.7 %, top-3 100 % (1 label unattributed) |
| Labels under a restricting scope + redacted distribution | `-- visibility scope` | 1 label, 2 redacted members |
| Label latency | `-- label latency` | n=3 min=30 med=88 max=599 |
| Coverage, three ways | `-- coverage` | 100 % of situations labelled; 100 % of pairs promoted; per-label full 2 / partial 0 / none 0 / **empty 1** |
| `legacy_capture` vs `current`, **never averaged** | `-- provenance` | legacy 1, current 3 |
| Server/client membership divergence | `-- membership divergence` | 1 reported, 1 diverged |
| Leakage exposure (epochs vs label times; re-fire near-duplicates) | `-- leakage exposure` | 1 distinct epoch; 6 observations over 6 distinct alarms |
| Retention state | `-- retention state` | 21 d / 2 000 000 / 365 d / 730 d |

### Effective sample size is stated as bags, not pairs

The number most often reported wrongly, and the reason this section exists:

```
-- EFFECTIVE SAMPLE SIZE -------------------------------------
independent bags (n)                             4
distinct operators                               2
distinct incidents (merge-aware)                 3

  *n* IS THE NUMBER OF INDEPENDENT BAGS, NOT THE NUMBER OF PAIRS.
```

`distinct_incidents` follows the **merge chain** (`COALESCE(situation.merged_into, …)`), so two
labels on situations that were later merged count as one incident. Treating them as two would
overstate independence — and that column only exists because `0008` added the merge edge.

`test_the_report_states_effective_sample_size_as_bags` asserts the fixture has strictly more pairs
than bags, so the claim is not vacuously true.

## 4. Aggregates only — asserted, not promised

`test_the_report_emits_aggregates_only` checks the rendered text for **every** NE address, OID and
operator name in the fixture and asserts each is absent. The dataset is a scope bypass by
construction (directive 7); the report may say *how many*, never *which*.

**Admin-only** is a property of the surface rather than of a check inside the report: it is a **CLI
subcommand and not a route**, so there is no HTTP path to it at all. The two routes this release does
add — `GET`/`POST /api/dataset/retention` — are `config`-class and `admin_only` in
`rbac.ROUTE_PERMISSIONS` and `rbac.ROUTE_SCOPE`, asserted by `test_the_three_postures_are_all_populated`
(22 → 24 admin-only routes) and by the declaration gate.

## 5. A defect the gate found before a human did

`test_the_report_counts_the_zero_member_bag` failed on first run: a verdict on a situation with **no
members** but one stray pair pointing at it was being recorded as coverage **`full`**.

Vacuously true — `promoted >= expected` where `expected` is `0` — and **misleading**, because a
reader would conclude a complete situation had been captured. Reporting it as `none` would have been
equally wrong in the other direction: it suggests pairs existed and were not found.

So `labels.coverage` gained a **fourth state, `empty`**, and the report counts it separately. The
specification names three cases; all three presuppose a bag with members, and the empty bag is the
degenerate case **Phase 0 discovered** — a verdict posted to an already-merged situation. This is
the decision protocol working as intended: ambiguity about whether to record something resolved
toward recording it.

---

## 6. It trains nothing

No fit, no weights, no split, no prediction, no recommendation about which model to use. There is no
`numpy` and no `scikit-learn` — the distribution helper is four indices into a sorted list, and the
runtime dependency count is **5, unchanged**.

The report closes with what it **cannot** tell anyone:

```
-- what this report CANNOT tell you --------------------------
  * whether a verdict was correct. There is no ground truth here, only
    what an operator said.
  * whether the labels are representative of the network. Operators
    label what they open, and this measures what they labelled.
  * which of the `legacy_capture` rows are actually bad. Nothing
    recorded it, which is precisely why they are marked and not deleted.
  * anything about pairs that were never evaluated. They are absent by
    construction; `partial` coverage counts them, and that is all.
```

A dataset whose limits are not written down invites a later reader to assume it has none — which is
how a measured bias becomes an unmeasured confidence. `test_the_report_says_what_it_cannot_tell_you`
keeps the section from being deleted as noise.

## 7. Placement

`bias.py` (247 lines) measures; `bias_report.py` (210) renders. Split at the seam the `eval/` tooling
already uses — `metrics.py` computes, the harness renders — and because the combined module was 435
lines, over the 400-line guard. Both are `engine`-layer in `tests/test_layers.py`.

Two `make` targets beside `make eval`, which is where they belong: both are deterministic offline
reports over frozen inputs, and both are gates rather than dashboards.

```
make bias-report     # python -m netcorenoc dataset bias
make dataset-stats   # python -m netcorenoc dataset stats
```
