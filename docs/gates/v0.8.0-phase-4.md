## S1 — `correlate.py` returns what it already computed

**The parity gate ran before anything was written**, which is the point of the ordering: if the
scoring seam had moved, nothing after it would have been worth measuring.

```

Correlator.features      sha256=b7742649119e8876da78de16301f1c11a8db41143b0e5735e373ee7a78c4393e
```

Both identical to the digests Gate 0 froze on the untouched v0.7.5 tree, and
`make eval` byte-identical at `c2e8a0ce…`.

The change is one line in the loop and one field on the return value:

```python
evaluated.append(EvaluatedPair(old, result))  # v0.8.0: record, decide nothing
```

`EvaluatedPair` is a **separate type** from `ScoredLink` despite carrying the same two fields,
because conflating them is this release's cardinal error: `ScoredLink` means *"the scorer accepted
this"*, `EvaluatedPair` means *"the scorer looked at this"*, and most of them were rejected or
dropped by the cap.

**`truncated` needs no extra field** — it is derivable as *linked and not in `links`* from what
`process()` now returns, which is what keeps the change additive.

Five tests, including the body-hash anchor, which is checked **separately** from `make eval`
precisely because float arithmetic can be reordered without moving any metric on this corpus.

## S2/S3 — the sink write and the observation row

`capture.py` owns every decision, `store/dataset.py` every statement, `engine.py` gets call sites.

**A defect caught during implementation and worth recording.** The first draft re-derived `A` and
`E` from the learner at capture time. `Engine._process` calls `observe_activation` and
`observe_pairs` **between** `correlator.process()` and capture, so the masses had already moved —
those rows would have been features the scorer never saw, indistinguishable from real ones. That is
the exact trap the specification names for re-scoring, one level down. The values are now read back
from `result.terms`, which carried them all along; v0.7.5 simply dropped them at the persistence
boundary.

Smoke test on `fiber_cut`: **28 evaluated pairs captured where `link` holds 16**, including the
**9 rejected pairs** v0.7.5 discarded, with `A` and `E` stored as *values* (0.1845, 1.0) rather than
contributions.

## S4/S5/S6 — membership, the client fingerprint, promotion

The server writes its own bag from engine state at the instant of the verdict. Verified end to end:

```
situation_alarm for the absorbed id : 0 rows   (still)
feedback JOIN situation_alarm       : 0 rows   (still)
feedback_member(id, 'server')       : [3, 4]   <- RECOVERED
situation.merged_into               : 1        <- the chain, now recoverable
```

An **empty bag is written as empty**, so a verdict on an already-merged situation is countable for
the first time instead of indistinguishable from a real label.

The client's report is the untrusted half: bounded by `ClientFingerprint.accept`, which can only
truncate and records that it did; never rejected; and never used to validate the existence of
anything.

**The one permitted `ui/app.js` change**: `feedback()` takes what the card actually rendered,
captured from the payload *that render* used rather than re-read at click time.

## The two guards that changed the design

### `capture.py` passed the 400-line guard

Split by **path**, not by size: `capture.py` runs per activation on the ingest path under the batch
lock; `labels.py` runs per operator verdict on the HTTP write path. Different frequency, different
lock, different subject matter — the same seam `eval/metrics.py` and the harness already use.

### `engine.py` passed its cohesion ceiling — 542 → 580

The ceiling is a **shrink-only ratchet**, and raising one for convenience is how a ratchet becomes a
comment. Everything extractable was extracted first (`_capture_run` moved to `maintenance.py`,
the prune to `Capture.prune_sink`, the record call compacted). The residual 38 lines are call sites
and two attribute assignments — and **a call site is by definition at the call**.

So the raise is **paid for** by a new guard (DECISIONS #108):

```
test_the_engine_holds_no_capture_logic   — no SQL statement, no dataset table name in engine.py
test_the_capture_module_is_the_one_that_grew — the extraction happened rather than the code vanishing
```

Verified non-vacuous by injecting `INSERT INTO dataset_pair` into `engine.py` and observing red,
then green on restore. **The release ends with a stronger guarantee than it started with**: the old
rule bounded size alone and was satisfiable by a file full of SQL.
