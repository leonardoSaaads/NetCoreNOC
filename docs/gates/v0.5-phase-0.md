# Gate v0.5 — Phase 0 (Comprehension)

Evidence that the v0.5.0 build starts from a genuine understanding of the v0.4.0 system.
Everything in the mandatory reading list was read in full before any file was touched:
`README`, `pyproject.toml`, `Dockerfile`, `Makefile`, `flake.nix`,
`.github/workflows/ci.yml`, `SECURITY.md`, `MIGRATION.md`, `CHANGELOG.md`,
`docs/DECISIONS.md`, `docs/DESIGN.md`, `docs/ROADMAP.md`, all `docs/SCOPE*.md`,
`docs/SECURITY-REVIEW-0.4.md`, `docs/threat-model.md`, `docs/CASE-SCHEMA-DRAFT.md`,
`netcorenoc/rbac.py`, `netcorenoc/shaping.py`, `netcorenoc/correlate.py`, then the full
tree of `netcorenoc/`, `eval/`, `tools/`, `tests/`.

This release is **structure, organization, and growth readiness — no engine change.** The
comprehension below is deliberately weighted toward *where paths are referenced* (Phase 2
moves them), *the three v0.6.0 surfaces* (Phase 5 specifies them), and *the invariants a
restructure must not break*.

## 0. Baseline reconciliation to the authoritative v0.4.0 archive

The maintainer's canonical v0.4.0 is the uploaded `NetCoreNOC0.4.0.zip`; the GitHub
checkout had drifted from it. A file-by-file comparison (archive vs. `git ls-files`) found
exactly:

| Difference | In archive | In checkout | Action |
|---|---|---|---|
| `.github/workflows/ci.yml` | present | **missing** | restored byte-identical from the archive |
| `.gitignore` | present | **missing** | restored byte-identical from the archive |
| `opticorr/` (27 files) | **absent** | present | removed with `git rm` |

`opticorr/` was a stale copy left from the v0.4.0 rename (DECISIONS #34): its `__init__.py`
still declared `OptiCorr` / `__version__ = "0.3.0"`, it lacked `shaping.py` and
`ui/vendor/CHECKSUMS.txt`, and nothing referenced it (not `pyproject` packaging, not the
`Dockerfile`, not `mypy`/`ruff`/`coverage` paths, not a single import in `tests/`, `eval/`,
or `tools/`). It is not part of the authoritative v0.4.0, so it is removed rather than moved.
After reconciliation, `git ls-files` matches the archive's file list exactly and every
tracked file is byte-identical to the archive. (The v0.4.0 phase-0 gate recorded the same
`ci.yml`/`.gitignore` archive-vs-checkout drift, so this is a known packaging artifact, not a
lost change.)

## 2. Repository layout, and every place a path is referenced

Current package layout is **flat**: the import package `netcorenoc/` lives at the repository
root (~20 modules, each ≲300 lines; `ui/` and `migrations/` are package data). Phase 2 adopts
the `src/` layout (`git mv netcorenoc → src/netcorenoc`). The path is referenced in exactly
these places, all of which Phase 2 must update in lockstep:

| Reference | File | Current value |
|---|---|---|
| Package discovery | `pyproject.toml` `[tool.setuptools.packages.find]` | `include = ["netcorenoc*"]` → needs `where = ["src"]` |
| Package data (F12 globs) | `pyproject.toml` `[tool.setuptools.package-data]` | key `netcorenoc = ["migrations/*.sql", "ui/*.html", "ui/*.js", "ui/*.css", "ui/vendor/*", "py.typed"]` |
| Lint source roots | `pyproject.toml` `[tool.ruff] src` | `["netcorenoc", "tools", "tests", "eval"]` |
| Type-check roots | `pyproject.toml` `[tool.mypy] files` + per-module overrides | `["netcorenoc", "tools", "tests", "eval"]`; override on `netcorenoc.receiver` |
| Coverage source | `pyproject.toml` `[tool.coverage.run] source` | `["netcorenoc"]` |
| Image build | `Dockerfile` | `COPY netcorenoc ./netcorenoc` (build stage) |
| Make targets | `Makefile` | `bandit … -r netcorenoc tools`, `vulture netcorenoc …`, `--cov=netcorenoc`, `python -m netcorenoc.main`, `python -m netcorenoc audit …`, the `migrate` one-liner (`from netcorenoc.store import Store`) |
| CI | `.github/workflows/ci.yml` | runs the Make targets by name (so it follows them automatically) |
| d3 checksum path | `tests/test_supply_chain.py` | derives `UI`/`VENDOR`/`REPO_ROOT` from `netcorenoc.__file__`; reads `pyproject` package-data — **resolves against the installed package, so it survives the move** |
| Doc cross-links | `README`, `SECURITY`, `MIGRATION`, `docs/*` | relative links between docs (Phase 2 adds a link checker to catch any that a move breaks) |

The import path stays `netcorenoc` after the move — **no public/API change.** `src/` layout
additionally forces tests to run against the *installed* package, which is exactly what guards
the F12 class of bug going forward.

Documentation is currently a **flat** `docs/` (versioned files side by side). Phase 2 turns it
into a navigable tree: `architecture/` (DESIGN, CASE-SCHEMA-DRAFT, new `repo-map.md`, the v0.6
draft), `adr/` (DECISIONS as one append-only log + `adr/README.md`), `security/`
(threat-model, SECURITY-REVIEW-*, the operator guide split out of root `SECURITY.md`),
`scope/` (SCOPE*), `releases/` (BUILD-REPORT*), `gates/` (unchanged), plus a `docs/README.md`
index. `docs/ROADMAP.md` stays at the docs root (the process document itself references that
exact path). Root-of-repo docs stay per convention (`README`, `LICENSE`, `NOTICE`,
`CHANGELOG`, `CONTRIBUTING`, `CODE_OF_CONDUCT`, `SECURITY`, `MIGRATION`).

## 3. The three surfaces v0.6.0 will make configurable (and why each is already clean)

1. **RBAC permission map — `netcorenoc/rbac.py`.** Single source of truth: `PERMISSIONS`
   (capability → minimum role, `viewer ⊆ editor ⊆ admin` via `ROLE_RANK`), `ROUTE_PERMISSIONS`
   ((method, templated path) → capability), `PUBLIC_ROUTES` (only `POST /api/login`),
   `AUDITED_DENIED_PERMISSIONS`. `api.security` reads these tables; nothing duplicates them
   (F8 collapsed the last duplicate). v0.6.0 makes this data-driven ("admin-defined per-role
   capabilities") — the surface is one dict, deny-by-default, with 401/403/404 semantics.
2. **Role-keyed visibility serializer — `netcorenoc/shaping.py`.** `FIELD_RULES`
   (field name → (min role, coarsen|drop)) drives `shape(obj, role)`, the single place a
   response body is projected by role; the engine/store/audit keep full fidelity. v0.6.0
   generalises this to per-role/per-principal *resource* scoping (which NEs/IPs/hosts a
   principal may see).
3. **Scoring parameters — `netcorenoc/correlate.py`.** Centralised named constants `W_T=0.3`,
   `W_A=0.35`, `W_E=0.35`, `TAU_S=30.0`, `LINK_THRESHOLD=0.5`; `tau` and `threshold` are
   **already instance fields** of the `Correlator` dataclass (defaulting to `TAU_S`/
   `LINK_THRESHOLD`) and are read in `score()`/`process()` from `self`. `W_T`/`W_A`/`W_E` are
   still read as module globals in `score()`. v0.6.0 makes the formula
   admin-/editor-configurable within validated bounds, read where `tau`/`threshold` already
   are — the ingestion hot path (`receiver.datagram_received`) never touches them.

## 4. Invariants this release must not break

- **F12 — the wheel/sdist ships the whole static UI.** `pyproject` package-data globs cover
  every file under `ui/` (`index.html`, `app.js`, `style.css`, `ui/vendor/*` incl.
  `CHECKSUMS.txt`) plus `migrations/*.sql` and `py.typed`.
  `tests/test_supply_chain.py::test_all_ui_assets_are_covered_by_package_data_globs` asserts
  every UI file matches a glob. After the `src/` move, verification is by an **installed-package
  test / freshly built wheel**, never by inspection.
- **F13 — the vendored d3 checksum.** `ui/vendor/CHECKSUMS.txt` pins `d3.v7.min.js` by
  SHA-256; `test_supply_chain.py` and `make checksums` assert it. The strict CSP
  (`default-src 'none'; script-src 'self'; …`) is why d3 is vendored, not CDN-loaded.
- **The frozen eval baseline.** `make eval` must stay byte-identical (§1). Any doc/packaging
  move that relocates the harness must not move a number; the byte-identical JSON reference is
  captured for per-phase diffing.
- **Zero new runtime dependencies.** `[project.dependencies]` stays `pysnmp`, `aiosqlite`,
  `fastapi`, `uvicorn`, `pydantic`. New dev/CI tooling (link checker, SHA-pin lint) lives in
  dev extras or workflows, each justified by a DECISIONS entry.
- **Same runtime identity.** One asyncio process, one SQLite (WAL) file, one static UI,
  environment variables only, no UI build step. Deployment artifacts (Phase 4) wrap this
  identity; they never change it. `.well-known/security.txt` (Phase 3) is the only new served
  path — static, public, additive to the existing `STATIC_ASSETS` allowlist under the existing
  CSP/security-headers middleware.

## 5. The one behaviour-adjacent decision (a non-removal)

The legacy `OPTICORR_*` environment aliases were promised for removal in v0.5.0 (DECISIONS
#34). Removing them in an *organization* release would be an unrelated breaking change, so
Phase 1 extends the deprecation window by one version (record as DECISIONS #39; update the
warning strings in `netcorenoc/main.py` and `netcorenoc/__main__.py` from "v0.5.0" to
"v0.6.0", and `MIGRATION.md`/`docs/ROADMAP.md`). The alias tests
(`test_main.py::test_settings_legacy_env_alias_still_works`,
`test_cli.py::test_audit_export_cli`) assert the presence of the deprecation warning and the
variable names, **not** the version string, so the string bump is safe.

## Consequences carried into the v0.5.0 plan

- Restructure first and mechanically (Phase 2); prove it moved nothing but files (283 tests +
  byte-identical eval + freshly built wheel serves the UI) before writing scaffolding or
  deployment on top of it.
- Every move is a `git mv`; every cross-link a link checker verifies. Never renumber the 38
  existing ADR entries — continue from #39.
- Nothing depends on a push, a pipeline, or an external account to be "done"; committed
  workflows are dormant, opt-in artifacts.
