## 1. The queue → engine → store flow

```
UDP 162 ─▶ receiver.datagram_received        (asyncio DatagramProtocol)
             • allowlist check (counted deny)
             • parse_trap → TrapEvent | quarantine_packet → QuarantinedPacket
             • community HMAC tag computed in-memory (F4), plaintext discarded
             • queue.put_nowait(item)  — NEVER awaits; QueueFull ⇒ stats.dropped++
                   │
                   ▼
        asyncio.Queue(maxsize=QUEUE_SIZE=100_000)
                   │
                   ▼
   Engine.run():  first = await queue.get(); drain up to BATCH_SIZE=500 with get_nowait()
             async with store.lock:            # one lock hold per batch
                 for item in batch: await self._process(item)
                 await store.commit()           # one SQLite txn per batch
             record per-TrapEvent latency (now - item.ts)
```

`Engine._process` per item (`opticorr/main.py:169`):
1. `QuarantinedPacket` → `store.quarantine_packet` and return.
2. `class_id` / `device_id` (cached, cosmetic `last_seen` throttled to 5 s).
3. `_seed_clear_pair` — register universal linkDown→linkUp / rising→falling once per OID.
4. **Alternation observation only while `len(window) < STORM_ALARMS`** (storm guard, DECISIONS 13).
5. If the OID is a known clear class → `_handle_clear` (close alarms, close situation if all cleared) and return.
6. `store.ingest` deduplicates by fingerprint `(device_id, class_id, instance)`; only a
   newly-`activated` alarm continues.
7. Flap demotion (`FlapDetector`, CV test) — a flapping fingerprint stops correlating.
8. `correlator.process` scores the alarm against the 120 s window → `CorrelationResult`.
9. Learning: `observe_activation`, `observe_pairs`, `precedence.observe` (see §3).
10. `_assign_situation` — connected components with merge-on-bridge, stores links + root.

**Invariant that v0.3.0 must not break (prime directive 2):** the datagram path does no
locking and no I/O beyond the single in-memory HMAC. All profiling work in v0.3.0 must land
in the **engine**, under the batch lock the engine already holds, and be flushed by
`maintenance()`. Not one byte of new work enters `datagram_received`.

## 2. Store lock discipline

`Store` holds **one** `aiosqlite.Connection` and one `asyncio.Lock` (`store.lock`,
`opticorr/store.py:63`). The lock exists because SQLite refuses to commit while another
statement is in progress on the same connection: an API read cursor interleaving with the
engine's batch commit crashed the engine under load (DECISIONS 12). Rules:

- The **engine** takes `store.lock` once per drained batch and once per `maintenance()` pass.
- Every **API handler** takes `store.lock` around its reads/writes and its own `commit()`.
- **Audit rows are written under the lock the handler already holds** — no extra lock.
- `maintenance()` (every `MAINT_INTERVAL_S=5 s`) closes idle situations, `learner.save` +
  `precedence.save` (flush dirty edges + JSON marginals to `meta`), purges expired sessions,
  and prunes every 12th tick. This is where v0.3.0's profiler flush and prune belong.

## 3. The learning triggers

`Learner` (`opticorr/learn.py`) owns matrices `A` (class×class) and `E` (device×device),
each a symmetric decayed co-occurrence mass with NPMI scoring, plus `ClearPairLearner`.

- **`observe_activation((class_id, device_id))`** — bumps the two marginals (activation
  totals). Called once per activated alarm.
- **`observe_pairs(new, others, storm)`** — the per-event window trigger. For each *distinct*
  other class it does one `A.observe_pair`; for each *distinct* other device (≠ own) one
  `E.observe_pair`. Weight is `STORM_DAMPING=0.1` in a storm. "One observation per activation
  per distinct other" keeps pair mass ≤ activation total so NPMI stays meaningful (DECISIONS 9).
- **`learn_epoch(members)`** — the closed/confirmed-situation trigger. `A.tick()` + `E.tick()`
  advance the forgetting epoch (lazy `(1-λ)^Δepoch` decay, λ=0.05), then each distinct class
  pair / device pair in the situation is reinforced once (damped if the situation is a storm).
- **`penalize(members)`** — the `split` feedback: halve (`SPLIT_PENALTY=0.5`) each distinct
  pair mass grouped together, once.
- `class_affinity = A.npmi`; `device_affinity` returns `1.0` for the same device, else
  `E.npmi` gated by `pair_mass ≥ MIN_EDGE_N=5`. **v0.3.0 renames this to `entity_affinity`
  keyed at NE level (§5.5); before any promotion each NE has exactly one entity so the value
  is numerically identical — the mechanical basis of the parity gate.**
- `ClearPairLearner.observe` learns raise→clear from ≥`CLEAR_CYCLES_TO_LEARN=2` strict
  alternations on a `(device_id, instance)` slot; seeded pairs are pre-registered. **v0.3.0
  adds a varbind-level state learner alongside this, additively (§5.4).**

Root cause (`rootcause.Precedence`): per ordered class/device pair, "who fires first" mass;
`pick_root` scores the earliest `ROOT_SAMPLE=25` members. Bounded-work caps everywhere
(`MAX_CANDIDATES=100`, `LEARN_CAP=20`, `MAX_LINKS_PER_ALARM=5`) keep storms linear.

## 4. The RBAC map

`opticorr/rbac.py` is the single source of truth, consumed by both the FastAPI `security`
dependency and the Phase-4 matrix / fail-closed tests — there is never a second copy.

- `ROLE_RANK`: viewer(0) ⊆ editor(1) ⊆ admin(2).
- `PERMISSIONS`: capability → minimum role (e.g. `situations.read`→viewer, `feedback.write`→
  editor, `audit.read`→admin).
- `ROUTE_PERMISSIONS`: `(METHOD, templated_path)` → capability. A route absent here **and**
  not in `PUBLIC_ROUTES` fails closed (401/403) at runtime and fails CI
  (`test_every_api_route_has_permission`).
- HTTP contract: 401 unauthenticated, 403 authenticated-but-insufficient, 404 only *after*
  authorization (no existence oracle). `AUDITED_DENIED_PERMISSIONS` lists denied (403)
  actions that are still audited.

**v0.3.0 adds** one capability (`entity.reset`, admin-only) plus read access to the entity
tree/profiles for viewer+, added to this one map and covered by the existing matrix test.

## 5. The audit chain

`opticorr/audit.py` + migration `0002`. `audit_log` is append-only at the storage layer
(`BEFORE UPDATE`/`BEFORE DELETE` triggers `RAISE(ABORT)`) and hash-chained:
`entry_hash = sha256(prev_hash + canonical)`, `canonical = json.dumps({id,ts,actor,role,
source_ip,action,object_type,object_id,outcome,details}, sort_keys, separators=(",",":"))`,
genesis `prev_hash` = 64 zeros. The row id is reserved as `MAX(id)+1` under the store lock so
the id inside the hash matches the stored id; only the oldest rows are ever pruned.

- `ACTIONS` is the frozen catalog; `write_event` asserts `action in ACTIONS`. Every mutating
  endpoint and sensitive read (including denied attempts) writes exactly one row.
- `verify_chain` walks in id order and reports the first broken link; a pruned prefix is
  accepted (the surviving first row's `prev_hash` is the archived boundary anchor).
- The only sanctioned deleter is `Store.prune_audit` (drop → delete → recreate triggers in
  one locked, audited txn — DECISIONS 14).

**v0.3.0 adds** system-actor audit actions `entity.promote`, `entity.reset`, `profile.reset`,
`ingest.gap`, added to `ACTIONS` and covered exactly as the v0.2.0 actions by
`test_audit_catalog_completeness`.

## 6. The two failure modes v0.3.0 targets (from the brief §2)

1. **Proxied reporting** — `device_id` = trap source IP assumes sender == sufferer; an OLT
   reporting 5 000 ONUs collapses or explodes.
2. **`_instance_of` fails silently** (`receiver.py:190`): "ifIndex else first non-standard
   varbind". When that varbind is a timestamp / sequence / serial, `instance` is unique per
   trap → dedup never fires, flap detector never repeats, `ClearPairLearner` (keyed by
   `(device_id, instance)`) never alternates. Degrades to "no learning" with no error.

Both are replaced by the learned entity model. The exact edit sites are catalogued above:
`receiver._instance_of` / `parse_trap`, `correlate.process` (O(1) window index, §5.6),
`learn.device_affinity` → `entity_affinity`, new `varbind_profile.py`, migration
`0003_entity.sql`, and the legacy-token removal.
