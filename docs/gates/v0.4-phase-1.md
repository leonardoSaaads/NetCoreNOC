# Gate v0.4 — Phase 1 (Rename gate + scope/threat-model/standards baseline)

## Part A — the rebrand rename gate (DECISIONS #34)

The rebrand `NewProjectNetworj`/`OptiCorr` → **NetCoreNOC** landed as one mechanical,
test-covered change set before any feature work.

**Scope executed**
- **Package**: `opticorr/` → `netcorenoc/` (`git mv`); every `import`/`from`, `python -m …`,
  `[tool.setuptools]`, `[tool.mypy] files`, `[tool.coverage] source`, `[tool.ruff] src`,
  Makefile targets, and the `mypy` module overrides updated.
- **Metadata**: `pyproject.toml` name/description/authors/Homepage
  (`github.com/leonardoSaaads/NetCoreNOC`), `flake.nix` package/app names, `Dockerfile`
  user/paths/labels, the README CI badge and `nix run` line.
- **Wire identifiers, with a one-version compatibility window** (treated like the v0.2.0
  legacy-token deprecation):
  - Env prefix `OPTICORR_*` → `NETCORENOC_*`; legacy names honoured for one version with a
    single startup deprecation warning per variable (naming the variable, never its value);
    removal is a v0.5.0 ROADMAP line + MIGRATION note. `NETCORENOC_*` wins if both are set.
  - Session cookie `opticorr_session` → `netcorenoc_session` (one forced re-login, documented).
  - CSRF header `X-OptiCorr-Client` → `X-NetCoreNOC-Client` — changed in UI **and** server in the
    same commit, no compatibility window (not a persisted credential).
- **User-facing**: UI `<title>` and header/login wordmark, bootstrap banner, FastAPI title,
  logger name (`getLogger("netcorenoc")`), README/docs prose.

**Gate results (rename changes names, never behaviour)**

| Check | Result |
|---|---|
| `ruff check .` / `ruff format --check .` | All checks passed / 50 files formatted |
| `mypy --strict` | Success, no issues in 50 files |
| `pytest` | **226 passed** (224 + 2 new legacy-env-alias tests) |
| `make eval` delta table | **byte-identical** to the pre-rename run (only the printed header brand changed) — `pairwise_f1=1.0000`, `ari=0.9999`, `entity_accuracy=0.4480`, `root_top1=1.0000`, no gated regressions |

**Backward-compat is regression-tested**: `test_settings_legacy_env_alias_still_works` (one
warning per variable, names the new var, never the value), `test_settings_new_env_takes_precedence_over_legacy`,
and `test_audit_export_cli` drives the legacy `OPTICORR_DB` through the CLI and asserts the
deprecation notice.

**Residual scan**: no lowercase `opticorr` or `NewProjectNetworj` survives outside historical
records (CHANGELOG, `docs/gates/*`, old BUILD-REPORTs/SCOPE/SECURITY-REVIEW-0.2) and the two
places the legacy names are *supposed* to remain — the `OPTICORR_*` deprecation narrative
(MIGRATION, README note, DECISIONS #34) and the historical `OPTICORR_API_TOKEN` removed-token
fact.
