# Gate v0.4 — Phase 2 (Design)

## 1. Schema change — none

**No migration ships in v0.4.0.** The chosen work (response shaping, task supervision, readiness,
store-integrity checks, graceful shutdown, container hardening, corpus/simulator) is
presentation-, control-, or tooling-side and touches no table or column. The one change that would
require a `0005_*.sql` — the `alarm.device_id` → `entity_id`/`ne_id` cutover — is re-deferred to
v0.5.0 (DECISIONS #35). So `PRAGMA user_version` stays at **4**.

Because there is no new migration, the Gate-2 "applies cleanly to a populated v0.3.0 database"
requirement reduces to: the existing v0.1→v0.4 migration path still applies to a populated DB with
data intact, audit triggers active, and the audit chain still verifying. This is exercised by
`tests/test_migration.py` (part of the green 226-test run) — it opens a populated fixture, migrates,
and verifies rows, triggers, and the hash chain survive.

## 2. Design notes — complete

`docs/DESIGN.md` gained a **v0.4.0** section covering:
- the response-shaping serializer (`netcorenoc/shaping.py`) and its role model (minimum-role per
  field, redact/coarsen below it, deny-by-default, one decision point);
- task supervision (log → backoff-restart-where-safe → `operator_warnings()`, never touching the
  datagram path);
- the readiness signal (`/readyz`, unauthenticated, ok/not-ok only, no detail leak);
- store integrity + fault handling (startup `integrity_check`/`foreign_key_check` that warns;
  `OperationalError` caught without breaking the chain);
- graceful shutdown (drain + flush + final commit within a deadline; chain consistent on interrupt);
- the UI design-token system + role-gated rendering (all in `style.css`; hidden not disabled; F1
  intact; four files);
- where the trap simulator lives (`eval/`/`tools/` only, never imported by `netcorenoc/`).

## 3. Migration doc — updated

`MIGRATION.md` retitled to NetCoreNOC and gained a **v0.3.0 → v0.4.0** section: the rebrand
(env-var aliases honoured one version + deprecation warning; cookie rename → one forced re-login;
CSRF header change; new package/module entry points), the no-migration upgrade path, and the
statement that learned state (matrices, promoted entities), sessions, tokens, and the audit chain
all survive and still verify.

**Gate 2: PASSED.** No migration to apply (stated explicitly); the existing migration path holds on
a populated v0.3.0 fixture with data intact, triggers active, and the chain verifying
(`test_migration.py`); design and migration notes complete.
