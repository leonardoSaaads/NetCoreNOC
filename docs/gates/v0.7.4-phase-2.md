## 1. F40 — the gate covered three verbs and only the decorator form

### The fix

`api/declare.py` gains `assert_every_route_is_declared(app)`, and `api/app.py` calls it **as the
last statement of `create_app`, before `return app`**.

```python
def assert_every_route_is_declared(app: FastAPI) -> None:
    for route in app.routes:
        path = getattr(route, "path", None)
        if path is None:
            continue
        for method in sorted(getattr(route, "methods", set()) or set()):
            if method not in ("HEAD", "OPTIONS"):
                require_declaration(method, path)
```

### Why it is complete by construction rather than by enumeration

The alternative — wrapping `put` and `patch` on `DeclaredRoutes`, and gating the non-decorator
registration form — would work, and would work only for the paths that exist today. It is a list,
and the next registration mechanism is not on it.

This assertion contains **no list of registration mechanisms**. It inspects the *result*: whatever
path a route took to get onto the application, it is on `app.routes` when `create_app` finishes, and
every entry there is put back through the same `require_declaration` the decorator calls. A
mechanism nobody has written yet still produces a route, so it is still caught.

### The decorator-time refusal is kept as well (directive 4)

The gate got a **second** check, not a replacement. Failing at the point of registration names the
route in the file the contributor is editing; failing at the end of `create_app` names it three
hundred lines away. `test_f40_the_decorator_time_refusal_is_kept_as_well` pins that both exist.

### It runs before `create_app` returns, and a test asserts that

A guard that runs only under test is a guard an operator can ship past.
`test_f40_the_assertion_runs_before_create_app_returns` parses `create_app`'s own source and asserts
that nothing but `return app` follows the call — so the assertion cannot be quietly moved into a
test helper later.

## 2. F41 — the exemption was a path prefix, not an absence of capability

### The fix

`require_declaration`'s `if not path.startswith("/api"): return` becomes a consultation of an
explicit allowlist:

```python
UNAUTHENTICATED_PATHS: frozenset[str] = frozenset({
    "/healthz", "/readyz", "/", "/openapi.json",
    "/app.js", "/style.css", "/vendor/d3.v7.min.js", "/.well-known/security.txt",
})
```

Membership is now a **reviewable claim** — "no capability is required to fetch this" — rather than a
consequence of a path not starting with four characters.

### Asserted against what is actually served, in both directions

`declare.py` cannot import `routes_static.py`: that module registers *through* this one, so the
import would be circular. The build prompt permits either derivation or assertion; assertion is what
is possible here, and it is done **twice**, from two independent directions:

| Test | Checks the allowlist against |
|---|---|
| `test_f41_the_allowlist_matches_what_is_actually_served` | `routes_static.STATIC_ASSETS` + the health surface + the schema route — the **source** |
| `test_f41_the_allowlist_is_exactly_the_live_non_api_surface` | every non-`/api` route on a **built app** |

The second exists because the first cannot see `/openapi.json`: FastAPI registers it itself, and no
source-level derivation over `routes_static.py` would ever mention it. A derivation that silently
omitted a served public path would be exactly the drift the allowlist is supposed to prevent.

### A note on `/openapi.json`

It is on the allowlist because it **is** served without an identity on this surface — the set is a
statement about what the appliance serves, not about who registered it. Whether the schema *should*
be public is a separate question, out of scope here (directive 5), and it is recorded as a ROADMAP
line and in `SECURITY-REVIEW-0.7.4.md`'s critical analysis rather than changed in a release whose
parity story forbids it.


**The 9 that pass on both trees are the point of the other half.** They are the eight
`test_f41_every_currently_served_public_path_is_still_accepted` cases and
`test_f40_the_decorator_time_refusal_is_kept_as_well` — the direction the fix must **not** change.
A regression test that only fails-then-passes proves the hole was closed; these prove nothing else
was.

### One test-design correction made to get an honest proof

The first version parametrised the public-surface test over `declare.UNAUTHENTICATED_PATHS`. That
made the whole module **uncollectable** against the old tree (`AttributeError` at import), so the
stash run reported a collection error rather than ten assertion failures — a proof that the symbol
is new, not that the behaviour is.

It now parametrises over the surface derived from `routes_static.STATIC_ASSETS`, which is
independent of the constant under test. That collects on both trees, and it is better test design
anyway: parametrising over the allowlist would have made the test **vacuous if the allowlist were
ever emptied**.

### One source rewording forced by an existing guard, and it is worth recording

`test_add_api_route_is_confined_to_the_static_asset_allowlist` greps the **text** of every module
under `api/` for the string `add_api_route` and asserts exactly one file contains it. Writing that
name in a *docstring* in `declare.py` and in a *comment* in `app.py` made the count 3, and the test
failed.

Since that assertion must pass unedited, the prose was reworded to describe the mechanism without
naming it ("a route registered directly on the FastAPI application"). The **actual** caller count is
unchanged at one.

That is a real, if minor, weakness in a text-scanning guard: it cannot distinguish a call from a
mention. It is **not fixed here** — directive 5 — and is recorded as a `docs/ROADMAP.md` line and in
`SECURITY-REVIEW-0.7.4.md`'s critical analysis.
