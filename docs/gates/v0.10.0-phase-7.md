## 6. Insufficiency, in both directions

**The direction a build is tempted to skip is the second, and it is here.**

| corpus | verdict | why it matters |
|---|---|---|
| the real corpus (37 incidents, 0 asserting bags) | `INSUFFICIENT_EVIDENCE` | four triggers fire; **no quality claim is made** |
| a purpose-built **sufficient** fixture | `BETTER` | `test_the_clean_corpus_fires_no_trigger_and_can_reach_better` |
| the same fixture, one field perturbed | `NOT_BETTER` | `test_not_better_is_reachable_and_is_not_insufficiency` |

Without the second and third rows, *"the verdict is `INSUFFICIENT_EVIDENCE`"* would be consistent
with a judge that can return nothing else — and every trigger test would pass for the wrong reason.
`test_the_clean_corpus_fires_no_trigger_and_can_reach_better` is the control for the whole trigger
suite and is named as such.

### Coverage — measured, and 0.02 points below the baseline

The brief asks for coverage **at or above 96.22 %**. Measured on the release tree:

```
$ python -m pytest -q --cov=netcorenoc --cov-report=term
TOTAL   6666 stmts   186 miss   1462 branch   123 partial   96%
exact: 96.20%
1174 passed in 644.08s
```

**96.20 % against a 96.22 % baseline — 0.02 points below, and it is reported rather than
adjusted.** Two thousandths of the tree, on 6 666 statements and 1 462 branches. The honest
description is *unchanged*; the honest arithmetic is *below*, and a build that rounded 96.20 up to
"at or above 96.22" would be doing the thing this release exists to make harder.

The new modules individually:

```
incidents.py            100%
judge.py                100%
seal.py                 100%
shadow_assertions.py    100%
store/seal.py           100%
shadow_cv.py             95%   (lines 173, 213)
census.py                73%   (measured on a subset; the whole suite covers more)
```

`shadow_cv.py`'s two uncovered lines are both **degenerate guards**: `if not values: return
Interval(0, 0, 0, 0)` and `if n <= 0: return 1.0`. Neither is reachable from any call site in the
package — every caller passes a non-empty mapping and a positive `n` — so covering them would mean
writing a test for an argument the code cannot receive. They are kept because a bootstrap that
divided by zero on an empty corpus would be a worse failure than an unexercised branch, and they are
named here rather than deleted to buy back two hundredths of a percent.
