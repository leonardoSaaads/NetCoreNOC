## 1. Queue → engine → store flow, and the store lock discipline

- **Receiver** (`receiver.py`): `TrapReceiver.datagram_received` runs on the UDP callback. It
  does allowlist check → defensive `parse_trap` (v2c, or v1 via RFC 3584 §3.1) → `queue.put_nowait`.
  A parse failure becomes a `QuarantinedPacket` (community octets blanked, F4); a full queue
  increments `stats.dropped` and returns. **No lock, no I/O, no await** on this path — Invariant 2.
- **Queue**: one `asyncio.Queue(maxsize=100_000)`.
- **Engine** (`main.py::Engine.run`): pulls one item, greedily batches up to `BATCH_SIZE=500`
  from a non-empty queue, then `async with self.store.lock:` processes the whole batch and
  `commit()`s **once**. Per `TrapEvent` latency (`now - item.ts`) is sampled after commit.
- **`_process`** (per item): `class_id`/`device_id`/`ne_id` (cached id lookups) → `profiler.observe`
  (in-memory, observe-only) → `_resolve_entity` (walk the NE discriminator chain to the finest
  present entity; `MAX_ENTITIES_PER_NE` caps it, never fails) → `_resolve_severity` →
  `_seed_clear_pair` → learning observation (**paused during storms**, `len(index) < STORM_ALARMS`)
  → clear / state-clear handling, else `store.ingest` (dedup by fingerprint) → flap demotion →
  `correlator.process` (sliding-window scoring t·A·E) → `observe_activation`/`observe_pairs`/
  `precedence.observe` → `_assign_situation` (connected components, merge on bridging links, pick
  root by precedence).
- **Lock discipline** (`store.py`): a single `aiosqlite` connection guarded by `self.lock`
  (`asyncio.Lock`). The engine holds it per batch; every API handler holds it per request; identity
  resolution holds it. SQLite refuses to commit while another statement is open, so the lock is
  what makes "one connection, many tasks" safe — a commit can never interleave with another task's
  cursor. **`audit.write_event` is always called under this lock.** Interleaved API writes join the
  engine's open transaction (a throughput choice, explicitly not an atomicity contract).

## 2. Learning triggers

- **Affinity (A / class)**: `learner.observe_activation(item)` and `observe_pairs(new, recent, storm)`
  build the co-occurrence matrix (npmi); `learn_epoch(members)` fires on situation close and on a
  `confirm` feedback; `penalize(members)` fires on a `split` feedback.
- **Precedence (E / root cause)**: `precedence.observe(lead, lag, weight)` per considered window
  member (`STORM_DAMPING` weight during storms); `pick_root` chooses the situation root.
- **Clears**: `learner.clears.observe(device_id, instance, class_id)` learns raise↔clear by
  alternation; `known_oids.CLEAR_PAIR_SEEDS` seeds the universal standard pairs; state-clear fields
  learned by `learner.states.observe(...)` / `is_clear(...)`.
- **Varbind profiler → promotion**: `profiler.observe(ne, class, varbinds, ts)` on **every** trap
  (repeats are the signal). Once per maintenance pass `_promotion_sweep` calls
  `profiler.promotion_chain(ne)` (entity discriminator, R/X/D score) and `_maybe_confirm_severity`
  (a small ordinal cross-class field validated against observed alarm lifetimes). Both are
  forward-only, audited (`entity.promote` / `severity.confirm`), and resettable by an admin (S11).

## 3. RBAC map and the CSRF / identity middleware chain (`api.py`)

`rbac.py` is the **single source of truth**: `PERMISSIONS` (capability → minimum role,
viewer⊆editor⊆admin via `ROLE_RANK`), `ROUTE_PERMISSIONS` ((method, templated path) → capability),
`PUBLIC_ROUTES` (only `POST /api/login`), and `AUDITED_DENIED_PERMISSIONS`. The `security`
dependency runs, in order:

1. **CSRF** — cookie-authenticated mutations only: `origin`/`referer` netloc must equal `host`
   **and** header `X-OptiCorr-Client: ui` must be present.
2. **Identity** — Bearer service token or `opticorr_session` cookie, resolved under `store.lock`.
3. **Bootstrap gate** — a principal owing a forced password change is limited to `BOOTSTRAP_ALLOWED`.
4. **RBAC** — `permission_for(method, path)`; `None` (unmapped route) **fails closed**; denied
   sensitive permissions are audited via `DENIED_ACTION`.
5. **Rate limit** — per-client token bucket.

A separate `security_headers` HTTP middleware sets the strict CSP and the security headers, plus
`Cache-Control: no-store` on `/api`.

**Confirmed loose ends (seeds for the F7 review):** `rbac.AUDITED_DENIED_PERMISSIONS` is defined
but unreferenced; `api.DENIED_ACTION` duplicates its key set — two tables for one fact. `auth.ROLES`
(line 48) and `auth.now_s()` (line 303) are dead. `GET /api/config` is gated by `config.write`
(a read behind a write capability). `learn.device_affinity` + the `alarm.device_id` column remain
the v0.2.0 shim promised for removal — woven through `correlate.py`, `rootcause.py`, `store.py`, and
several tests.

## 4. Audit hash chain

`entry_hash = sha256(prev_hash + canonical(entry))`, `canonical` = deterministic JSON over
`CANONICAL_KEYS`, genesis `prev_hash` = 64 zeros (`audit.py`). Rows are append-only at the storage
layer via `BEFORE UPDATE` / `BEFORE DELETE` triggers (migration `0002`), so any edit to history
breaks the chain. `verify_chain` walks in id order and reports the first broken link (genesis-anchor
or archived-boundary aware for pruned logs). `write_event` reserves `MAX(id)+1` under the lock and
redacts `_FORBIDDEN_DETAIL_KEYS` defensively. CLI: `python -m opticorr audit verify|export`.

## 5. The `eval/` harness gates

`eval/harness.py` replays every `eval/corpus/*.json` scenario **offline** through the real engine
(injected clock, fixed seeds → deterministic), scores each against ground truth (`metrics.py`), and
prints a delta table vs the frozen `eval/baselines/v0.2.0.json`. It exits non-zero if any
`GATE_METRIC` drops more than `GATE_TOLERANCE=0.01`. `make eval` runs it; `--cold` reproduces the
v0.2.0 parity (no promotion sweep). This build must leave this table non-regressing.

## Consequences carried into the v0.4.0 plan

- The rename must not touch behaviour: the eval delta stays byte-identical (Gate 1).
- Reliability work lives entirely on the maintenance / HTTP side; `datagram_received` is frozen.
- The `device_id` cutover is **re-deferred** to v0.5.0 (DECISIONS #35) — it is core-path churn, and
  this is a safety release ("if in doubt, re-defer").
- The two duplicated RBAC tables collapse to one with a divergence test (S1).
