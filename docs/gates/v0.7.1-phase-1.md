## 2. The four tests that pass on both trees, and why that is correct

These are **guards**, not reproductions. They must pass before *and* after, and they are what stops
each fix from over-correcting:

| Test | Guards against |
|---|---|
| `test_f34_an_in_scope_editor_can_still_write` | the perimeter becoming a lockout — an editor scoped to everything must still write |
| `test_f37_label_writes_to_real_targets_still_work` | the existence check breaking the feature it guards |
| `test_f38_the_unrestricted_result_set_is_unchanged` | the SQL change moving the unscoped result set (parity by construction) |
| `test_f36_closing_a_situation_still_ticks_the_epoch` | moving the tick off the feedback path removing it from the path that owns it |

`test_f36_closing_a_situation_still_ticks_the_epoch` passing now is exactly right: v0.7.0 already
ticks on close, and the F36 fix must not change that.

  §3 records every deferral with the version that owns it; §4 restates the ten invariants.

  | # | Decision | Finding |
  |---|---|---|
  | 65 | A write is inside the perimeter or it is a defect — and it denies through the *existing* 404 | F34 |
  | 66 | Scope selectors resolve against NE identity and address only — never operator-writable data | F35 |
  | 67 | The timeline filters on NE identity, not on a rendered display string | F35 |

  | 69 | The learning epoch belongs to a closed situation, not to feedback | F36 |
  | 70 | A label write to a nonexistent target is a 404 — and the affected tests are repaired, not weakened | F37 |

  | 72 | Truncation applies to the filtered set: the scope predicate moves into the SQL | F38 |
  | 73 | One transaction discipline, implemented once | F39 |
  | 74 | The perimeter extraction is v0.7.2's theme; its shape is recorded now and none of it built here | — |

- Nothing is fixed yet. `src/` is unchanged; the only edits are tests and documentation.
- The 11 failures above are the *desired* state at Gate 1. Gate 3 requires all of them green, all
