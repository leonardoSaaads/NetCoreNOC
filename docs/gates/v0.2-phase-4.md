# v0.2 Gate 4 — Verification (P0)

Date: 2026-07-20. Verdict: **PASS**.

All Phase-4 checks green. 171 tests pass; coverage 94.63%; ruff, `mypy --strict`, bandit,
pip-audit clean.

## 1. Authorization matrix (`tests/test_rbac.py`)

Parametrized over **every** registered `/api` route × {anonymous, viewer, editor, admin} ×
method, with expectations generated from the `rbac.py` map itself:

- anonymous ⇒ 401; authenticated-but-insufficient ⇒ 403; authorized ⇒ never 401/403.
- **Fail-closed**: `test_every_api_route_is_in_the_permission_map` walks `app.routes` and
  fails if any `/api` route (not in `PUBLIC_ROUTES`) is missing from `ROUTE_PERMISSIONS`.
- **No oracle**: `DELETE /api/users/999999` ⇒ 403 for an editor (missing resource still
  hidden), 404 for an admin — authorization precedes resource lookup.

## 2. Sessions (`tests/test_auth.py`)

Idle expiry (30 m, purged), absolute expiry (12 h even with activity), idle sliding,
logout revocation, password-change revokes all sessions, role-change revokes sessions,
**fixation rejected** (a fresh id every login), cookie flags (`HttpOnly; SameSite=Strict;
Path=/`), and `Secure` present only when TLS is enabled.

## 3. Throttling (`tests/test_auth.py`)

Lockout begins at the 5th consecutive failure and backs off 1 → 2 → 4 s, capped at 900 s;
per-username **and** per-IP; resets on success. **No enumeration**: unknown-user and
wrong-password return an identical 401 message (a dummy scrypt runs for absent users).

## 4. XSS and headers (`tests/test_security_ui.py`, live browser)

Hostile payloads (`<img onerror>`, `<script>`, event handlers) persisted through the real
ingest path in instance / varbind / label; responses are JSON-clean (data, not markup).
CSP and `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy` asserted on every
route class; `Cache-Control: no-store` on `/api`. A real headless-Chromium run confirmed
the payload does not execute under the live CSP.

## 5. Audit completeness and integrity (`tests/test_audit.py`)

Every catalog action emitted and asserted (auth, management, operation, sensitive reads),
denied sensitive attempts recorded with `outcome=denied`. Tamper test edits a row via raw
SQLite (triggers dropped) and `verify_chain` reports the exact broken id. Append-only
triggers abort `UPDATE`/`DELETE`. `details` never carries a password, token value, or
community string (unit + end-to-end).

## 6. Secret-leak scan (`tests/test_findings.py`)

Login + token-creation + user-creation flows run under `caplog`; every secret value used
(passwords, session id, service-token value) is grepped for across all captured log lines
— none present. The root-logger `RedactionFilter` masks bearer tokens, cookies, and
`key=value` secrets as defense in depth.

## 7. Performance regression

In-process, auth + audit active: **60,000 events, 0 dropped**, engine drain ≈ 2,115
traps/s, API p50 447 ms / p95 514 ms / max 1.63 s during the storm; audit chain verified
OK afterward. `tests/test_perf.py` guards the invariant (zero loss + audit rows written
during a concurrent storm) on every CI run. (The full 1000 traps/s × 60 s UDP path is
`make loadtest`; the v0.1.0 soak envelope is unchanged — auth/audit are HTTP-side only.)

## 8. Migration (`tests/test_migration.py`)

Populated v0.1.0 DB (schema v1, seeded) → open with v0.2.0 `Store` → `user_version` 2,
v0.1.0 data intact, `user`/`session`/`api_token`/`audit_log` present, append-only triggers
active, a legacy quarantine row still reads back, bootstrap admin creatable. Forward-only
and idempotent across repeated opens.

## 9. Static analysis / coverage

`bandit` 0 issues (targeted `# nosec` with justifications), `pip-audit` no known
vulnerabilities, coverage 94.63% (gate ≥ 85%; ≥ v0.1.0 97.22% − 3 = 94.22%).

**Gate 4: PASS** — every verification item green with numbers recorded. Ready for Phase 5
(release).
