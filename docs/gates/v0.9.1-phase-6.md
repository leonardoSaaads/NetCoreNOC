## 5. Packaging, linters, coverage

### 5.0 A gate this document originally claimed and had not run

**`make deadcode` was not executed before the release commit, and CI caught it.** This section
originally read "packaging, linters, guards ✅" on the strength of `ruff`, `mypy`, `pytest` and
`eval` having been run **individually**. `make qa` is `lint typecheck deadcode test eval`, and the
one target in it that had never been invoked is the one that failed:

```
$ make deadcode PYTHON=python
src/netcorenoc/store/feedback.py:162: unused method 'feedback_exclusion' (60% confidence)
make: *** [Makefile:17: deadcode] Error 3
```

Recorded rather than quietly fixed, because the failure is procedural and the lesson generalises:
**running a target's constituent commands is not running the target.** Every gate in
`.github/workflows/ci.yml` has now been run as CI runs it (§5.2), and `make qa` end to end (§8).

**The fix, and why it is an allowlist entry rather than a code change.** `feedback_exclusion` is the
read accessor for the child table `0010` added, and nothing in the runtime package reads it — for
the same reason and at the same point in the same arc as `feedback_members` in v0.8.0: **this
release captures the assertion and does not consume it.** The reports need only aggregates
(`excluded_count`, and `m·(n−m)` from the label row); the consumer of the member ids is v0.10.0,
where an asserted negative becomes a training row. `vulture_allowlist.py`'s own header names
"methods exercised only from the test suite" as what it exists for, and the sibling entry makes
exactly this argument. Deleting the accessor would push a `SELECT … ORDER BY position` into six test
assertions and leave v0.10.0 to re-derive a query this release already got right; inventing a
production caller to satisfy a linter would be worse.

### 5.1 A second defect the dead-code gate structurally could not catch

Diffing vulture's **unsuppressed** output against the v0.9.0 base showed two arrivals, not one:

```
NEW:  store/feedback.py: unused method 'feedback_exclusion'
NEW:  store/feedback.py: unused method 'feedback_members'
GONE: store/dataset.py:  unused method 'feedback_members'
```

`feedback_members` did not become dead — **it moved**, in DECISIONS #128. **Vulture matches by name,
not by path**, so its exemption followed it silently and the gate stayed green while the allowlist's
comment went on naming `store/dataset.py`, a file that no longer contains it. Corrected, and
recorded in `docs/ROADMAP.md`: an allowlist that cannot notice a move is one whose provenance decays
without anything ever going red.
