# v0.9.2 — Gate 5: the demonstrated guards

> **A guard nobody has watched fail is not a guard. Green is not evidence; green *after a recorded
> red* is evidence.**

Every guard this release ships is below, in one shape: the guard named, the **exact defect injected
as a diff against the corrected tree**, the command, the verbatim **red**, the verbatim **green**,
and the **control that had to pass in both runs**.

A guard with no recorded red blocks this gate. A guard whose control was absent blocks this gate —
the reviewer's first probe of the declaration gate reported CAUGHT for everything because the
default `/docs` route was itself undeclared, and every conclusion was worthless until a control was
added.

---

## Method

A harness applies an exact textual patch to the **corrected** tree, runs the guards and the control,
records the output, reverts with `git checkout --`, and runs again. Each case records four things:

* the **diff** — what the tree actually looked like when the red was recorded, generated by
  `git diff` rather than transcribed;
* the **red** — the guards under the injection, verbatim;
* the **green** — the same guards *plus the control*, on the unmodified tree, verbatim;
* the **control under the injection** — which must pass, or the red proves only that something
  broke.

The controls are named per case rather than shared, because a single global control would pass for
reasons unrelated to the defect under test.

**Two populations, reported separately.** §1 is the **mandatory** list — the defects this release was
required to prove it would notice. §2 is the **mutation ledger**: a further set seeded across the
release's own surface, where the interesting result is the survivors, not the ratio.

## 3. The ledger, and what its survivors bought

**The ratio is not the result.** It is reported because leaving it out would look like hiding it, and
it is followed immediately by the part that matters.

| run | caught |
|---|---|
| the ledger's **first** run, before any repair | **9 of 15** |
| after the repairs below | **15 of 15** |

The second number is the weaker of the two. A ledger that catches everything after you have fixed
what it caught is not evidence about the suite; it is evidence that you read your own output. **The
first run is the measurement**, and its six survivors each named a real gap in a guard that had
looked adequate:

| Survivor | Why it survived | What it bought |
|---|---|---|
| **L2** the `pyvenv.cfg` walk reverted | the test called `_is_inside_venv` **directly**, so it measured a helper nothing was obliged to call | the walk gained a `root` parameter and the guard now drives *the walk*, over a fixture |
| **L3** the drift query counting rows | **two causes**, and the second is a caution about this method — no test exercised the drift query against a **repeated** mark, *and* the harness had patched only the first of the two `COUNT(DISTINCT …)` occurrences, so half the mutant never landed | `test_a_repeated_mark_is_not_reported_as_drift`, and the harness now replaces **every** occurrence, because a textual mutation is textual |
| **L4** the migration backfill counting rows | the upgrade fixture had no duplicate mark to count twice | the fixture now marks one member **twice**, so `4` reported reconciles to `2` |
| **L5** the schema `CHECK` dropping `member_count IS NOT NULL` | the store layer refuses it first, so no code path reaches the constraint | `test_the_schema_refuses_a_reconciled_count_with_no_bag_size`, which goes **around** the store |
| **L6** the store bound loosened by one | the fixture used `10` against a bag of `4`, which `n + 1` still refuses | `test_the_store_layer_refuses_exactly_at_the_boundary` — `n` legal, `n + 1` not |
| **L13** `verify_evidence` no longer called | every drift test called the verification **by hand** | `test_the_maintenance_sweep_itself_runs_the_verification`, driven through `capture.prune` |

**L3 is worth dwelling on for the second reason rather than the first.** A partially-applied mutant
looks exactly like a surviving one, and had the ledger stopped at "SURVIVED" it would have recorded a
gap that was half imaginary — or, worse, missed the real gap beside it. The lesson is not about
`COUNT(DISTINCT)`: it is that **the injection harness is itself a guard, and it had no control.** It
does now, in the only form available: the diff is generated by `git diff` after the patch is applied,
so a mutation that did not land as intended is visible in the record rather than inferred from a
verdict. Every diff on this page was read.

Two of the survivors are the same mistake in different clothes, and it is worth naming because it is
the mistake this whole gate exists to catch: **a test that calls the thing directly proves the thing
works and proves nothing about whether anything calls it.** L2 and L13 both survived for exactly
that reason, in code written by the same hand, in the same week, while writing a document about
guards that silently stop guarding.

**L15** deserves its own paragraph. The blind count taken over *all reported marks* rather than over
the *reconciled* ones is an **equivalent mutant on every input except one**: the hidden set is a
subset of the bag by construction, so the two expressions agree unless a mark is repeated. Without a
duplicate in the fixture there is no observable difference, and the mutation would have been
correctly recorded as equivalent. It is not equivalent — it is wrong on `[h, h, h]` — and the
fixture that shows it is one line.

## 4. What this gate does **not** cover

In the voice of [`v0.9.1-test-audit.md`](v0.9.1-test-audit.md), which closed 19 of 31 and was a
better document for saying which 12 it missed.

1. **Defects of another shape.** Every mutant here is a small perturbation of correct code — the
   competent-programmer hypothesis that fault-based testing rests on. **F46 was not that shape.** It
   was not a mutation of a correct expression; it was the original expression, written once and
   never questioned, and no mutation operator would have generated it because there was nothing to
   mutate *from*. A suite that kills every mutant on this page would not have found F46, and saying
   so is more useful than the ratio above.
2. **Races.** Everything here is single-threaded and single-process. The write path takes
   `store.lock`, and two verdicts on one situation racing each other is not exercised by any
   injection on this page.
3. **Missing cases rather than wrong ones.** An injection can only fail a guard that exists. A
   quantity nobody thought to record — which is precisely what F47 was — cannot be injected against.
4. **Anything needing two simultaneous changes.** Each case here patches one construct. A defect
   that requires the reconciliation *and* its guard to move together is invisible to this method,
   and the guard files are as mutable as the source ones.
5. **The UI.** `src/netcorenoc/ui/app.js` is 52 KB and **no test executes it**. Everything this
   release says about "the shipped UI sends only ids it rendered" is a claim about code that is read
   and not run. It is the single largest untested surface in the repository and it is the one that
   decides whether F46's corpus exposure stays at zero.
6. **The migration against a database this repository has never seen.** `0011` is proved against a
   fixture written by v0.9.1's own store methods. A production database carrying rows from v0.8.0
   with columns this repository's corpora do not exercise is a different object, and `MIGRATION.md`
   says what an operator should check.
7. **Timing, beyond a loose median.** `test_the_oracle_stays_closed_in_timing` asserts *no usable
   signal*, not a benchmark. A statistically careful attacker with many samples is not modelled, and
   the release does not claim otherwise.
