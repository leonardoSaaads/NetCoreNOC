# v0.12.0 — the demonstrated guards

**A guard nobody has watched fail is not a guard.** Every guard this release adds is shown red under
an injected defect, then green on restore, with a **control that had to pass in both** — so a red
that came from breaking the suite generally is distinguishable from a red the guard actually caught.

The shape is `v0.11.0-guard-demonstrations.md`'s, inherited exactly: the guard named with its test
id, the defect as a diff against the corrected tree, the command, the verbatim RED, the verbatim
GREEN, and the control.

Command, for every entry:

```sh
python -m pytest -q --no-header -p no:cacheprovider <test id>
```

**Five of the eight injections are edits to `src/netcorenoc/ui/app.js`** — the file this release
promises not to change. Each was applied, measured, and reverted, and the file's SHA-256 was
verified after the last of them:

```
app.js restored: c9758ffb2a4fd5fdeac584fa6828260291063a2130844eed69c80c818d43858c
expected:        c9758ffb2a4fd5fdeac584fa6828260291063a2130844eed69c80c818d43858c
MATCH: True
```

## 1. A capability removed from a panel's requirement

The defect that would put an admin panel in a viewer's browser: lower what the Audit tab requires
until every authenticated role holds it.

```diff
--- a/src/netcorenoc/ui/app.js
+++ b/src/netcorenoc/ui/app.js
-  { id: "audit", label: "Audit", cap: "audit.read" },
+  { id: "audit", label: "Audit", cap: "situations.read" },
```

**RED** — three guards, and they fail for three different reasons:

```
FAILED tests/test_ui_invariants.py::test_a_role_never_renders_a_panel_whose_capability_it_lacks
1 failed in 1.50s
FAILED tests/test_ui_invariants.py::test_no_admin_capability_produces_a_panel_for_a_non_admin
1 failed in 1.34s
FAILED tests/test_ui_invariants.py::test_every_panel_a_role_reaches_requests_only_routes_that_role_may_call
1 failed in 1.31s
```

**CONTROL** (`test_a_partial_split_sends_exactly_the_marked_ids_and_no_others`) — `1 passed in 1.28s`
under the injection. The harness still boots, still renders, still drives a gesture; only the
capability boundary moved.

**GREEN** — `1 passed in 1.47s`, `1 passed in 1.35s`, `1 passed in 1.45s`.

### 1.1 The guard did not catch this as first written, and here is the measurement

`test_a_role_never_renders_a_panel_whose_capability_it_lacks` originally computed the admin-panel set
as an **observed difference**:

```python
admin_only = seen["admin"] - seen["viewer"]
```

That assertion is **unfalsifiable by the defect it exists to catch.** Lower a panel's required
capability so a viewer *does* see it, and the panel simply leaves the difference set — there is
nothing left to compare. Measured, not reasoned: the original form was restored under the injection
and run.

```
$ python -m pytest -q --no-header <the original set-difference form, under injection 1>
1 passed in 1.46s
```

This is Appendix B's *"a test that kills the obvious mutant and misses the real one"*, and — exactly
as in v0.10.0's cycle test — **the fixture was part of the guard**: the expected set was being
derived from the same run that was supposed to be checked against it.

The repair takes the expected set from an authority the injection does not touch. `_admin_ceiling_panels()`
clicks each of admin's tabs, resolves what each panel *requests* against `rbac.ROUTE_PERMISSIONS`,
and keeps the panels whose capability has minimum role `admin`. The harness reports each click's
`data-panel` id for this — keyed on the panel, never on the tab's label, because a label is copy.

Two things worth saying plainly. **The other two guards caught it either way**, so the invariant was
never unguarded — but "another test would have caught it" is not a reason to leave a guard that
cannot fail for its own subject. And **this was found only because the injection was mandatory**;
nothing in the test's own construction suggested it. That is the same lesson `SECURITY-REVIEW-0.11.0.md`
§3.4 recorded about F48, one release earlier, and it is the second measured instance of it.

## 2. The escaping helper bypassed on one render path

The device name is operator-supplied text (`/api/labels`) and reaches the DOM through
`el({text})` — `textContent`, never markup. This routes it through `innerHTML` instead.

```diff
--- a/src/netcorenoc/ui/app.js
+++ b/src/netcorenoc/ui/app.js
-    const devName = el("span", { class: "name", text: deviceName(a) });
+    const devName = el("span", { class: "name" }); devName.innerHTML = deviceName(a);
```

**RED**

```
FAILED tests/test_ui_invariants.py::test_no_render_path_turns_operator_supplied_text_into_markup
1 failed in 1.36s
FAILED tests/test_security_ui.py::test_ui_source_has_no_f1_antipatterns - ass...
1 failed in 0.48s
```

**Both halves of ADR #168's pairing fire, and they fire for different reasons** — the behavioural one
because `<img>` and `<script>` elements now exist in the rendered document, the text-level one
because the string `.innerHTML` now exists in the file. On a machine without Node only the second
would fire, which is the argument for keeping it.

**CONTROL** (`test_a_partial_split_sends_exactly_the_marked_ids_and_no_others`) — `1 passed in 1.34s`.

**GREEN** — `1 passed in 1.31s`, `1 passed in 0.44s`.

**What makes this demonstration meaningful rather than circular.** The harness DOM implements
`innerHTML` as a **real parse** (`tests/domharness/html.mjs`). Without that, the injected assignment
would have been a no-op in the harness and the guard would have stayed green — the escaping invariant
would have been passing for a property of the instrument. The parser exists for `index.html` anyway;
wiring it to `innerHTML` is what makes the violation *expressible*, and this red is the proof that it
is.

## 3. The partial-split gesture sending one id the operator did not mark

One extra id — the first member of the situation, whether or not the operator ticked it.

```diff
--- a/src/netcorenoc/ui/app.js
+++ b/src/netcorenoc/ui/app.js
-      onclick: () => feedback(sid, "split", shown, [...marked]) }));
+      onclick: () => feedback(sid, "split", shown, [...marked, d.alarms[0].id]) }));
```

**RED** — `FAILED …::test_a_partial_split_sends_exactly_the_marked_ids_and_no_others` — `1 failed in 1.34s`

**CONTROL** (`test_a_role_never_renders_a_panel_whose_capability_it_lacks`) — `1 passed in 1.48s`: the
capability boundary is untouched, so the red is the payload and not the render.

**GREEN** — `1 passed in 1.31s`.

**Why this one matters out of proportion to its size.** `excluded_ids` asserts *marked-by-rest
negative and nothing else*. One extra id is one human judgement recorded about a pair no human
judged — and the bias report, the agreement report, the shadow verdict and the promotion gate are all
computed over those rows. v0.9.2 moved the *evidence* boundary server-side; the **marks** are still
the client's to report faithfully, and until this release nothing checked that they were.

## 4. An SSE update destroying an in-flight gesture — the v0.7.5 defect, re-created

v0.7.4's `renderSituations` opened with `clear(sits)`, so every card — expanded ones included — was
destroyed on every update. Restored verbatim:

```diff
--- a/src/netcorenoc/ui/app.js
+++ b/src/netcorenoc/ui/app.js
+  clear(sits);
   const held = new Map();
```

**RED**

```
FAILED tests/test_ui_invariants.py::test_an_sse_update_mid_gesture_does_not_destroy_the_click_target
1 failed in 1.36s
FAILED tests/test_security_ui.py::test_render_situations_does_not_clear_the_list_unconditionally_first
1 failed in 0.48s
```

**CONTROL** (`test_a_partial_split_sends_exactly_the_marked_ids_and_no_others`) — `1 passed in 1.33s`.
This control is the important one here: **the split gesture still works perfectly** when no update
arrives mid-gesture. That is precisely why the defect survived into production in v0.7.4 — every
test of the feedback path passed, because none of them delivered an update while a card was open.

**GREEN** — `1 passed in 1.31s`, `1 passed in 0.44s`.

**This is the assertion `FEEDBACK-PATH-0.7.5-DRAFT.md` §5 asked for and could not have.** DECISIONS
#99 recorded that there was no DOM to drive, and the claim was carried by a human executing
`v0.7.5-manual-verification.md`. The red above is Tests A and D of that protocol, mechanical.

## 5. A client-side request issued without the capability

Not "a panel is mis-gated" (§1) but the deeper regression the invariant names: the client stops
deciding and lets the server refuse.

```diff
--- a/src/netcorenoc/ui/app.js
+++ b/src/netcorenoc/ui/app.js
-const can = (cap) => !!(session && session.capabilities.has(cap));
+const can = (cap) => !!session;  // let the server refuse it
```

**RED**

```
FAILED tests/test_ui_invariants.py::test_a_capability_the_client_lacks_produces_no_request_at_all
1 failed in 1.31s
FAILED tests/test_ui_invariants.py::test_a_role_never_renders_a_panel_whose_capability_it_lacks
1 failed in 1.55s
```

**CONTROL** (`test_a_partial_split_sends_exactly_the_marked_ids_and_no_others`) — `1 passed in 1.39s`.

**GREEN** — `1 passed in 1.36s`, `1 passed in 1.46s`.

**Separate from §1, and required to be.** There the *map* was wrong and one panel leaked; here the
map is intact and the **gate** is gone, so a viewer requests every admin route and receives eight
403s. A server-side test would see nothing wrong: the server refuses correctly in both cases. The
whole content of this invariant is that the request is **never made**.

## 7. The principle-6 guard's extractor broken

The failure mode a build-step guard actually has: not a missing rule, a **broken extractor**.

```diff
--- a/tests/test_build_step.py
+++ b/tests/test_build_step.py
-    return sorted(entry for entry in paths if _is_build_step(entry))
+    return []  # a broken extractor reports every tree clean
```

**RED** — `FAILED …::test_the_guard_finds_a_package_json_that_is_actually_there` — `1 failed in 0.18s`

**CONTROL** — and this control **is the finding**:

```
CONTROL under injection [test_the_tracked_tree_contains_no_build_step_apparatus]
1 passed in 0.14s
```

**The principle-6 guard itself stays green with its extractor returning nothing.** It would report a
tree containing a bundler, three lockfiles and `node_modules/` as clean, and nothing about its output
would look wrong. The vacuity check is the *only* thing that notices, and that is why it exists and
why it is driven through a **real git repository** rather than by calling a helper — v0.9.2's ledger
entry L2 records a guard test that called its helper directly and stayed green when the caller was
reverted.

**GREEN** — `1 passed in 0.21s`.

## 8. The harness made to skip silently

**The most likely way this release fails**, injected on purpose.

```diff
--- a/tests/test_dom_harness.py
+++ b/tests/test_dom_harness.py
-requires_node = pytest.mark.skipif(not AVAILABLE.ok, reason=AVAILABLE.skip_message)
+requires_node = pytest.mark.skipif(True, reason="")
```

**RED** — `FAILED …::test_node_absent_is_a_skip_and_never_a_silent_pass` — `1 failed in 0.18s`

**CONTROL** (`test_availability_accepts_the_floor_itself`) — `1 passed in 0.15s`: `availability()`
still resolves a good interpreter correctly, so the red is the *mark* and not the detection logic.

**GREEN** — `1 passed in 0.17s`.

**And what the suite looked like while it was injected**, which is the whole point:

```
$ make dom
ssssssssssssssssss                                                       [100%]
18 skipped, 1321 deselected in 0.99s
```

Eighteen skips, no reason attached, and every other test in the repository green. A reader of
`1339 passed` would have seen nothing at all. **This is why the gate documents quote executed DOM
tests and never a collected count**, and why the anti-vacuity rule (`run_scenario` refusing a result
with no proof of execution) is a second, independent mechanism rather than a restatement of this one.

## 9. The mutation ledger — survivors, **by name**

Injections that were tried and **not** caught, listed individually rather than as a ratio.

### S1 — the observed-difference form of invariant 1 (§1.1)

**Survived, and was repaired.** `admin_only = seen["admin"] - seen["viewer"]` passed under injection
1 (`1 passed in 1.46s`, measured). Repaired to derive the expected set from `rbac.PERMISSIONS`. Listed
here rather than silently fixed because it is the release's own instance of the failure it is about.

### S2 — d3's render paths are not covered by anything

`updateGraph` and `loadTimeline` execute against a recording double, so **no injection into either
can be caught by these guards**. This was not measured as a survivor because it is a declared
exclusion (ADR #167, `SCOPE-0.12.0.md` §5) rather than a gap discovered — but the practical effect is
identical: a defect introduced into the graph or the timeline today is caught by nothing. Recorded in
`../ROADMAP.md`.

### S3 — the harness's own DOM is guarded only where an invariant depends on it

`selftest.mjs` covers seventeen semantics, chosen because a captured invariant rests on each. Any
other divergence between this DOM and a browser's is **unguarded and unmeasured**. Two known
examples: no event capture phase, and `isConnected` is computed by walking parents rather than by a
document registry. Neither is reached by anything `app.js` does today.

### S4 — nothing verifies that the captured fixtures still match the server

`uifixtures` captures from the live app each run, so drift is impossible *by construction* — but
there is no assertion that the captured shapes contain the fields `app.js` reads. If a route dropped
`alarm_count`, the harness would render a card saying `undefined alarms` and every invariant would
still pass. A shape assertion would close it; none was written.

### S5 — the `panelWithoutCapability` bypass is one call, not a routing model

§6.1 of Gate 3 drives `renderPanel(id)` directly. A real router would also set state, change history
and re-enter `selectPanel`. The finding stands; the coverage of the *class* does not.

## 10. What this ledger does not establish

The ledger is **manual and its author chose the mutations**, and §1.1 is direct evidence that this
bias is real: the injection that found the weakest guard in this release was one the build prompt
*mandated*, not one that was chosen. That is now the second measured instance in two releases
(`SECURITY-REVIEW-0.11.0.md` §3.4 was the first, over F48).

**There is no reason to believe the survivor list above is complete**, and it is not claimed to be.

One narrower limitation. Five of the eight injections edit `ui/app.js` and are reverted immediately;
the evidence that they were reverted is a SHA-256 match at the end of the run plus a clean
`git status`. That is strong for the file as a whole, but the demonstrations were run **as a batch**,
so a defect that survived one injection and was masked by the next would not be separately visible.
Each guard's GREEN was re-measured after its own restore, which bounds it — but it is a batch, and
saying so is more useful than implying eight independent runs.
