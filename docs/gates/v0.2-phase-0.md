## The one-process dataflow

```
devices ─UDP 162─▶ receiver.py ─asyncio.Queue─▶ Engine.run (main.py) ─▶ Store (SQLite WAL)
                   allowlist                     dedup / flapping          ▲ one connection
                   defensive parse               learn A,E / precedence    │ + asyncio.Lock
                   └▶ QuarantinedPacket ─────────correlate → situations    │
operator ◀─HTTP 8080─ api.py + ui/index.html ◀───────────────────────────┘
```

One asyncio event loop runs three tasks (`main.run`): `Engine.run` (queue drain),
`Engine.maintenance_loop` (every 5 s), and the uvicorn `QuietServer`. One SQLite
connection is shared by all of them.

## Mechanism 1 — queue → engine → store flow

- **Receiver** (`receiver.datagram_received`): allowlist check → `parse_trap` →
  `queue.put_nowait`. It never awaits and never blocks; a full queue increments
  `stats.dropped` and returns. A parse failure becomes a `QuarantinedPacket`
  (raw bytes truncated to 4096) rather than an exception. `QueueItem = TrapEvent |
  QuarantinedPacket`.
- **Engine.run**: blocks on `queue.get()` for the first item, then greedily drains up to
  `BATCH_SIZE=500` more with `get_nowait`. The whole batch is processed **inside one
  `async with self.store.lock:` block, ending in a single `store.commit()`** — one
  SQLite transaction per batch. Latencies (`now - item.ts`) are sampled after commit.
- **Engine._process** per item: quarantine packets are written and returned early;
  otherwise it resolves `class_id`/`device_id` (cached dicts + upsert), seeds standard
  clear pairs on first sight (`_seed_clear_pair`), feeds alternation learning (paused in
  storms), then either routes a learned clear class to `_handle_clear`, or `store.ingest`
  (fingerprint dedup) → flapping check → `correlator.process` → `learner.observe_*` +
  `precedence.observe` → `_assign_situation` (connected components with merge-on-bridge,
  root recompute).

## Mechanism 2 — the store lock discipline (Decision 12)

There is exactly **one** `aiosqlite` connection. sqlite refuses to `commit()` while any
statement is mid-iteration, so an API read cursor interleaving with the engine's batch
commit once raised *"cannot commit transaction - SQL statements in progress"* and killed
the engine (found at 1000 traps/s). The fix: a single `asyncio.Lock` on `Store`.

- The **engine** holds it per batch (`Engine.run`) and per maintenance pass
  (`Engine.maintenance`).
- **Every API handler** holds it around its own read/write (`async with store.lock:`).
- `apply_feedback` runs under the lock the caller already holds and commits inside it.

Regression-guarded by `test_concurrent_api_reads_during_ingest` (2500 events streamed
while `/api/stats` and `/api/situations` are polled; the engine must not die).

**v0.2.0 consequence (prime directive 2):** auth and audit live on the HTTP side only.
Session/token resolution, RBAC checks, CSRF, and audit-row writes must never be added to
`receiver`/`Engine._process`. Audit writes happen inside API handlers under the same
store lock the handler already takes — no new lock, no new commit path on the trap path.

## Mechanism 3 — the learning triggers (Decisions 7, 9, 11, 13)

Two triggers, both required to converge (Decision 7):

1. **Per-activation window co-occurrence.** On each newly activated alarm the engine
   observes one occurrence and, for the ≤20 most recent distinct window members, one pair
   observation each (`learner.observe_pairs`) — *once per distinct other class/device*, so
   pair mass can never outgrow the activation total (Decision 9). Precedence lead/lag mass
   is recorded the same way.
2. **Closed-situation epochs.** When a situation fully clears or goes idle,
   `_close_situation` → `learner.learn_epoch(members)` ticks the forgetting epoch
   (`(1-λ)^Δepochs`, λ=0.05) and reinforces each distinct member pair once.

Affinity is evidence-discounted NPMI (`Matrix.npmi`, shrunk by `n/(n+1)`, Decision 8);
device edges need `n ≥ 5` before they count (`MIN_EDGE_N`). Storms (`window ≥ 50`) damp
updates 10× **and pause raise/clear alternation learning** (Decision 13) so random
interleavings don't mint false clear pairs. `confirm` feedback replays `learn_epoch`;
`split` halves the grouped pair masses (`penalize`). A lone clear with no active raise
is alternation evidence only, never an alarm row (Decision 11).

## Persistence model I must extend, not disturb

`store.py` is thin hand-written SQL behind one class; migrations are plain `.sql` applied
by `PRAGMA user_version` (`_migrate` runs every `*.sql` whose numeric prefix exceeds the
stored version, then bumps it). Schema v1 (`0001_init.sql`): `meta, device, alarm_class,
alarm, edge, situation, situation_alarm, link, feedback, label, quarantine`. Learned
state persists as `edge` rows (kinds: class/device/lead_class/lead_device/clear_pair)
plus JSON marginals in `meta`. v0.2.0 adds `0002_auth_auth.sql` (`user, session,
api_token, audit_log` + append-only triggers) — forward-only, must apply to a **populated**
v0.1.0 DB.

## The six findings, located in the read

- **F1 stored XSS** — `ui/index.html` builds `innerHTML` from server strings without
  escaping: `renderStats` (chip labels are constant, but pattern is unsafe),
  `renderDetail`/`termBar`/`alarmName`/`deviceName` interpolate `class_name`, `class_oid`,
  `device_ip`, `instance`, labels, and link ids straight into template literals;
  `renderSituations` builds card HTML. `instance` and varbind-derived strings are
  attacker-controlled via UDP 162, and with the allow-all default (Decision 4) this is an
  **unauthenticated** injection into the operator's browser. Fix precedes all auth (S1).
- **F2 shared static token** — `api.guard` compares one process-wide token; `index.html`
  keeps it in `localStorage` (line 135), exfiltratable by F1.
- **F3 secret in logs** — `main.run` logs the generated token
  (`log.info("generated API token … %s", token)`).
- **F4 community string persisted** — `receiver` never extracts the community, but
  `quarantine.raw` stores the whole datagram, whose SNMPv2c header carries the community
  (a password) in cleartext. The engine also has no community grouping tag yet.
- **F5 no TLS** — uvicorn is plain HTTP; cookies/tokens would travel cleartext.
- **F6 `0.0.0.0` default** — `Settings.http_host`/`trap_host` default to `0.0.0.0` with a
  `# nosec B104` note but no operator-facing warning.
