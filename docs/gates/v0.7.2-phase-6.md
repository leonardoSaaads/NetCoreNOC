## 1. The security review

`docs/security/SECURITY-REVIEW-0.7.2.md`. **Zero findings.** The series stays at F39; F40 is unused.

A move-only release should produce none, and a review that manufactures one to look diligent is
worse than one that says "none". So the review says none, and spends its length on the two things
that matter instead: proving the claim, and saying what the release does not buy.

What it assesses, and what it found:

| Required assessment | Result |
|---|---|
| No new surface | ✅ routes 48→48, capabilities 25→25, `ROUTE_PERMISSIONS` 39→39, `PUBLIC_ROUTES` 1→1, audited-denied 15→15, audit actions unchanged, migrations 7→7, dependencies 5→5, served paths 7→7 |
| No decision moved or duplicated | ✅ 43/43 handler bodies byte-identical; the perimeter's own code moved under one token-level rule; the four single-decision-site tests survive with their assertions intact; `AppContext` is frozen, so a route module *cannot* substitute its own |
| The import-time invariants survived | ✅ **demonstrated live** — injecting a drift into `rbac.AUDITED_DENIED_PERMISSIONS` and reloading `api/perimeter.py` raises the F8 assert. `rbac.py` gained two more of the same kind |
| The middleware still runs on every response | ✅ verified against the **installed wheel run as a real process**: CSP and `X-Frame-Options: DENY` on all seven public paths, `Cache-Control: no-store` on `/api` |
| Packaging integrity | ✅ wheel and sdist both carry 16/16 `api/` modules, the full UI, 7 migrations, the d3 `CHECKSUMS.txt` |

And the critical analysis it was required to make, in its own words:

* **This release does not make the perimeter more correct.** The same code in different files has
  the same behaviour. Every caveat in `SECURITY-REVIEW-0.7.1.md` §4 stands unchanged — scoping is
  still not tenant isolation, the rate limiter is still in-memory, `SafeScorer` still cannot preempt,
  the audit chain is still append-only by convention, `label` still has no foreign key.
* **What it buys** is a perimeter a reviewer can read in one sitting, and a discipline under which
  F34's class fails at startup instead of surviving to production.
* **`Perimeter` is now constructible outside `create_app`** — convenient for tests, and a second way
  to instantiate the authorization machinery. Harmless (it holds no state a caller could not reach
  through `store`), and named in §5.3 rather than left to be discovered.
* **The gate fires at application construction, not at module import** — the practical guarantee is
  the same, but "import time" would overstate the mechanism, and a security document that overstates
  its own mechanism is the wrong kind of document. Two checks *are* strictly import-time, in
  `rbac.py`.
* **`ROUTE_SCOPE` is declared and tested, not enforced** — that moves the guarantee from *nothing*
  to *declared and tested*, not to *structural*.
* **`rbac.py` got worse and this release did it** — 348 → 436 lines, allowlisted with v0.7.4 as
  owner and a named split seam.

### `threat-model.md`

**Not changed in substance, and that is the correct answer.** No trust boundary, asset, adversary or
control moved. Four sentences named `api.py` as the file holding a control; those file references
were corrected (a file reference is not a posture) and a dated note at the top says exactly that
much and nothing more.
