# v0.10.0 — guard demonstrations

**A guard nobody has watched fail is not a guard.** Every guard this release ships is demonstrated
red under an injected defect before its green counts as evidence. The shape is inherited exactly
from [`v0.9.2-guard-demonstrations.md`](v0.9.2-guard-demonstrations.md): the guard named with its
test id, the exact defect as a diff, the command, the verbatim RED, the verbatim GREEN, and **the
control that had to pass in both runs**.

**A guard with no recorded red does not close this gate. A guard whose control was absent does not
close it either.**

### The reds worth reading rather than counting

**P2-B** — the cycle guard removed:

```
E  AssertionError: the cycle was not flagged
E  assert False
E   +  where False = Resolution(incident=302, cycle=False, unterminated=True).cycle
```

A **cycle reported as a depth-bound failure** — exactly the confusion two separate guards exist to
prevent. An operator reading *"this chain is implausibly long"* about `301 → 302 → 303 → 301` would
hunt the wrong defect.

**M1** — the rate pooled over pairs. The test does not assert the property, it **measures the
difference**: a 60-member storm respecting nothing and a 4-member bag respecting everything average
to **0.5** over bags, where the pooled rate is **0.004** — the storm wearing the corpus's name.

**M5** — a single trigger dropped. Three tests red, including
`test_every_registered_trigger_is_reachable`, which exists so that a registered condition nothing
can reach is indistinguishable from one somebody forgot to wire.

## Part 2 — the survivors, named

> **Report the survivor list, not the ratio.** v0.9.2's first run was 9 of 15 and two survivors were
> the same mistake in the build's own tests — which was the finding, not the number.

**Three of seventeen mandatory injections survived.** Two were weak guards and one was a bad
injection. All three are recorded here with what was done about each.

### M3 — the champion measured by a second code path. **SURVIVED, and it exposed a real defect.**

The injection added an early return scoring a bag `1.0` whenever the model produced no partition for
it. `test_the_champion_and_the_challenger_go_through_one_code_path` passed, because it only ever
passes **non-empty** component maps.

**The mutant was not merely unkilled — it was a defect already in the shipped code.** With an empty
mapping, `component.get(a, a) != component.get(b, b)` is `True` for every pair, so a bag the model
produced nothing for scored **1.0: every asserted negative pair respected**. That is a perfect number
produced by nothing happening — v0.9.0's measured policy-B failure and §2.6(c)'s trivially-satisfied
case, arriving through a door neither of them guards.

**Disposition: fixed.** A bag with no partition is now **excluded and counted**, exactly as a
`coverage IN ('none','empty')` bag is, and `test_a_bag_with_no_partition_scores_nothing_rather_than_one`
carries a control proving the same bag *with* a partition is still scored. The fix took
`shadow_eval.py` to **410 of its 400-line budget**, so the fourth metric moved to
`shadow_assertions.py` — **split, not exempted**, on the seam that `shadow_eval.py` scores a
*partition* against a human verdict while this scores a *human assertion* against a partition.
Re-injected:

```
FAILED tests/test_judge.py::test_a_bag_with_no_partition_scores_nothing_rather_than_one
1 failed, 34 passed in 0.85s
```

**This is the single most valuable result in this document.** The mutation ledger found a defect the
whole rest of the suite was blind to, in the metric this release exists to add.

### M6 — a floor printed without its detection threshold. **SURVIVED. Weak guard.**

The first guard read `shadow_render.py` for the substring `"detectable"` or `"detection"`. Both
printed lines were deleted and it stayed green — **because the explanatory paragraph underneath
still contained the words.** A guard satisfiable by *prose about the number* rather than by the
number.

**Disposition: guard rewritten** to read the **rendered output** and require both claims to appear
on lines carrying a digit. Re-injected:

```
FAILED tests/test_judge.py::test_the_renderer_prints_the_threshold_wherever_it_prints_the_floors
1 failed in 0.25s
```

This is Appendix B's grep lesson in a new place: the first guard asked whether the source *mentioned*
the thing, and the property is whether the report *prints* it.

### M7 — the CV fold assignment made incident-blind. **SURVIVED. Bad injection.**

The injection replaced the rotation with `{incident: rng.below(folds)}` — which is still
**per-incident**, so no incident spanned two folds and the guard was right to stay green.

**Disposition: recorded as a known limitation, not fixed**, because the property is guaranteed by a
signature rather than by a body. `assign_folds` takes `Sequence[int]` of **incidents**; there is no
argument through which rows could be passed, so *a row-wise split is inexpressible without changing
the signature* — and an injection that changes the signature also breaks the call site, which is a
compile-time failure rather than a guard.

**What that means honestly: `test_no_incident_spans_two_folds` cannot fail while the signature
stands, and it is therefore a documentation of the design rather than a detector of a regression.**
It is kept — with its own control asserting the assignment actually *spreads* incidents, so
"everything in fold 0" would be caught — and named here rather than presented as a guard that has
been watched to fail.

**A11 is the second finding in this document that was a real bug rather than a mutant.** The first
version of `_Lcg.below` returned `state % bound`. A power-of-two-modulus LCG has notoriously poor
**low** bits: `state % 2` alternates with period 2, so every resample of a two-cluster corpus drew
exactly one of each and the interval came back **zero-width** — a bootstrap reporting perfect
precision because it never resampled anything.

`test_the_bootstrap_resamples_incidents_and_not_observations` caught it, by asserting a two-cluster
corpus has a **wider** interval than a 200-cluster one. Both were `0.000`. Fixed to
`(state >> 16) % bound`, after which the **shipped** bootstrap reproduces the plan's §3.1 table:

```
  n=  12  plan 0.500   observed 0.500
  n=  37  plan 0.289   observed 0.297
  n=  50  plan 0.246   observed 0.260
  n= 100  plan 0.180   observed 0.180
  n= 500  plan 0.079   observed 0.080
```

**Two further defects were found by the dead-code gate rather than by a mutant**, and neither was
resolved by an allowlist entry:

* `Power.sufficient` unused meant `judge()` had **inlined** the power condition — a second
  implementation of a quantity §2.5 makes both a reported number *and* a verdict trigger, which is
  how the printed number and the deciding number come to disagree silently (DECISIONS #152);
* `Judgement.decisive` unused meant the report never said that `INSUFFICIENT_EVIDENCE` is a
  measurement rather than a finding against the challenger.

## Part 4 — what this instrument does not cover

In the voice of [`v0.9.1-test-audit.md`](v0.9.1-test-audit.md), which closed 19 of 31 and was a
better document for saying which 12 it missed.

**Defects of another shape.** Every mutant here is a *single, local, syntactic* change — a comparison
flipped, a predicate deleted, a constant moved. Nothing here would catch a defect that is correct in
every line and wrong in its composition: a fold assignment that is sound and a bootstrap that is
sound and an incident identity that is sound, wired together in an order that leaks.

**Anything needing two simultaneous changes.** The mutation technique is single-point by
construction. The seal's protections in particular are a *conjunction* — construct-once **and**
unreadable **and** logged **and** plan-gated — and a coordinated change to two of them could satisfy
each guard individually.

**Races.** Nothing here runs two coroutines against one store. `_seal_once` reads `seal_row()` and
then constructs, under `store.lock`; the schema's `UNIQUE` makes the race harmless, but *that
reasoning is argued rather than tested*.

**Missing cases rather than wrong ones.** Every guard checks that a stated property holds. None
would notice a §6.2 trigger that the plan registers and this build never implemented — except
`test_every_registered_trigger_is_reachable`, which checks the `Trigger` enum against itself and
would therefore be equally silent about a condition missing from **both**.

**The fold-integrity property**, per Part 2's M7: guaranteed by a signature, not watched to fail.

**The corpus, for four of this release's mechanisms.** The judge, the fourth metric, the
blind-fraction rule and the transitive incident resolution are each demonstrated **only** on
purpose-built fixtures, because Gate 1 measured that the fullest corpus this repository can
construct supplies zero asserted negative pairs, has every merge chain one hop deep, and has an
empty `checked` scope population. Fixtures prove semantics; they do not prove the code meets real
data, and no test in this repository does.

**The UI.** `app.js` is 52 KB that no test executes, and it is the surface an operator would use to
read every number this release produces. Unchanged from v0.9.1's finding and unchanged by this
release.
