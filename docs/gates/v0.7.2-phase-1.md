## 2. Decisions recorded (#75–#84)

| # | Decision | The alternative it rejects, and why |
|---|---|---|
| 75 | The layer model and the placement rule, decided once for the whole project | Deciding only the HTTP layer now → v0.7.3 re-argues the same question with less context and a bigger diff |
| 76 | The perimeter boundary is *"may this request proceed?"*, not *"which region of the file?"* | Moving by proximity would have split the write-side scope check from the read-side one — **precisely the mistake F34 was** |
| 77 | `Perimeter` is a class | Free functions grow a parameter each → every call site changes → forty handlers edited → the parity proof is gone |
| 78 | `AppContext` + a **mandatory** local-rebinding block in every `register()` | `ctx.audit_row(...)` at call sites is tidier code and the wrong trade: it edits all forty handlers, so the hash table proves nothing |
| 79 | The package is `api/`, one level deep — **explicitly superseding** SCOPE-0.5's "prefer flat" and ADR #74's flat `perimeter.py`, for this subtree only | `http/` shadows a stdlib name in a reader's mind and contradicts every existing import; keeping flat leaves a 1 370-line `api.py`, which is the problem restated |
| 80 | `ROUTE_SCOPE` is descriptive now, enforcing later | Injecting the check changes control flow, and control flow is behaviour — one such change makes every other gate in this release unfalsifiable |
| 81 | The module-size guard ships with a **shrink-only** debt allowlist, installed in Phase 2 against the *unmodified* tree | Documenting the limit is what the project already had; enforcing it with no allowlist means splitting five modules in one autonomous run |
| 82 | Path normalisation deferred, with the three inconsistencies **named** | Renaming in the same release that moves forty handlers means a broken matrix cannot be attributed to a cause |
| 83 | `store.py`/`main.py` specified here, built in v0.7.3; the `Store` mechanism deliberately **left open** | Guessing the mechanism now is the same re-litigation this document prevents, in reverse |
| 84 | The four source-reading tests get a new **source**, not new assertions | Deleting or weakening them trades away three of v0.7.1's regression guards to make a refactor look cleaner |

### The supersession, stated rather than implied

SCOPE-0.5's hard constraints read: *"prefer the flat module set inside `src/netcorenoc/`; a shallow
grouping is optional and must earn itself"*. ADR #74 went further and proposed a single flat
`src/netcorenoc/perimeter.py`. **Both are superseded, for the `api/` subtree and no other**, by ADR
#79. The rest of `src/netcorenoc/` stays flat, and `MODULE-ARCHITECTURE.md` forbids a second level
of nesting anywhere. Superseding a standing preference quietly is how a project's rules stop
meaning anything, so it is written into the ADR series rather than left to be inferred from the
tree.

### Layer violations found while writing it

Two, both **named and left alone** (build-prompt directive 3 — a fix hidden inside a structural
release is invisible to review):

1. `main.py` → `netcorenoc.api` — engine importing http, the one genuine upward import. `main.py`
   is the `Engine` **and** the process entry point sharing a module; the entry point may
   legitimately reach up, the `Engine` may not. Resolved naturally by the v0.7.3 split.
2. `runtime.py` → `receiver.Network` / `parse_allowlist` — cross-cutting importing ingest. Small,
   real, and a cycle risk if `receiver` ever needs runtime config.

One tolerated exception, recorded so it is a decision and not an oversight: `audit.py` and `auth.py`
import `store.Store` under `if TYPE_CHECKING`. Type-only, no runtime edge, and the alternative is a
`Protocol` restating `Store`'s surface in a second place.
