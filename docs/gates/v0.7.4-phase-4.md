## 2. `rbac.py` still single-sources authorization — and the proof that mattered

This was the release's highest structural risk: **a split of the authorization tables that quietly
creates a second source would be worse than the debt it removes.**

### The shape of the defect

```python
PERMISSIONS = dict(tables.PERMISSIONS)      # WRONG — and invisible
```

Equality holds at import, so every existing test stays green. The two objects diverge the first time
either is mutated or shadowed — and `tests/test_declaration.py` **already mutates**
`rbac.ROUTE_PERMISSIONS` in a fixture, so this is not hypothetical.

### Two new tests, and both were shown to fail before being accepted

| Test | Catches |
|---|---|
| `test_the_tables_are_re_exported_by_identity_not_by_copy` | `rbac.X is rbac.tables.X` for all **eight** tables |
| `test_no_module_but_tables_binds_an_authorization_table` | a module-level rebinding anywhere under `rbac/` except `tables.py` — parsed from the AST, so a genuine function-local is not flagged |

**Sabotage 1 — a deliberately-copying `__init__.py`:**

```
FAILED test_the_tables_are_re_exported_by_identity_not_by_copy[ROLE_RANK]
FAILED ... [PERMISSIONS] [ROUTE_PERMISSIONS] [PUBLIC_ROUTES] [ROUTE_SCOPE]
FAILED ... [AUDITED_DENIED_PERMISSIONS] [RECOVERY_CAPABILITIES] [_CEILINGS]
FAILED test_no_module_but_tables_binds_an_authorization_table
9 failed, 8 deselected
```

**And, with that same sabotage still in place, every pre-existing test:**

```
$ pytest -q tests/test_rbac.py tests/test_declaration.py tests/test_governance.py \
         tests/test_scorer_api.py tests/test_security_ui.py tests/test_upgrade.py \
         -k "not identity and not binds_an_authorization"
218 passed, 9 deselected in 79.76s
```

**218 pre-existing tests pass green against a broken authorization surface.** That is the whole
argument for directive 3, measured rather than asserted: equality is not the property that matters,
and nothing the project already had could tell the difference.

#### One finding from writing the sabotage, worth recording

The first sabotage used `frozenset(PUBLIC_ROUTES)` — and **three of the eight tests passed**, because
CPython returns the *same object* when `frozenset()` is called on a frozenset. The copy was not a
copy. The sabotage was corrected to `frozenset(set(...))` before the proof was accepted. A guard
proved against a sabotage that is not actually the defect proves nothing, and this one nearly was.

**Sabotage 2 — a local fallback in `policy.py`** (the same defect wearing a different shape):

```
$ pytest -q tests/test_rbac.py -k "identity or binds_an_authorization"
FAILED test_no_module_but_tables_binds_an_authorization_table
1 failed, 8 passed
```

The eight identity tests **pass** here — `__init__.py` re-exports correctly — while `policy.py`
shadows `PERMISSIONS` and the resolver reads the wrong table. Neither test subsumes the other, which
is why directive 3 asks for both.

### The prose travelled with the tables

DECISIONS #87 records that `ROUTE_SCOPE` pushed `rbac.py` past the guard and that **neither the
table nor its justifications could be traded away** to get under it. Splitting is the fix that keeps
both, so every `"unscoped"` justification comment moved with its entry, and
`test_every_unscoped_declaration_carries_a_written_justification` still finds all five.

`tables.py` is **277** lines — 241 of table and prose, 36 of docstring and imports. A split that had
arrived under the guard by shortening comments would have solved the wrong problem.

### The three module-level asserts moved with what they assert

`rbac.py` carried three import-time assertions the build prompt's line ranges do not mention:
`ROUTE_SCOPE` and `ROUTE_PERMISSIONS` declare the same routes; `admin_only` is derived from
`PERMISSIONS` in both directions; `RECOVERY_CAPABILITIES ⊆ ceiling("admin")`. All three are in
`tables.py`, immediately after what they constrain. Left in `policy.py` they would have run *after*
the tables were built rather than as part of building them — three structural guarantees deleted
while every test stayed green (DECISIONS #96).

## 3. `varbind_accum.py` — one extraction, not a package

`Accumulator` (49), `Candidate` (20), `_CoOccur` (31), `value_hash`, `_as_int` and the nine constants
they own → `varbind_accum.py` (**154**). `VarbindProfiler` and its module frame stay in
`varbind_profile.py` (**305**).

**Constant ownership was computed from the AST, not assumed** (Phase 0 §4.3). Four symbols —
`ENTITY_MIN_DISTINCT`, `ENTITY_MAX_CARD_RATIO`, `FD_MIN_PAIRS`, `value_hash` — are used by both the
moved classes and `VarbindProfiler`. They move with the classes whose semantics they define and are
imported back, because the alternative is a circular import: the decision protocol's "leave it where
it is" cannot apply when the import graph forbids it (DECISIONS #97).

`varbind_profile.py` re-exports every moved name in the PEP 484 `as` form, so the five symbols Phase
0 found reachable from outside — `Accumulator`, `ENTITY_PROMOTE_OBS`, `ENTITY_PROMOTE_SCORE`,
`MAX_DISPLAY_CHARS`, `MAX_TRACKED_VALUES` — resolve unchanged. `severity.py` and
`tests/test_promotion.py` were not edited.

**Layer:** `engine`, not cross-cutting. The build prompt says the new modules are "all of them
cross-cutting"; that is true of `rbac/*` and `shaping/*` — and those need **no `LAYER_OF` entry at
all**, because `tests/test_layers.py` keys a packaged module by its package name. `varbind_accum` is
a new top-level module and follows its parent, which `MODULE-ARCHITECTURE.md` §1 places at `engine`.

## 5. `DEBT_ALLOWLIST` reaches zero — and is still defended

```python
DEBT_ALLOWLIST: dict[str, tuple[int, str]] = {}
ALLOWLIST_MEMBERSHIP_CEILING: frozenset[str] = frozenset()
```

Both direction tests are **kept**, per build-prompt §5.5:

* `test_allowlist_only_shrinks` — catches a stale entry. It now has nothing to check, and that is
  fine; it is the half that would fail if a module were fixed and its entry left behind.
* `test_no_module_may_join_the_allowlist` — catches a **new** entry. With
  `ALLOWLIST_MEMBERSHIP_CEILING` empty, *any* addition to `DEBT_ALLOWLIST` fails immediately. This
  is the half that matters now, and it is why the ceiling was emptied rather than left holding three
  dead names.

An empty allowlist that nothing defends is a coincidence, not a guarantee.

| Guard | State |
|---|---|
| `DEBT_ALLOWLIST` | **empty** |
| `ALLOWLIST_MEMBERSHIP_CEILING` | **empty** — any new entry fails |
| `COHESION_EXEMPT` | **unchanged**, one entry (`engine.py`), ceiling 542, no owner, no date |
| Layer-rule `EXEMPTIONS` | **empty** |
| Package nesting | one level — `test_the_package_is_at_most_one_level_deep` passes |

`test_modules_discovered`'s canary was `assert "rbac.py" in modules`; since `rbac.py` no longer
exists it now names `rbac/tables.py`. That is the guard-the-guard assertion — it exists so a glob
matching nothing cannot make every other assertion vacuous — and it needs a live name to do its job.

v0.7.2** (DECISIONS #84), where four source-scanning guards silently began scanning almost nothing.
The **assertions** are untouched: only the file the test reads changed, from the module that no
longer holds the table to the one that does.
