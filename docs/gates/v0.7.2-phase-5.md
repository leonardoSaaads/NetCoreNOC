`serve` closure is inside `_asset_route`, which moved to `routes_static.py` verbatim.

### The strongest form: the same database, both versions, every route

A **live v0.7.1 database** was produced by installing the real v0.7.1 tree (commit `9cb2086`) into
its own virtualenv and driving it: 40 traps through the engine, a maintenance pass, four users, two
service tokens, four scorer configurations with history, both governance policy kinds with history,
labels, feedback, runtime config in `meta`, and a six-row audit chain. Then two copies were made and
**every** `/api` route (plus the seven public paths) was called on both — v0.7.1 code against one,
v0.7.2 against the other — and the full responses compared.

```
routes compared : 46   (39 authenticated + login + 7 static/health; SSE excluded, covered separately)
statuses        : 200 ×43, 403 ×1, 404 ×1, 422 ×1  — identical on both sides
response diff   : EMPTY — all routes answer identically
```

Only live wall-clock values written *by the probe run itself* are scrubbed; the stored timestamps
(`ts` on the six pre-existing audit rows, `first_seen`/`last_seen` on alarms, `created_at` on the
policy and scorer rows) are compared and match. Response bodies, status codes, `Cache-Control` and
the CSP header all match field for field, including every link's three scored terms to six decimal
places.
