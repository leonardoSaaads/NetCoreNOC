## 2. The authorization decision — exactly where it happens

**One site.** `src/netcorenoc/api.py::create_app.security()` (lines 290–327) is the only place a
request's capability is resolved. It is attached to every protected `/api` route either as
`dependencies=guarded` (`[Depends(security)]`) or as an explicit
`principal: auth.Principal = Depends(security)` parameter when the handler needs the principal.

Order inside `security()`:

1. **CSRF** (line 293) — cookie-authenticated mutations only (`method in MUTATING`, cookie
   present, no `Authorization` header) must pass `csrf_ok()`: `Origin`/`Referer` netloc equals
   `Host`, **and** header `X-NetCoreNOC-Client: ui`. Failure → **403**.
2. **Identity** (line 301) — `resolve_identity()` tries `Bearer` then the session cookie, under
   `store.lock`. `None` → **401** (`"authentication required"`).
3. **Bootstrap gate** (line 305) — `principal.must_change_password` and the route is not in
   `BOOTSTRAP_ALLOWED` → **403**.
4. **RBAC** (lines 308–322) — **the decision**:
   ```python
   permission = rbac.permission_for(method, path)  # ROUTE_PERMISSIONS lookup
   if permission is None or not rbac.role_allows(principal.role, permission):
       if permission in rbac.AUDITED_DENIED_PERMISSIONS:  # audited-denied, single source
           await audit_row(
               ...,
               DENIED_ACTION[permission],
               "denied",
               object_type="route",
               object_id=f"{method} {path}",
           )
       raise HTTPException(status_code=403, detail="insufficient role")
   ```
   `permission is None` is the **fail-closed** branch: a route absent from `ROUTE_PERMISSIONS`
   and not public is denied at runtime and fails CI
   (`test_rbac.py::test_every_api_route_is_in_the_permission_map`).
5. **Rate limit** (line 324) — token bucket per client address → **429**.

**Where 404 comes from.** Never from `security()`. Every 404 is raised *inside the handler*, after
authorization has already passed — `situation()` line 538, `entity_detail()` line 579,
`reset_entity()` line 618, `change_role()` line 742, `delete_user()` line 765, `revoke_token()`
line 814, `rollback_scorer()` line 1071. This ordering is what makes 403 never an existence
oracle, asserted by `test_rbac.py::test_403_precedes_404_no_existence_oracle`.

**How `AUDITED_DENIED_PERMISSIONS` produces a denied row.** `rbac.AUDITED_DENIED_PERMISSIONS` is
the single source of "is this denial worth a row?"; `api.DENIED_ACTION` is *only* the presentation
mapping capability → catalog action. An `assert` at import time (api.py line 94) plus
`test_rbac.py::test_f8_audited_denied_single_source` prevent drift. The row carries
`outcome="denied"`, `object_type="route"`, `object_id="{METHOD} {path}"`.

**How a session re-evaluates on role change.** Authorization is computed **per request** — there
is no cached capability set anywhere. `resolve_session()` (auth.py) re-reads the `user` row
through `store.get_session()` (which joins `user`) on every request, so `principal.role` is always
live. Belt and braces: `POST /api/users/{uid}/role` calls `store.revoke_user_sessions(uid)`
(api.py line 744), and so does a password change (line 488). Tests:
`test_auth.py::test_role_change_revokes_sessions`, `…_password_change_revokes_sessions`.

> **v0.7.0 consequence.** Because the capability decision is already one expression at one site
> and is already recomputed per request, layering `ceiling ∩ policy` means replacing
> `rbac.role_allows(principal.role, permission)` with a single resolver call at *that same line*.
> No second decision site is created, and live-session re-evaluation comes free — it is the
> property the current code already has.

## 3. The shaping decision — every field, and every surface scoping must filter

**One site.** `src/netcorenoc/shaping.py::shape(obj, role)` — a recursive, role-keyed serializer.
Field rules match by **key name at any depth**; a field with no rule passes through unchanged.

`FIELD_RULES` (the complete current table):

| Field | Min role for full value | Below it |
|---|---|---|
| `ip` | `editor` | **coarsen** → `/24` (v4) or `/48` (v6) network |
| `device_ip` | `editor` | **coarsen** |
| `device` | `editor` | **coarsen** (a label passes through `coarsen_ip` unchanged) |
| `source_ip` | `admin` | **drop** |
| `community_tag` | `editor` | **drop** |

`_rank(None) == -1`, so an unknown/absent role gets the strictest projection
(`test_shaping.py::test_unknown_role_gets_the_strictest_projection`).

**Every read endpoint returning NE / entity / situation / alarm / graph / timeline data** — the
exact surfaces v0.7.0's scope filter must cover:

| Route | Handler (api.py) | Store call | Shaped today? | NE-bearing? |
|---|---|---|---|---|
| `GET /api/stats` | `stats()` L502 | `store.stats()`, `list_ingest_gaps()` | no | **aggregate counters** (`devices`, `active_alarms`, `open_situations`) |
| `GET /api/graph` | `graph()` L515 | `graph_snapshot()` | yes (`ip`) | **yes** — `device` nodes + learned `edge` rows |
| `GET /api/classes` | `classes()` L521 | `list_classes()` | no | no (class dimension only) |
| `GET /api/situations` | `situations()` L526 | `list_situations()` | no | **yes** — via membership |
| `GET /api/situations/{sid}` | `situation()` L533 | `situation_detail()` | yes (`device_ip`) | **yes** — alarms carry `device_ip` |
| `GET /api/timeline` | `timeline()` L550 | `timeline_marks()` | yes (`device`) | **yes** — `COALESCE(label, d.ip)` |
| `GET /api/entities` | `entities()` L560 | `list_ne()` + `entities_for_ne()` | yes (`ip`) | **yes** — one row per NE |
| `GET /api/entities/{ne_id}` | `entity_detail()` L570 | `list_ne()`, `entities_for_ne()`, `varbind_profiles_for_ne()` | yes (`ip`) | **yes** — a single NE |
| `GET /api/state-clears` | `state_clears()` L603 | `list_state_clears()` | no | no (class dimension only) |
| `GET /api/events` (SSE) | `events()` L1161 | `stats()`, `graph_snapshot()`, `list_situations("open")` | yes | **yes** — all three |
| `GET /api/quarantine` | `read_quarantine()` L1093 | `list_quarantine()` | no | admin-only ⇒ never scoped |

**Two facts scoping depends on.**

1. **`ne` and `device` are 1:1 by IP.** `0003_entity.sql` L73–74 seeds
   `INSERT INTO ne (id, ip, …) SELECT id, ip, … FROM device`, and thereafter `Store.ne_id(ip)`
   and `Store.device_id(ip)` are called in lockstep per event. `alarm` carries **both**
   `device_id` and `ne_id` (`UPDATE alarm SET ne_id = device_id` at L89). Ids therefore coincide
   today — but the scope filter will join on **IP**, not on id equality, because id alignment is
   an artefact of the migration, not a declared invariant, and the `device_id` → `ne_id` cutover
   is an open ROADMAP line.
2. **The graph is a `device` projection.** `graph_snapshot()` selects from `device`, not `ne`. A
   scope resolved to NE ids must therefore also carry the corresponding **IP set** to filter graph
   nodes and their edges.

> **v0.7.0 consequence.** `shape()` recurses over an arbitrary body and knows nothing about rows.
> Resource scoping is a *different* operation on a *different* axis (which rows, not which
> fields), so it gets its own resolver next to `shape()` in the same module — one decision site
> per axis, composed at each read path, exactly as the governance draft specifies.

## 4. The two candidate-selection implementations to unify

### 4a. The engine — `Correlator._recent_live()` (`correlate.py` L177–187)

State: a `deque[WindowAlarm]` (`window`) plus a parallel `dict[int, WindowAlarm]` (`index`) that
defines **liveness**; `remove()` deletes from `index` only, leaving a **tombstone** in the deque.

```
_evict(now):   while window and now - window[0].ts >  window_s: popleft (+ drop from index)
               while len(window) > max_window:                  popleft (count live as overflow)
_recent_live(): iterate reversed(window); keep entries whose id is in index;
                stop at max_candidates; reverse → chronological
```

Constants: `WINDOW_S = 120.0`, `MAX_CANDIDATES = 100`, `MAX_WINDOW_ALARMS = 20_000`.

### 4b. Preview — the windowing inside `preview.partition()` (`preview.py` L64–103)

```python
window = [w for w in window if new.ts - w.ts <= PREVIEW_WINDOW_S]
for old in window[-PREVIEW_MAX_CANDIDATES:]:
    ...
window.append(new)
```

Constants: `PREVIEW_WINDOW_S = 120.0`, `PREVIEW_MAX_CANDIDATES = 100` — numerically equal to the
engine's, but **separately declared**. Nothing in the tree ties the two together: changing
`correlate.WINDOW_S` alone would silently make the what-if lie.

### 4c. Are they behaviourally equivalent today on a tombstone-free snapshot? — **Yes, confirmed**

| Aspect | Engine | Preview | Same? |
|---|---|---|---|
| Retention predicate | keep iff `now - ts <= window_s` (drop on `>`) | keep iff `new.ts - w.ts <= PREVIEW_WINDOW_S` | ✅ identical, including the `==` boundary |
| Cap | last `max_candidates` **live** entries | `window[-PREVIEW_MAX_CANDIDATES:]` | ✅ identical when no tombstones |
| Order handed to the scorer | chronological (`recent.reverse()`) | chronological (list order) | ✅ |
| Self-exclusion | `remove(new.alarm_id)` before selection; `append` after | `append` after the loop | ✅ (preview ids are distinct by construction) |
| Absolute cap | `MAX_WINDOW_ALARMS = 20_000` | none — but bounded by `MAX_PREVIEW_ALARMS = 5_000` | ✅ cap cannot bite |

**Empirical confirmation.** A randomised differential probe (300 trials; 1–120 alarms; Δt drawn
from `{0, 0.5, 3, 17, 61, 130}` s to straddle both window edges; `max_candidates ∈ {3, 10, 100}`;
`window_s ∈ {30, 120}`) replayed both selectors over the same alarm sequence and compared the
**candidate id list per new alarm**:

```
trials=300 mismatches=0
engine constants:  WINDOW_S 120.0          MAX_CANDIDATES 100
preview constants: PREVIEW_WINDOW_S 120.0  PREVIEW_MAX_CANDIDATES 100
```

**The two divergences that exist today, and which the unification removes:**

- **Constants are duplicated, not shared.** Equality is a coincidence maintained by hand.
- **Tombstones.** The engine's window can hold cleared/re-activated alarms that are *not*
  candidates; preview's snapshot has no such notion. On a tombstone-free snapshot — which is what
  `store.recent_alarms_for_preview()` returns — the selections coincide. This is the equivalence
  §5/S0 makes **structural** rather than accidental, and it is exactly the caveat the parity test
  must encode.
