# v0.14.0 — Gate 8: guards, mutations, and the verification battery

**Gate 8 asks three things**: every guard with a recorded red and a named control; the mutation
ledger listing every survivor **by name, not as a ratio**; and the limitations section written.

The demonstrations are [`v0.14.0-guard-demonstrations.md`](v0.14.0-guard-demonstrations.md) — fifteen
injections, fifteen reds, fifteen controls, and one control that turned out not to be one. This
document is the **verification** half, and §3 is the ledger.

## 2. Coverage, against **both** registered bands

ADR #194 registered a band **before** the measuring run, as ADR #181 requires, and #181's own band is
carried forward and not re-cut. Both are reported:

| Band | Range | Measured | |
|---|---|---:|---|
| ADR #181 (v0.13.0) | 95.60 – 96.60 % | **95.92 % / 95.94 %** | **inside** |
| ADR #194 (v0.14.0) | 95.30 – 96.40 % | **95.92 % / 95.94 %** | **inside** |

**Two runs, both reported, neither picked.** The statement count is identical at 7 822 and the
figures differ by 0.02 — one branch, and exactly the spread ADR #194 measured on the Gate-0 commit
before any of this code existed. v0.12.0 established the rule after reporting a single sample and
having to withdraw the claim: *report both figures rather than guessing which is the number.*

**The prediction is worth one sentence on its own.** ADR #194, written before a line of model code
existed, projected the denominator moving *"from 7 119 statements to about 7 819"*. It is **7 822** —
three statements out, on a release that added seven `src/` modules and two console screens. That is
luck in the last digit and arithmetic in the rest, and it is recorded because a band derived from a
denominator estimate is only as good as the estimate.

## 3. The mutation ledger — survivors, **by name**

Ten mutations were written with the *expectation* that some would survive. Two were caught; **eight
survived the whole suite**, and each was confirmed by running all 1542 tests against it:

```
BASELINE (clean tree): 1542 passed in 298.70s
```

Every survivor below produced exactly that line.

### S-A — the CART tie-break is not asserted anywhere

```diff
- if gain > best_gain:
+ if gain >= best_gain:
```
`cart.py`'s docstring is specific: *"the winner among equals is the lowest feature index and then the
lowest threshold — the rule the tie-break lives in the two loops and the one `>`."* Making the
comparison non-strict inverts it to last-wins. **1542 passed.**

Determinism is unaffected — the new rule is equally deterministic — so
`test_two_fits_in_two_processes_are_byte_identical` cannot see it, and nothing asserts *which*
deterministic tree comes out. It matters because two builds of this project would then disagree about
the same corpus, silently.

### S-B — *caught*

`bisect_right` in place of `bisect_left` in the attribution's cell lookup is caught by
`test_the_sum_identity_holds_exactly`.

### S-C — the discrimination floor's estimator is not asserted

```diff
- spread = math.sqrt(sum(...) / len(values))
+ spread = math.sqrt(sum(...) / max(1, len(values) - 1))
```
`_discrimination`'s docstring argues population rather than sample standard deviation, *"because the
probe set is the whole population this floor is defined over"*. The change makes every model's spread
slightly larger and therefore **admits models the floor was written to refuse**. **1542 passed.**

### S-D — a non-computable rate contributing zero is not asserted

```diff
- if score.over_merge is not None:
-     over.setdefault(incident, []).append(score.over_merge)
+ over.setdefault(incident, []).append(score.over_merge or 0.0)
```
This is the distinction `docs/ROADMAP.md`'s *"Found while building v0.11.0"* records as having cost
this project a release: **a rate that is not computable is not a rate of zero.**
`promotion_metrics.py`'s docstring says so in the function this mutates. Nothing tests it.
**1542 passed.**

### S-E — the harness's `bind` failing open is not asserted

```diff
- sock.bind((to_wire(source), 0))  # raises rather than falling back
+ with contextlib.suppress(OSError):
+     sock.bind((to_wire(source), 0))
```
The exact construct `appliance.py`'s own docstring identifies as *"right for a burst generator and
wrong here"*. Under it every trap arrives from `127.0.0.1`, the whole simulated network collapses
onto one NE **before the correlator sees it**, nothing fails, and every number in Gate 7 would be
about a different corpus. **1542 passed.**

The most dangerous survivor in the list, because it corrupts a *measurement* silently rather than
breaking a behaviour loudly.

### S-F — which principal sends the CSRF headers is not asserted

```diff
- if self.console:
+ if True:
```
The harness would then send `Origin` and `X-NetCoreNOC-Client` from its **bearer** clients too. That
is not a vulnerability — `perimeter` only checks them on a cookie-authenticated mutation — but it
would mean the harness had stopped carrying each principal's real headers, and a future CSRF check
that *did* apply to tokens would be demonstrated against a client that was already sending the
answer. **1542 passed.**

### S-G — the bootstrap resampling bags instead of incidents is not asserted end to end

```diff
- out[incident_of.get(situation, situation)].append(row)
+ out[situation].append(row)
```
`PREREGISTRATION-0.10.0.md` §2.6(d)'s whole point: **the bootstrap resamples incidents**, so a storm
that contributed one bag contributes one bag. `shadow_cv.cluster_bootstrap` is tested directly, but
nothing asserts that `promotion_metrics` hands it *incidents*. **1542 passed.**

### S-H — the storm's size is not asserted against the constant it exists to clear

```diff
- STORM_ONUS = 56
+ STORM_ONUS = 12
```
`generator.py` says *"a storm has to clear `learn.STORM_ALARMS` (50) to exercise `STORM_DAMPING` and
`MAX_LINKS_PER_ALARM`."* Twelve does not. The shape would keep its name and stop being a storm — and
F58, which is entirely about what a storm does, would not have been findable. **1542 passed.**

`eval/simulation/measure.py` exits non-zero if any shape produces no near-threshold pair, and it
still would: twelve ONUs produce plenty. **A shape can lose its point without losing its content.**

### S-I — the merge chain's bridge order is not asserted

```diff
- base + 20.0,
+ base + 40.0,
```
Reordering the bridges collapses the chain to depth 1, which
`docs/gates/v0.14.0-phase-6.md` §4 spends a page explaining is the difference between a `COALESCE`
and a transitive resolution. `measure.py --increments 6` exits non-zero when the longest chain is
below 2 — **and `make qa` does not run it.** **1542 passed.**

### S-J — *caught*

Turning the candidate scorer's load failure into a silent fallback is caught by
`test_a_candidate_whose_document_will_not_load_is_refused_not_substituted`.

### 3.1 What the survivors have in common

Six of the eight are **properties a docstring states and no test asserts** — and in four cases the
docstring is emphatic, italicised, and points at a past defect. The project's habit of writing the
reason next to the code is doing real work; it is not doing the work of a test.

Two of them (S-H, S-I) are guarded by `eval/simulation/measure.py`, which **is** a gate and **is not
in `make qa`**. That is a one-line CI change and it is a ROADMAP entry rather than a fix here.

is at or under 400, in `src/`, `eval/` and `ui/` alike.

## 6. What this gate does not establish

* **That the guards are complete.** Fifteen caught is fifteen caught. **F58, F59 and F60 were each
  found by driving the system, not by a guard**, and the guards for two of them exist now because
  the defects did first. `SECURITY-REVIEW-0.14.0.md` §7.1 says this at more length and it is this
  release's least comfortable result.
* **That the ledger is unbiased.** *The ledger's author chose the mutations.* v0.12.0 recorded that
  bias and this is its third measured instance: eight of ten survived, which says as much about the
  choosing as about the suite. A mutation set generated mechanically would say something different
  and nobody has run one.
* **That coverage means what it looks like.** 95.92 % is a statement about lines executed. S-A to S-I
  all live in **covered** lines: every one of those files is exercised, and every one of those
  behaviours is unasserted. Coverage and assertion are different measurements and only one of them is
  reported as a percentage.
* **Anything about the visual layer.** Outside the instrument since v0.12.0.
  [`v0.14.0-live-verification.md`](v0.14.0-live-verification.md) is the pass that looked, and it
  found five defects every structural assertion was green through.
