## Security scans

- **bandit** (`-c pyproject.toml -r opticorr tools`) — **0 issues** (exit 0). The only `# nosec`
  annotations are the pre-existing, reviewed `B104` binds and `B608` parameterized-query
  strings; the new SQL (`closed_alarm_varbind_lifetimes`, `list_state_clears`,
  `clear_varbind_roles`, `reset_ne_ids`) is fully parameterized or static.
- **pip-audit** — the only findings are CVEs in the environment's **`pip` installer tool**
  (24.0), not in any OptiCorr runtime dependency. v0.3.0 keeps the prime directive of **zero new
  runtime dependencies**, so the runtime dependency surface is unchanged from v0.2.0.
- **F1/CSP** — `test_security_ui.test_ui_source_has_no_f1_antipatterns` still holds after the
  S11 UI additions: no `innerHTML`, no inline scripts/styles, no external origins; every new
  external string (entity keys, severity tokens, state values, `key_source` OIDs) reaches the
  DOM only through `createTextNode`/`textContent`. The F1 XSS harness drives hostile payloads
  through the entity/severity/profiler surface and they round-trip as inert data.

## Threat-model re-read (per-phase discipline)

`docs/threat-model.md` was re-read this phase. The v0.3.0 attack surface — attacker-controlled
strings over UDP 162 becoming entity keys / severity / state values — is covered: entity-key
XSS (inert-data test), entity-cardinality DoS (`MAX_ENTITIES_PER_NE`, warned + audited),
profiler memory DoS (`MAX_TRACKED_*` + the bounded severity `display` map + `MAX_STATE_SLOTS`),
learning poisoning (thresholds/margin + admin `entity.reset`/`profile.reset`), and silent
misattribution (`key_source`/`confidence` surfaced + `entity_accuracy` frozen-baseline gate).

a measured learning lift, both security scanners are clean of OptiCorr findings, and every
