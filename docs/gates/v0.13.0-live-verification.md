# v0.13.0 — live verification: the console in a real browser

Everything in [`v0.13.0-phase-7.md`](v0.13.0-phase-7.md) is measured through the DOM harness. The
harness links the real module graph, mounts the real components and dumps the real tree — and it
has **no layout, no cascade and no paint**. It cannot tell you that two words are touching, that a
table cell is blank, or that a card is unreadable. Gates 2 to 7 assert *structure*, and structure
was green while six things were wrong on screen.

This document is the pass that looked.

> **The tool is scratch, not a dependency.** The drive below uses Playwright and the pre-installed
> Chromium from a scratch directory outside the repository. `pyproject.toml` is unchanged, nothing
> in `tests/` imports it, and `make qa` neither runs nor requires it. The runtime dependency count
> is still five. A browser drive that had become a fourth CI dependency would have bought a smaller
> thing than it cost.

---

## 1. Method

A real appliance, not a fixture server.

```sh
NETCORENOC_DB=/tmp/live/live.db \
NETCORENOC_TRAP_PORT=11162 \
NETCORENOC_HTTP_PORT=8099 \
NETCORENOC_HTTP_HOST=127.0.0.1 \
python -m netcorenoc.main
```

Empty SQLite, first-run admin, migrations `0001`–`0013` applied on boot. Alarms arrive the way they
arrive in production: **real SNMPv2c trap PDUs over UDP**, sent by `tools/trap_replay.py`, which is
already in the tree. No API was used to insert an alarm, no row was written by hand, and the
correlator was not told anything.

Before the drive, the bytes the appliance serves were compared with the bytes in the working tree,
because a stale in-memory copy would have made the whole exercise a measurement of an older UI:

```
SAME  app/views/settings.js
SAME  app/views/situations.js
SAME  app/views/overview.js
```

The browser is the Chromium that ships with this container, driven headless at 1440 × 1000, with
console messages and every HTTP response ≥ 400 collected for the whole session.

### 2.2 The console at the end of the session

```
error: Failed to load resource: the server responded with a status of 401 (Unauthorized)
error: Failed to load resource: the server responded with a status of 404 (Not Found)
```

Both are expected and neither is a defect:

- **401 `GET /api/me`** — the boot probe. The console asks who it is before it has a session; the
  appliance says "nobody"; the sign-in card is rendered. That request *has* to be made and it *has*
  to be refused, and Chromium logs every 4xx to the console whether or not the page handled it.
- **404 `/favicon.ico`** — the browser asks for one unprompted. The appliance ships no favicon, and
  `STATIC_ASSETS` is a compile-time allowlist, so the answer is a clean 404 rather than a path
  lookup. Adding a favicon to silence a log line would add a shipped asset to a release that was
  supposed to add none.

No other error, no warning, no failed request, across a session that touched all 17 views, expanded
four situations and wrote two judgements.

## 3. The scenarios, on screen

### 3.1 Fibre cut — `eval/corpus/fiber_cut.json`

Situation **#1**, 8 alarms.

```
Probable root: 1.3.6.1.4.1.1271.2.1.1 on 127.0.0.2
per-term contributions: T 0.29, A 0.00, E 0.35, T 0.29, A 0.06, E 0.35
```

The three named terms are on screen with **the number beside each bar**, which is the one thing this
release exists to do. Class affinity reads `0.00` on the first link and `0.06` on the second: the
appliance has learned almost nothing about these classes yet, and the screen says so rather than
rounding it away.

### 3.2 PON dying gasp, authored — **rejected**

An authored trap set (one OLT power alarm plus six Huawei ONU dying gasps, `1.3.6.1.4.1.2011.5.104.*`
from `127.0.0.40`) correlated into situation **#4**: 7 members, 20 explained links.

Two members were ticked as not belonging and the grouping rejected:

> **Recorded: this grouping is wrong. Only the members you marked are asserted negative.**

That sentence is the whole reason the reject path is worth driving. A reject that asserted every
pair negative would poison the corpus with pairs the operator never looked at; the wording tells the
operator exactly what their tick did.

### 3.3 OLT storm — `eval/corpus/olt_storm.json` — **accepted**

Situation **#3**, **501 alarms**, every member rendered in one card, no virtualisation and no
truncation.

> **Recorded: this grouping is correct. Every pair in it is now an asserted positive.**

### 3.4 PON dying gasp, as the repository ships it — **accepted**

**A correction to an earlier claim of mine.** While setting up §3.2 I said no PON dying-gasp
scenario existed in this repository and authored one. That was wrong, and it was wrong because I
checked `tools/trap_sim.py --list` — which offers `bgp_flap`, `chassis_card` and `login_burst` — and
stopped there. `eval/corpus/pon_dying_gasp.json` has shipped since **v0.3.0**. The canonical fixture
was then replayed, and it is the more interesting of the two:

```
events: 1051   sources: 10.10.0.1 ×1051   distinct trap_oids: 4   span: 10.5 s
description: "One OLT proxies ~1050 ONU traps during a power outage; entity id is in varbinds."
```

Situation **#5**, **1 038 alarms**, expanded in **3.9 s**:

```
columns: ['', 'device', 'class', 'instance', 'severity', 'count', 'state']
distinct devices in the card: ['127.0.0.1']
distinct instances (entities): psu-A, onu-0, onu-1, onu-2, onu-3, … 347 distinct
entity affinity non-zero on 30 of 30 explained links
Probable root: 1.3.6.1.4.1.2011.6.128.1.1.1.1 on 127.0.0.1
```

**One device, 347 entities.** Every trap arrives from the same source, so the device has no
discriminating power at all — the entity identifier is buried in a varbind, and the entity-affinity
term is carrying the entire grouping. The screen shows that: `E` is non-zero on all thirty explained
links and `A` is `0.00` throughout. An operator can read *why* a thousand alarms are one incident
without being told, which is the claim the release is making.

Accepted, and recorded.

## 4. Six defects found by looking, that every test passed through

None of these is a crash. Every one of them is a thing the DOM harness cannot see, and all 1 428
tests were green while all six were on screen.

### 4.1–4.5 Five collapsed spaces (`htm` whitespace semantics)

`htm` collapses a newline **adjacent to a tag boundary to nothing**, not to a space. So this:

```js
html`<p class="root">Probable root:
  <b>${alarmName(root)}</b>`
```

paints `Probable root:1.3.6.1.4.1.1271.2.1.1`. The harness dumps the same text nodes either way and
reports a correct tree.

| File | On screen, before |
|---|---|
| `views/situations.js` | `Probable root:1.3.6.1.4.1.1271.2.1.1on 127.0.0.2` |
| `views/overview.js` | `…reached the pre-registered floors is computed by<code>make shadow-report</code>` |
| `views/governance.js` | policy sentence joined to the following `<code>` |
| `views/promotion.js` | verdict joined to the outcome that follows it |
| `views/retention.js` | count joined to the unit after it |

All five were fixed with an explicit `${" "}` rather than by reflowing the template — a reflow that
happens to put a space in is a fix nobody can see in a diff and nobody will preserve. The whole tree
was then re-scanned with a regex over every `` html`…` `` block; the scan reports **0** remaining.

### 4.6 The blank cell in the settings precedence table

`NETCORENOC_ALLOWLIST` is unset, and unset means *accept every source*. The effective column
rendered the empty string, so the most permissive value the appliance has printed **as nothing at
all** — in a three-column table whose entire purpose is to explain why a setting has the value it
has.

```js
effective: effective === "" || effective == null
  ? html`<span class="muted">(empty — every source accepted)</span>`
  : html`<b class="mono">${String(effective)}</b>`,
```

On screen now:

```
NETCORENOC_ALLOWLIST | (unset — empty = accept every source) | (none) | (empty — every source accepted)
```

A test asserting `cell.textContent === ""` would have passed. A test asserting the cell *exists*
would have passed. The defect is that an empty string is a legible value for this setting and the
table rendered it as absence.

## 5. Three defects in the probe, recorded because Appendix B named them

The drive script found its own bugs, and all three are traps this project has a name for.

1. **A guard scoped by a literal string.** The probe asserted `"Why these were grouped" in text`
   and reported the section missing. `h3 { text-transform: uppercase }` means `inner_text()`
   returns **what is painted** — `WHY THESE WERE GROUPED`. The section was on screen the whole
   time. Matched case-insensitively now.
2. **A selector that cannot match is a check that measures nothing.** The probe counted distinct
   devices with `td.dev`. `DataTable` puts no per-column class on a `<td>`; the columns are
   positional. It matched zero cells and reported an empty set as a failure — it would equally have
   reported an empty set as a pass had the assertion pointed the other way. Re-addressed by reading
   the `device` column's index out of the `<thead>`.
3. **A control that was never there.** The theme probe clicked a `button` containing the text
   `Dark`. The control is a glyph button whose only stable handle is its accessible name,
   `aria-label^="Theme:"`. The first version failed on a control that works.

The distinction that matters: **§4 is six product defects; §5 is three probe defects.** Reporting
nine would have inflated the finding, and reporting six without §5 would have hidden that the
instrument needed correcting too.

## 7. What this pass did **not** verify

Named, because a verification document that only lists what it did is an advertisement.

- **No second browser.** Chromium only. Firefox and WebKit were not driven, and no statement is
  made about them.
- **No small viewport.** 1440 × 1000 throughout. The stylesheet has responsive rules; they were not
  exercised, and the 501-row and 1 038-row cards were not looked at on a narrow screen.
- **No screen reader.** The accessibility floor claimed in ADR #180 is structural — roles, labels,
  focus order, one tab stop — and all of that was checked. **Nothing here was heard.** No NVDA,
  JAWS or VoiceOver pass was made, and the network graph remains explicitly excluded.
- **No contrast measurement.** The two themes were rendered and read by eye. No contrast ratio was
  computed against WCAG AA.
- **No performance claim beyond one number.** A 1 038-member card expanded in 3.9 s on this
  container, once. That is an observation, not a budget: it was not repeated, not measured on other
  hardware, and no threshold was registered in advance.
- **No multi-user session.** One admin, one browser, one tab. Concurrency, session expiry mid-drive
  and the SSE reconnect path under real network loss were not driven here — the reconnect *logic*
  is covered by the harness, and the harness has no network.
- **This is not automated.** It is a script in a scratch directory and a set of screenshots. It is
  not in `make qa`, it will not run in CI, and it does not protect the next release. What protects
  the next release is §4's lesson written down: **the harness cannot see whitespace or emptiness,
  so a UI change needs one pass with eyes on it.** That is ADR #182.

## 9. What CI caught that none of this did

**The release was tagged, packaged and handed over. Then CI failed on the first push.**

```
make security PYTHON=python
python -m bandit -q -c pyproject.toml -r src/netcorenoc tools
...
Total issues (by severity):  Low: 12
make: *** [Makefile:12: security] Error 1
```

Twelve bandit findings — B404, B603, B607 — all in the three `tools/evidence/` commands this
release added, which are the first code in `src/` or `tools/` to use `subprocess` at all.

### Why every gate above missed it

**`make security` is not part of `make qa`, and I never ran it.** `qa` is
`lint typecheck deadcode test eval`. Bandit was the one static analyser in this repository that the
routine local gate did not invoke, and the release that first introduced a `subprocess` call was
the release that found out. Everything §1–§8 measures is real; none of it was ever going to see
this, because none of it ran the check.

**A local gate that does not run what CI runs is a gate with a hole in it, and the hole is exactly
the size of the check nobody local performs.** That is a more useful statement than "I forgot".

### The repair, in three parts

1. **The findings are closed at the source, not suppressed wholesale.**
   - **B607** (partial executable path) is a genuine property and was **fixed**, not annotated:
     `git` is now resolved once through `shutil.which()` to an absolute path, so a directory earlier
     on `PATH` cannot decide which `git` runs, and its absence is an explicit error rather than a
     confusing failure inside a subprocess.
   - **B603/B404** carry `# nosec BXXX` on the exact line with the reason written above it, matching
     the convention already used for B105, B104 and B608 elsewhere in this repository. Every
     annotated call passes a fixed argv with `shell=False`, an absolute executable, and no operator
     input. Bandit now reports **"No issues identified"** with **30** targeted suppressions, up from
     24 — and the six new ones are each one line, one code, one stated reason.
2. **The local gate now runs the check.** `make security` is split: `scan` is the offline half
   (bandit) and is now part of `make qa`; `pip_audit` stays in `security` because it queries PyPI
   and would make the routine local gate fail on an offline machine for a reason that has nothing to
   do with the code. `make security` still runs both, so CI's step is unchanged.

   **Adding `scan` to `qa` broke a test, and the test was wrong.**
   `test_make_qa_runs_the_dom_harness` asserted the literal string
   `"qa: lint typecheck deadcode test eval"` — which is precisely the trap Appendix B names, a
   guard scoped by a literal. It failed on a change that makes the gate *stronger*, while the
   property it actually claims is only *"`test` is one of `qa`'s prerequisites, so nobody has to
   remember to run the harness."* The recipe is now parsed and that property asserted directly.
   Demonstrated rather than asserted:

   ```
   corrected tree      guard + control            -> 2 passed
   `test` dropped from qa                         -> 1 failed, 1 passed   (control held)
   a second `qa:` target appended                 -> 1 failed
   ```

   A guard that only fires on the exact wording of the thing it guards is a guard that fires on
   edits and not on regressions.
3. **Three more defects in the same three files, found while fixing the first.**
   - `ROOT = Path("/home/user/NetCoreNOC")` — the build container's absolute path, hardcoded in all
     three tools. **The reproduction commands printed in `v0.13.0-phase-7.md` worked on exactly one
     computer in the world.** `ROOT` is now derived from the script's own location.
   - `PY = ROOT / ".venv" / "bin" / "python"` — assumed a virtualenv at a fixed path. CI installs
     into the system Python, so the tools would have invoked an interpreter that does not exist.
     Now `sys.executable`.
   - `mutation_ledger.py` wrote `.demos/mutants.json` into a directory only
     `guard_demonstrations.py` created — as an **import-time side effect**. Running the ledger on
     its own raised `FileNotFoundError` after the measurement finished. Both tools now create their
     own output directory inside `main()`, so importing a module no longer writes to the repository.

### And re-running the instruments found a fourth thing: the ledger was reporting a fiction

Re-running the three evidence commands from the repaired tree — the only way to know a refactor
did not quietly break the tools a release's claims rest on — produced a result the documents
contradicted.

`tools/evidence/mutation_ledger.py` printed **17/19 with two survivors**, against a build report
that said **21/21 with none**. Three faults, all in the instrument:

| Fault | Effect |
|---|---|
| `SUITE` omitted `tests/test_api.py` | Both Python mutants live in `routes_admin.py`/`routes_static.py`; the tests that kill them are HTTP tests. **The ledger was measuring its own `SUITE` list, not the repository.** |
| the `routes_static.py` anchor named a dict comprehension the file does not contain | Recorded honestly as `NOT APPLIED — anchor missing` — which means **that mutant had never been measured at all**, in any run |
| the third mutant existed only in prose | Found and closed during the build, never added to the table, so the tool could not reproduce the number printed beside it |

All three fixed. The command now prints **20 mutants, 20 killed, 0 survivors**, the committed
`evidence/v0.13.0/mutation-ledger.json` is that run, and `21` is gone from both documents — it was
never a measurement, it was arithmetic done in prose over a table that held nineteen.

The other two instruments came back clean: **15/15 guard demonstrations** still red under injection,
green after revert, with the control holding in both, and the `ui/` tree digest matching the tree
independently afterwards; and the render drive differs from the committed evidence in exactly the
values §4.6 changed.

### The honest shape of this

Six defects in §4 were found because I looked at the screen. **Four more were found because CI ran
a check I had not, and three more because I re-ran the instruments instead of trusting what I had
written about them.** All of it is the same lesson pointing at different instruments: a green gate
is evidence about what it measures and silence about everything else.

The sharpest of the three is worth stating on its own, because it is the failure this whole release
argues against. **A gate document quoted a number its own reproduce command did not print, and
nobody would have known without running it.** The prose said 21/21; the tool said 17/19. Writing
"reproduce it with `python tools/evidence/mutation_ledger.py`" beneath a figure the command does not
produce is worse than quoting no figure, because it borrows the authority of a measurement without
having made one.

The gate documents in this release are careful to name what they do not cover. This one did not name
`make security`, because I did not notice it was missing, and §7.2 did not name the gap between its
table and its arithmetic, because I did not re-run it. Both are named now — and `make qa` runs the
first.
