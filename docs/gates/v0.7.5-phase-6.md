## 4. Quickstart verified from scratch — **substitute**

The build prompt requires the quickstart verified via `docker compose up`.

```
$ docker compose config
docker compose config: VALID

$ docker info
daemon: NOT running
```

**The Docker daemon is unavailable in this build environment, so the image was not built and the
container was not run.** Said plainly.

The documented substitute was performed: a **freshly built wheel** installed into a **clean
virtualenv**, serving every public path with the security headers intact —
`v0.7.5-phase-5.md` §9 has the full transcript. It establishes that the package resolves from
`site-packages` rather than `src/`, that `create_app` runs (and therefore the F42 gate runs as its
last statement, producing exactly `{APIRoute, Route}`), that all eight public paths return 200 with
the four security headers, that `/api/stats` still 401s without an identity, and that the **shipped**
`app.js` carries the v0.7.5 changes and no `innerHTML`.

It does **not** establish that the container image builds, that the hardened runtime (read-only
rootfs, dropped capabilities, non-root uid) works, or that the healthcheck passes. Those are
unverified in this build and a maintainer with a daemon should run `docker compose up --build` once
before tagging in anger.

## 5. Upgrade from a live v0.7.4 database — **verified directly**

Not a substitute. A git worktree at commit `b2ea0f7` (the v0.7.4 release) wrote the database with
that code — 16 real traps through the real `Engine.run()` loop, a real user, a real API token and a
chained audit row written by the project's own `audit.write_event`. v0.7.5 then opened it:

| | |
|---|---|

| Schema (tables, indexes, views; normalised SQL) | **identical** |
| Row counts, all 25 tables | **identical** |
| `PRAGMA integrity_check` | **ok** |
| Audit chain under v0.7.4 (writer) | `OK: 1 entries verified; final hash 405275083f09…` |
| Audit chain under v0.7.5 (reader) | `OK: 1 entries verified; final hash 405275083f09…` |

`v0.7.5-phase-5.md` §8 also records the harness defect found and fixed along the way — the first
version hand-rolled the audit hash and produced a false "chain BROKEN" — because a verification
script that fabricates the artefact it verifies can report a success that is not there just as
easily as a failure.

## 6. The manual verification protocol — **present, and unexecuted by this build**

`docs/gates/v0.7.5-manual-verification.md` exists, is written to be run by someone who did not build
this (20 minutes, exact commands, explicit PASS/FAIL criteria, a sign-off block), and includes a
checkpoint that **halts the protocol if the SSE stream is not live** — because every test after that
point would otherwise pass for the wrong reason.

**This build did not execute it.** There was no browser and no operator. That is stated in §9 of the
protocol itself, in `v0.7.5-phase-4.md` §5, in `SECURITY-REVIEW-0.7.5.md` §7.1, in the build report
§4 and §9.1, and in the `CHANGELOG.md` entry — five places, because it is the single most misreadable
fact about this release.

**Three of the four intentional behaviour changes are proved by that document and by nothing else.**
A green `make qa` is not evidence for them.

prompt's delivery model instructs that a 403 be reported rather than routed around. It was: no
GitHub API call, no alternate remote, no pull request. All commits are local on the designated
