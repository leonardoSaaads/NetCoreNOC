## 1. The file list comes from `git ls-files`, and that is the whole design

```python
proc = subprocess.run(["git", "ls-files", "-z"], cwd=str(root), …)
```

Three properties, each chosen against a failure this repository has already had.

**It cannot drift by name.** A directory walk needs a skip-list, and v0.10.1's F51 was a skip-list
scoped by the literal string `.venv` — a virtualenv named anything else stopped being skipped, and
the guard started reporting on thousands of files nobody here wrote. A build-step guard with a
skip-list fails the same way in the *mirror*: an artefact under a directory the list happens to name
stops being **found**, and the guard goes quiet without going red. `git ls-files` answers *"what
does this repository contain"*, which is the question, and has no name-based scope to widen.

**It cannot report clean by accident.** `tracked_files()` returns `None`, never `[]`, when git does
not answer. An extractor that answered "no files" outside a repository would report every tree
clean, and `test_the_tracked_tree_contains_no_build_step_apparatus` asserts `paths is not None`
before it asserts anything about the contents. That is Appendix B's *"measuring nothing and
concluding CLOSED"* with a guard's name on it.

**It draws the line where the line belongs.** An **untracked** `node_modules/` is not part of what
the maintainer ships; a **tracked** one is. §3 asserts both directions.

The four artefact classes are four **named predicates** rather than one boolean expression, because
each is a separate claim and the vacuity check exercises each separately:

```python
inside_package_dir      = any(part in BUILD_STEP_DIRS for part in parts)
is_manifest_or_lockfile = name in BUILD_STEP_FILES
is_bundler_config       = stem in BUILD_STEP_STEMS
is_generated_ui         = "ui" in parts and "dist" in parts
```

## 2. The vacuity check, driven through the same code path

**A broken extractor reports every tree clean.** So the check does not call a helper — it builds a
**real git repository**, adds each artefact class to it with a real `git add`, and asserts the real
extractor finds it.

That the repository is real is not incidental. v0.9.2's ledger entry L2 records a guard test that
called `_is_inside_venv` directly and **stayed green when the walk was reverted to the name list**,
because the helper still existed and nothing called it. A fixture that bypassed `git ls-files` here
would repeat that exactly.

Seven artefacts, added and removed **one at a time**, so a partial extractor cannot pass by
recognising one class:

| added, then `git add -f` | found |
|---|---|
| `package.json` | ✅ |
| `package-lock.json` | ✅ |
| `yarn.lock` | ✅ |
| `pnpm-lock.yaml` | ✅ |
| `vite.config.js` | ✅ |
| `node_modules/left-pad/index.js` | ✅ |
| `src/netcorenoc/ui/dist/bundle.js` | ✅ |

**And the other half**, which is the one usually forgotten: an extractor that flagged *everything*
would pass the table above.
`test_a_clean_scratch_repo_is_reported_clean` asserts a repository holding only a `README.md` comes
back `[]`.

## 3. Tracked versus present, asserted in both directions

```python
# untracked node_modules/left-pad/index.js on disk
assert build_step_artefacts(paths) == []
# … then `git add -f node_modules`
assert build_step_artefacts(paths) == ["node_modules/left-pad/index.js"]
```

The harness needs no `node_modules` and creates none. The rule is stated for the day some tool makes
one.

**`node_modules` is deliberately *not* in `.gitignore`** (ADR #169), and there is a test asserting
it stays out. Ignoring it would be the obvious tidy-up and it is the wrong one: the guard is scoped
to the tracked set *by design*, so the only remaining signal that a machine has grown one is a dirty
`git status`. Ignoring it would remove that signal **and** leave the guard unable to see it by
construction — two blind spots where there was one.

## 4. Tool versus product, written down where v0.13.0 will read it

> **Node as a test dependency is permitted. Node as a build step for shipped assets is not.**

The distinction is in `tests/test_build_step.py`'s module docstring, deliberately — v0.13.0 will
open this file while vendoring a framework, and the rule should be in front of whoever does it.

What principle 6 forbids is a **transformation between the source and what a browser receives**: a
bundler, a transpiler, a minifier, a lockfile that must be resolved before the UI exists. Not the
existence of a JavaScript interpreter on a developer's machine.

Four assertions make the distinction structural rather than merely written:

| Test | Asserts |
|---|---|
| `…_the_harness_is_a_tool_and_is_not_flagged_as_a_product_build_step` | the harness is tracked, comes back clean, and appears in no `package-data` glob |
| `…_the_harness_is_a_test_tool_and_never_a_runtime_dependency` (Phase 2) | the runtime dependency list is unchanged at five; nothing under `src/` names the harness |
| `…_the_harness_tree_holds_no_installed_dependency` (Phase 2) | every `import` in the harness resolves to `node:*` or a sibling file |
| `…_the_ui_is_still_loaded_directly_by_the_browser` | two script tags, both naming files that exist on disk byte-for-byte as served; no module type, no import map |

The last is the property principle 6 is actually about, stated positively: **what the browser
receives is what is in the tree.**

## 5. The four UI files, pinned

Here rather than in a file of its own, because it asserts the same thing from the other side: not
only is there no machinery to transform the UI, the UI did not move.

```python
UI_HASHES = {

    "index.html":          "8a2d870f5588eb0f5cced0646d76d08d0258c8746b08e976198e904c18e9699b",
    "style.css":           "3101122e3eeafd38c1f3780048edb8cbd7c4ef814bd04e1dadb29f33e946343c",
```

Byte sizes are recorded beside them, because a size is the figure a reader can check by eye.

A later release **will** change these files and will update this table in the same commit. That is
the point: the change becomes a deliberate, reviewable line in a diff rather than something that
happens while someone is in the file for another reason.
