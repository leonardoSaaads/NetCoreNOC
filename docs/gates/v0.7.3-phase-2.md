## 2. The concurrency invariant test (§4.4)

`tests/test_store_concurrency.py`, **9 tests**, green on the pre-split tree.

This is the one test in the release whose absence would let a real defect through. Every other test
in the suite would pass a `Store` that had been split into several objects with several connections;
the failure mode is data corruption under concurrency, and nothing else drives three domains at
once.

| Test | What it would catch |
|---|---|
| `test_the_connection_property_is_stable` | a `conn` property that builds per access or per mixin |
| `test_exactly_one_connection_is_reachable_from_the_store` | a second `_conn`, or a façade delegating to nested store-like objects |
| `test_exactly_one_lock_is_reachable_from_the_store` | two locks, each caller believing it has exclusive use |
| `test_no_store_method_acquires_the_store_lock` | a new mixin "helpfully" taking the lock — instant deadlock against all three real callers |
| `test_concurrent_writes_from_three_domains_serialise_and_land` | writes from `devices` + `feedback` + `audit_log` under `asyncio.gather`; **one commit from one caller** must make all three durable, which is only true on a shared connection |
| `test_the_audit_chain_survives_concurrent_appends` | a fragmented lock: 24 concurrent appends must produce contiguous ids `1..24` and a chain that re-verifies |
| `test_write_txn_rolls_back_and_leaves_nothing_for_another_caller` | F39's exact failure — an unrelated caller's commit adopting an abandoned mutation |
| `test_write_txn_commits_on_success` | the discipline degenerating into a rollback that never commits |
| `test_write_txn_takes_the_same_lock_the_engine_takes` | the perimeter acquiring a *different* lock from the engine |

### 2.1 Mutation evidence

| Mutation applied to the real tree | Result |
|---|---|
| `Store.__init__`/`open` gain a second `aiosqlite` connection | `test_exactly_one_connection_is_reachable_from_the_store` **FAILED** |
| `Perimeter.write_txn` acquires its own `asyncio.Lock` instead of `store.lock` | `test_write_txn_takes_the_same_lock_the_engine_takes` **FAILED** |
| The concurrent audit appends stop taking `store.lock` | `test_concurrent_writes_from_three_domains_serialise_and_land` **and** `test_the_audit_chain_survives_concurrent_appends` **FAILED** |

All mutations were reverted; `git status src/` is clean.

### 2.2 The F39 regression test needs no editing

`tests/test_api.py::test_f39_a_failed_write_leaves_nothing_to_commit` drives the discipline through
a real HTTP request against a `Store` obtained from the `store` fixture. It touches no module path
and no internal of `Store`, so it exercises the post-split object unchanged. Confirmed again in
Phase 5.

## 3. The layer-dependency test (§5.4)

`tests/test_layers.py`, **13 tests**, green. Parses every module's imports with `ast` and asserts
`MODULE-ARCHITECTURE.md` §1's rule: downward or cross-cutting, never upward.

Confirmed in Gate 0 §6.2 and worth restating: **no test enforced this rule before now.** That is
precisely why the one violation was recorded in v0.7.2 and is only being resolved a release later.

Design points worth naming:

* **The layer table is duplicated from §1 deliberately**, and the duplication is itself asserted —
  `test_every_runtime_module_is_assigned_a_layer` fails on a module nobody has placed, so a new
  module cannot escape the rule by not appearing in the table.
* **Type-only imports are excluded.** `if TYPE_CHECKING:` creates no runtime edge and no cycle, and
  §1 already records `audit.py`/`auth.py` → `store.Store` as tolerated on exactly that ground.
* **`runner.py` and `__main__.py` are classified `http`, not exempted.** §1 says the process entry
  point may legitimately reach up to build the server while the `Engine` may not. An entry point
  that builds an HTTP server *is* a delivery concern, so it belongs at that layer; calling it an
  exemption would claim the rule was bent when in fact the module was misplaced.
* **`EXEMPTIONS` starts with exactly one entry and ends empty.** The guard is installed against the
  unmodified tree, so it necessarily begins holding the violation §1 records — the alternative is
  writing the guard *after* the code it measures, which is the failure mode this phase exists to
  prevent. `test_the_exemption_list_holds_nothing_new` pins it to that single known name so it
  cannot grow while briefly non-empty, and Phase 4 deletes the entry and tightens the assertion to
  emptiness. Build prompt §5.4 asks for "empty **by the end of** this release", which is what this
  is.
* **`test_the_engine_does_not_import_the_http_layer`** states the specific edge this release
  resolves, separately, so it cannot regress quietly.

## 4. `COHESION_EXEMPT` (§5.3, DECISIONS #91)

Added to `tests/test_architecture.py`, currently **empty** — Phase 4 populates it with `engine.py`
once its final size is a measurement rather than a target. The mechanism is built now because Gate 0
§4.1 already settled that it will be needed (425 must-stay method lines).

Five constraints, each with its own test:

| Constraint | Test |
|---|---|
| The reason must cite an invariant **by name** from §1 | `test_every_cohesion_exemption_cites_a_named_invariant` |
| A module may be in `COHESION_EXEMPT` **or** `DEBT_ALLOWLIST`, never both | `test_no_module_is_both_debt_and_cohesion_exempt` |
| Entries carry **no owner and no fix date** — the semantic difference | `test_cohesion_exemptions_carry_no_owner_and_no_fix_date` |
| An exempt module may not **grow** past its recorded count | `test_cohesion_exempt_modules_have_not_grown` |
| At most **two** entries | `test_cohesion_exempt_is_capped` |

Plus `test_cohesion_exempt_names_only_real_modules` and
`test_cohesion_exempt_modules_actually_need_the_exemption`, which guard the guard.

### 4.1 A hole closed in the older guard

`DEBT_ALLOWLIST`'s "may only shrink" was asserted in **one direction only**. `test_allowlist_only_shrinks`
catches an entry that is no longer *needed*; nothing caught a **new** entry, so a contributor could
have added a module and every guard would have stayed green. Build prompt §6 asks that the test
"actually would fail if a module were added" — it would not have. `test_no_module_may_join_the_allowlist`
and `ALLOWLIST_MEMBERSHIP_CEILING` fix that.

### 4.2 Mutation evidence

| Mutation | Result |
|---|---|
| `learn.py` added to `DEBT_ALLOWLIST` with a v0.8.0 owner | `test_no_module_may_join_the_allowlist` **FAILED** (and `test_allowlist_only_shrinks`, since it is under the guard) |
| `COHESION_EXEMPT["store.py"] = "too big for now, v0.7.4 will fix it"` | **three** failures, exactly the three constraints violated: cites no named invariant, also on the debt list, names a release |
