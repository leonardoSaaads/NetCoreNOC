# v0.9.2 — Gate 4: the consumers

Every derived quantity about the evidence now reads tier 2. The reports say which tier each figure
is, and the disagreement between them is the first number printed.

---

## 1. What moved, and what deliberately did not

| Consumer | v0.9.1 read | v0.9.2 reads |
|---|---|---|
| `bias` — corpus-wide `asserted_negative_pairs` | `excluded_count` (tier 1) | **`excluded_reconciled`** |
| `bias` — per-channel `asserted_negatives` | `excluded_count` (tier 1) | **`excluded_reconciled`** |
| `bias` — `unasserted_pairs_in_partial` | `excluded_count` | **`excluded_reconciled`** |
| `bias` — `marked_fraction_tenths`, `asserted_negatives_per_label` | `excluded_count` | **`excluded_reconciled`** |
| `shadow_report` — `asserted_negatives` | `excluded_count` | **`excluded_reconciled`** |
| `bias` — `exclusions_truncated`, `remainder_offered`, `remainder_asserted` | tier 1 | **tier 1, unchanged** — they describe the *report* and the operator's own claim |
| `bias` — `client_reported`, `client_diverged`, `client_truncated` | tier 1 | **tier 1, unchanged** — every one is a statement about the client |
| `learn.penalize` | tier 2 already | **unchanged, byte-identical** |

**The two per-channel and corpus-wide paths are separate code**, in separate SQL, and each had its
own copy of the defect. They are guarded by separate tests
(`test_the_corpus_total_is_derived_from_the_reconciled_count` and
`test_the_per_channel_total_is_derived_independently`) so that neither can be repaired while the
other is quietly reverted.

## 2. The number this release exists to move

`test_the_corpus_total_is_derived_from_the_reconciled_count` drives Gate 0 §1's exact corpus:

| corpus | v0.9.1 total | v0.9.2 total |
|---|---|---|
| 8 honest labels (9-member bags, 2 marked) | 112 | **112** |
| + one label: bag of 4, 600 ids sent (truncated to 512) | −259 984 | **112** |
| + one label: bag of 60, 30 ghost ids marked | −259 084 | **112** |

Neither hostile label asserts a pair, and the total now says so. The disagreement is visible rather
than silent: `reported_vs_reconciled_rows = 2`, `reported_vs_reconciled_marks = 542`,
`client_reported_marks = 558`, `reconciled_marks = 16`.

## 3. The reports make the tier visible

### 3.1 `make bias-report` — the disagreement first

```
-- THE EVIDENCE BOUNDARY (read this first) -------------------
label rows: reported != reconciled               0
  marks that difference accounts for             0
marks the CLIENT reported (untrusted)            1
marks the SERVER reconciled                      1
  of those, derived by migration 0011            0

  A NUMBER THAT DESCRIBES THE EVIDENCE IS DERIVED BY THE SERVER; a
  number that describes the client may be derived from the client. The
  marked ids are what an operator's browser SENT, and until v0.9.2 their
  raw count was multiplied into the asserted-negative total below — so a
  label marking ids that named no member of its bag could move that total
  while asserting nothing at all. The reconciled count is the reported
  set intersected with the server's own bag, computed at the verdict.
  A NON-ZERO FIRST LINE means some label was written by something other
  than the shipped UI. Nothing is corrected on its account: a
  disagreement is evidence about a write path, and repairing the row
  would destroy it.

-- SCOPE OF THE ASSERTION (never averaged) -------------------
  clean   (nothing was hidden)                   0
  checked (restricted, and measured)             0
  unknown (no scope was recorded)                1
marks about members not observable               0
```

`test_the_disagreement_is_the_first_number_the_report_prints` asserts the position, not merely the
presence: the first non-heading line after the banner must be the disagreement.

**One label was corrected while reading this diff.** The third population first printed as *"unknown
(written before 0011)"*, and the frozen fixture immediately showed why that is wrong — the fixture's
own row **is** post-`0011` and reconciled; what it lacks is a resolved scope. The line now reads
*"unknown (no scope was recorded)"* and the prose names both causes. A label that misdescribes its
own population would have been a small lie in the one report a v0.10.0 reader will trust.

### 3.2 `make shadow-report` — whose measurement each figure is

```
  ADDITIONAL OBSERVATIONS — not floors, and not substituted for one:
  split AND mixed bags      (no floor)        20
  asserted negative pairs     (server)         0
  client-reported marks       (client)         0
```

The middle column names the tier. This report is where a floor is most likely to be promoted in
v0.10.0, so the distinction has to be legible at the point of reading rather than in a document.

## 4. `dataset_stats` splits `feedback_member` by source

```
feedback_member          7      # still printed: the row cost is real either way
feedback_member.server   5      # the bag the engine wrote — authoritative
feedback_member.client   2      # what the browser said it rendered — untrusted
```

A client can inflate the second by up to `MAX_CLIENT_MEMBERS` (512) per label, and v0.9.1 summed the
two silently, so an operator sizing retention could not see which half was growing. The total is
unchanged, so nothing an operator already read has gone away.

## 5. Determinism, and the two frozen gates

Both reports are byte-stable across two runs and are gated on a fixture:

* `tests/test_bias.py::test_the_report_is_deterministic_across_two_runs` — green;
* `tests/test_bias.py::test_the_report_matches_the_frozen_expectation` — **re-frozen by hand**, the
  full diff read before replacing `tests/fixtures/bias-report.txt`;
* `tests/test_shadow.py::test_the_report_matches_the_frozen_expectation` — **re-frozen by hand**,
  `tests/fixtures/shadow-report.txt`.

**The diff was read, not accepted.** `ASSERTED NEGATIVE PAIRS` on the bias fixture is **2 before and
2 after** — the figure does not move on an honest corpus, which is exactly the claim Gate 0 §6 made
and is the strongest evidence that the repair is prospective. What changed is that the report now
says more about the same number.

## 6. Two modules split, because the guard is the guard

| Module | Before | After | Seam |
|---|---|---|---|
| `shadow_report.py` | **400** (no headroom) | 185 | reader / renderer → `shadow_render.py` (255) |
| `bias.py` | 367 | 273 | subject → `bias_labels.py` (182) |

Neither guard was raised; `MAX_MODULE_LINES` is still 400, `DEBT_ALLOWLIST` is still empty, and
`COHESION_EXEMPT` still holds `engine.py` alone at 580. ADR #139 records both splits, including the
one hard part: `bias.py` imports `bias_labels` and never the reverse, which is why the shared
primitives moved into the new module rather than staying in the older one.

`tests/test_layers.py::LAYER_OF` gains both. `tests/test_challenger.py` gains `shadow_render.py` in
**both** of its enumerations — a split of an already-allowed module, and adding it to the second
list *widens* what the never-reaches-the-champion guard covers.
