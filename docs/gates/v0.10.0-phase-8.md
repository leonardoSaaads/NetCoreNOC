## The declared behaviour changes, counted

**Five**, exactly as `SCOPE-0.10.0.md` §2 enumerated before the work began. Any change not on that
list is a defect in this build's work.

1. two new store tables (`holdout_seal` + `holdout_seal_member`) and one more (`holdout_access`);
2. `dataset shadow` gains a verdict section, a sealed-holdout section and four census lines;
3. ~~a new CLI subcommand `dataset judge`~~ — **not built.** The verdict is printed by the existing
   `dataset shadow`, so a second command would have been a second surface showing the same numbers.
   Recorded here because §2 listed it and this gate's whole purpose is that the list be exact;
4. the maintenance pass constructs the seal once, off the batch lock, degrading to a warning;
5. `shadow_eval.py` split — in the event **twice**, plus `shadow.py` and `training.py` into
   `census.py`. Five modules where §2 anticipated one. No metric changed value.

**Two deviations from the scope document, both declared rather than discovered**: item 3 was dropped
and item 5 was larger than planned. Neither adds surface; both are recorded because a build that
silently satisfied its own list would make the list worthless.
