## 2. Two guards whose scope was a string

Both bounded to tests and guards. **Zero production changes**, as required.

### 2.1 The perimeter's fail-open branch had no test

`if permission is None or permission not in capabilities:` — inverting that to `is not None and`
makes an **undeclared `/api` path permitted**, and the v0.9.1 suite stayed 960/960 green. The
declaration gate makes the state unreachable through `create_app`, which is exactly why the branch
is defence in depth and exactly why nothing was watching it: every route the app can serve is
declared, so no test that goes through the app can reach the `permission is None` arm.

`tests/test_guard_scope.py::test_an_undeclared_api_path_is_refused_even_holding_every_capability`
constructs a `Perimeter` directly — the documented second instantiation path, already used by
`tests/test_store_concurrency.py` — and drives it with a request carrying **no resolved route**, so
`_route_path` falls back to the raw URL path.

Three things make it mean something:

* the principal is an **admin**, holding every capability in the product, so a refusal cannot be
  explained by a missing capability;
* the premises are asserted rather than assumed — `permission_for("GET", UNDECLARED)` really is
  `None` and the control path really is declared, so a typo cannot make the test vacuous;
* **the session is opened on `time.time()`**, the clock `resolve_identity` reads. This is Appendix
  B's two-clocks trap in miniature: a session minted at a fixture epoch would be long expired by
  that clock, all three probes would fail with 401, and the test would prove nothing while looking
  like a pass. The test says so in its own docstring.

**Control:** a declared route, the same principal, the same object, the same session — which must be
allowed. Recorded red: demonstrations §14 (`L1`).

### 2.2 `_SKIP_DIRS` excluded `.venv` by name

A virtualenv created in the repository under any other name — `env`, `venv`, a CI cache — put every
third-party `README.md` through the broken-link checker: thousands of files nobody here wrote,
failing a guard about this repository's own documentation.

The repair identifies a virtualenv by **`pyvenv.cfg`**, which every one has and no hand-written
directory does, so the whole class goes rather than one more name being added to a list.

**This guard's first version was itself defective, and the ledger caught it.** It called
`_is_inside_venv` directly, so reverting the *walk* left it green — a test measuring a helper that
nothing was obliged to call. `_markdown_files_under(root)` now takes the root as a parameter, the
guard drives the walk over a fixture, and the widening is demonstrated by construction. Recorded
red: demonstrations §15 (`L2`).

## 3. The capability-table invariant: assessed, and left as a ROADMAP line

The build prompt asks whether the **editor tier** should get the structural protection the **admin**
tier has — `scorer.write` demoted from `admin` refuses at import; `label.write` demoted from `editor`
to `viewer` fails exactly one test out of 960 — and says to make it a ROADMAP line if it costs more
than an import-time assertion.

**It costs more.** The candidate invariant is *"every mutating route's capability ranks at or above
`editor`, with the self-service pair enumerated as the exception"*, and the exception list is where
the cost is: `password.change` is a mutating route a `viewer` must hold, and so is `logout`. An
import-time assertion would therefore need a maintained enumeration of exceptions, which is a second
table that can drift from the first — and a structural guard whose exception list is wrong is worse
than an expectation test, because it looks stronger.

**ROADMAP line, not a change in this release.** Ambiguity about scope resolves to a ROADMAP line
(§11 of the build prompt), and this release does not touch `rbac/`.
