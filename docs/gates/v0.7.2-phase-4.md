## 2. The parity proof, after every step

Run after each of the nine moves, and again at the end:

```
BODY PARITY OK      43/43 handler bodies hash identically to v0.7.1
DECORATOR PARITY OK 43/43 decorators differ only by @app. -> @route.
```

Not one handler signature, docstring or body changed a character across a 1 752-line split. The
mechanism is the mandatory rebinding block: each `register()` binds `ctx`'s fields to the local
names the handlers already use, so the text below is identical and the *scope* it resolves in is
reconstructed rather than the *code* rewritten.

`tests/test_architecture.py::test_route_table_order_is_unchanged` passed at every step: the nine
`register()` calls run in v0.7.1 declaration order, so the 48-entry route table — and every
path-matching precedence in it — is byte-identical.

## 3. What the guards caught, in order

A refactor this size is only as good as what fails while it happens. Four things did:

1. **A deleted decorator (Phase 3).** Removing the `situation_in_scope`/`audit_scope_denial` block
   took `@app.post("/api/situations/{sid}/feedback")` with it. No handler text changed, so no body
   hash could see it; the route-order test named the exact index.
2. **`apisource` refused `governance_cache.py`.** The moment a module appeared that nobody had told
   the source-scanning helper about, the four v0.7.1 text guards failed rather than quietly
   scanning less. Exactly the behaviour it was written for.
3. **The F39 body-slicer ran off the end of the corpus.** Slicing "from this decorator to the next"
   has no next for the last handler. Fixed with a decorator-shaped terminator in `api_source()`, so
   the final slice is as tight as every other and the helper no longer depends on which module
   sorts last.
4. **A dropped `import time` in `routes_audit.py`.** `prune_audit` calls `time.time()`; `ruff`
   (F821) and `mypy` both caught it before the test run did.

Every one was found by a gate that existed before the step that broke it. None required judgement
to notice.

## 5. Test-side changes in this phase

1. `tests/test_structure.py::SUBMODULES` gains the fifteen `api.*` modules, so each is proved to
   resolve from the **installed** package — the F12 guarantee the `src/` layout bought, extended
   one level down.
2. A new `test_the_api_package_holds_exactly_the_expected_modules`: a module added to the package
   must also be added to `SUBMODULES` and to `apisource.MODULE_ORDER`, or the build fails. That is
   what stops the two guards silently drifting apart from the tree.
3. `tests/apisource.py` gains the corpus terminator (§3.3).
4. `DEBT_ALLOWLIST` loses `api/app.py`.

`vulture_allowlist.py`'s 33 `# unused function (netcorenoc/api.py:NNN)` comments were rewritten to
name the module that now holds each handler. Vulture matches on the **names**, so the allowlist
never stopped working; the comments were pointing at a file that no longer held what they said.
