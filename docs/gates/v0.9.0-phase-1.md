# v0.9.0 — Gate 1: the pre-registration

**No model has been trained.** No fit exists, no coefficient exists, no metric over a model exists,
and the tree contains no training code. That is the gate's first and most important claim, and the
commit history is its evidence: this commit precedes every line of `challenger.py` and `training.py`.

### What it fixes, before any result could influence it

| | |
|---|---|
| **Hypotheses** | H1 the champion's conditioned agreement (descriptive, no model); H2 feasibility, **conditional on the floors**; H3 whether the derivation policy matters |
| **Derivation policies** | **A** (`split` → all pairs negative) and **B** (`split` discarded). C and D out of scope, with reasons; D's size-weighting half applied to both |
| **Features** | four plus an intercept — `decay` (τ₀ = 30 s, **fixed, not learned**), `class_affinity`, `entity_affinity`, `same_oid_root`. **Five free parameters**, which is what the events-per-variable floor is computed against |
| **Excluded features** | every key; `incumbent_linked`; `storm`; the epochs — each with its reason |
| **Training population** | all labelled bags, weighted `1/(pairs in bag)` then class-balanced. **Mixed-bag-only** retained as a diagnostic population; **unweighted** run as a pre-registered contrast |
| **Primary metrics** | `over_merge_rate` and `under_merge_rate` from `eval/metrics.py` at **partition** level, plus `split_bag_intact_rate` as a separately named third quantity |
| **Truth** | the human verdict at bag granularity. Never `incumbent_linked` |
| **Secondary** | calibration at **bag** level: five-bin reliability curve and Brier score |
| **Forbidden** | pairwise accuracy as a quality metric, in any section, under any name |
| **Held out** | by **incident and time** — merge-aware incident, ordered by earliest label, last third held out. Explicitly *not* v0.10.0's split |
| **Intervals** | cluster bootstrap over **incidents**, 1 000 resamples, fixed seed, 2.5/97.5 percentile; `n/a` below 10 incidents |
| **Floors** | `split` ≥ 50, mixed ≥ 20, operators ≥ 3, top share ≤ 60 %, incidents ≥ 30, policies ≥ 2 |
| **Hardening** | `resolved = the more demanding of (project floor, deployment policy)`, `meta` key `config.evidence_floors`, absent by default |
| **Projection** | formula fixed, and `undefined` where the label span is zero — an extrapolation from a single instant is a fabricated number and this release does not print one |
| **Skew** | pre-registered expectation **0.0000 %**, compared with `==`, not a tolerance |
| **Conclusions** | **ten** outcomes, §7.1 … §7.10, each with what the release will say |
| **Stopping rules** | one fit per policy; no metric added after a result; no floor changed; the file is not edited |

### The floor the plan already knows it will fail

§5.2 sets `split` bags ≥ **50** — ten per free parameter, five free parameters. Phase 0 §2 measured
**13** in the richest corpus this repository can construct, and **5** mixed bags of which **1** was a
`split`. The plan was written with that measurement already in hand, which is why §7.1 —
*insufficiency* — is written first, in the most detail, and is the branch the build report is
instructed to lead with.

Registering a floor one already knows will fail is the opposite of gaming: the temptation a
pre-registration exists to remove is setting the bar where the result happens to land.
