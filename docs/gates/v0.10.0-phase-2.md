# v0.10.0 — Gate 2: incident identity

**The first v0.10.0 code.** Its commit cites the ratified plan's hash,
`c03aef0181554c0c71482e57d03677f25964c3a5ac20a7bf1b1d74bff1ba1e01`.

Everything downstream groups by incident — the estimator, the seal, every clustered bootstrap — so
this is built and proved first.

---

## 1. What changed

`store/shadow.py` resolved incidents with `COALESCE(s.merged_into, f.situation_id)`, **twice**, in
two separate SQL statements. That is **one hop**, and `merge_situations(sid, other)` marks the source
merged into `sid` where `sid` can itself later be merged, so one hop is not incident identity.

| | before | after |
|---|---|---|
| where identity is decided | two SQL `COALESCE`s | `incidents.resolve_all`, once |
| how deep it follows | one hop | to a fixed point |
| a cycle | undetectable | flagged, resolved to `min(cycle)` |
| an absurd chain | undetectable | flagged **separately** |
| the one-hop answer | the only answer | reported beside the new one |
| pre-v0.8.0 merges | unmeasured | counted and printed |

**New modules**, both engine-layer and both registered in `tests/test_layers.py` before they were
written:

* **`incidents.py`** — pure arithmetic over a mapping. No store, no lock, no I/O, no clock. It
  imports nothing from this package, so it cannot violate any layer direction.
* **`census.py`** — *what the labelled corpus contains*. Split out of `shadow.py`, which reached
  **417 of its 400-line budget** when the resolution arrived. **Split, not exempted**, and the seam
  is real: `shadow.py` owns the shadow *lifecycle*, `census.py` owns *what the corpus holds* —
  which every floor, every estimate and the seal all ask and none of them owned.

`training.py` also crossed the guard (400 → 408) when `CorpusStats` gained two fields, so
`CorpusStats` moved to `census.py`, whose entire subject it is. It is re-exported from `training`
because `assess()` takes one and every caller since v0.9.0 has imported it from there.

**Final sizes — nothing over 400, nothing added to `DEBT_ALLOWLIST`, `COHESION_EXEMPT` unchanged:**

```
shadow.py      350    training.py    381    census.py      138    incidents.py   182
store/shadow.py 262
```

## 2. One implementation, and it is structural rather than conventional

The store now returns the merge **edges**; the arithmetic happens once. SQLite could have followed
the chain with a recursive CTE, and then there would have been **two** implementations — one in
Python for the seal and one in SQL for the estimator — which is exactly how the two come to disagree
about which incidents exist **with nothing going red**.

`incident` is written onto a row in exactly one place, `incidents.stamp`. A consumer that skips it
has **no `incident` key at all** and fails loudly, rather than quietly reading a one-hop answer.
That is not a happy accident; it is why the SQL stopped emitting the column.

`census.corpus_stats(bags, identity)` takes the identity map as a **required** argument. Optional
would let a caller obtain a `CorpusStats` whose `incidents` came from somewhere else, and a caller
that has not resolved identity now cannot call the function at all.

**Two call sites, both proved by parse rather than by reading:**

* `shadow.Shadow.train` — the slow loop that fits the challenger;
* `shadow_report.collect` — the report.

`test_both_consumers_resolve_identity_through_the_one_function` walks each function's AST and
requires a call to `resolve_identity`. It carries its own vacuity check — and that check **fired
during development**, rejecting a wrong function name (`shadow.py::run`, which does not exist)
rather than passing over an empty list.

### The two consumers still on one hop, named rather than quietly fixed

`agreement.py`'s bag query and `bias.py`'s `distinct_incidents` also compute identity with a
`COALESCE`. **They are not changed**, and this is a scope decision rather than an oversight:
Workstream 1 names `store/shadow.py`, Part VII rule 7 forbids a fix inside a move, and both feed
byte-frozen v0.9.0 reports. They are named here, in `incidents.py`'s docstring, and in the ROADMAP
so a later release converts them deliberately. On this corpus all four agree at 37, so nothing they
report is currently wrong — which is exactly the condition under which a silent divergence would
later appear.
