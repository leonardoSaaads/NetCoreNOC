## What S0 actually removed

The debt was **not** the duplicated loop — it was the duplicated *numbers*.
`preview.PREVIEW_WINDOW_S` and `PREVIEW_MAX_CANDIDATES` were independent literals that happened to
equal `correlate.WINDOW_S` and `MAX_CANDIDATES`. Both are now **aliases** (`is`-identical, asserted),
and `correlate.select_candidates()` is the single implementation of the rule.

The one genuine difference between the callers is named as a parameter rather than papered over:
the engine's deque carries **tombstones** (alarms cleared or re-activated, dropped from `index` in
O(1) but still physically present), so it passes `index` as the liveness set; preview replays an
immutable snapshot where every entry is live, so it passes `None`.

Two tests, at two levels:

- **behavioural** — `preview.partition()` reproduces the engine's **actual situation partition**,
  member for member, on a hand-built stream straddling the ~21 s cold-start link radius and the
  120 s window edge, and over hypothesis-generated streams;
- **structural** — both callers go through `select_candidates`, asserted over their source, and
  preview's bounds are the engine's objects. A parity test alone is what v0.6.0 could have had; it
  proves agreement *today*. This proves the two cannot drift.

`make eval` is byte-identical across the change, which is the real proof that a structural
extraction inside the correlator changed no behaviour.

## Two problems the tests found (both fixed, not accommodated)

1. **A second decision site, in the code I had just written.** `scope_for()` in `api.py` began as
   `if principal.role == "admin" or ...` — the admin-never-scoped short-circuit. That is exactly the
   role comparison F28 exists to forbid: an authorization-relevant rule living outside the resolver,
   invisible to the generated matrix. `test_f28_no_role_comparison_outside_rbac` failed on it. Fixed
   by moving the rule to `shaping.is_scopable()`, next to the resolver that enforces it; `api.py`
   now contains no role literal at all, and the short-circuit is only an optimisation because
   `visible_nes()` re-applies the same rule regardless.

2. **A per-row lock inside a listing.** The first `/api/situations` scope filter took `store.lock`
   once per returned situation to fetch its members — correct, but a round trip per row. Replaced
   with `store.situation_member_nes()`, one query for the whole page, returning a **list** rather
   than a set so the honest visible/redacted counts survive.

## Empty-policy parity, as an equality

The parity gate is not a spot check. `test_empty_policy_resolves_exactly_to_the_v060_behaviour`
asserts, for **every** (role × capability) pair:

```python
(capability in rbac.resolve_capabilities(role, None, None)) == rbac.role_allows(role, capability)
```

`role_allows` is v0.6.0's function, kept precisely so the parity gate has an independent oracle to
compare the resolver against (this is why it appears in `vulture_allowlist.py` — nothing in `src/`
calls it any more, and that is deliberate). This equality is what lets
`test_rbac.py::test_authorization_matrix` keep generating its expectations from `role_allows` and
still describe what the server enforces.

A **second** matrix now runs with a policy **active**
(`test_authorization_matrix_with_a_policy_active`), regenerating expectations from the resolver over
every route × role, plus an inverse sweep proving that granting every role every capability opens no
route the ceiling forbids.
