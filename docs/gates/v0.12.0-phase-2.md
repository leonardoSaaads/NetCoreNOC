# v0.12.0 — Gate 2: the harness

**Gate 2 asks five things**, and the fifth is the one that decides whether this release is worth
anything: the harness must execute `ui/app.js` in a DOM; runs must be deterministic across two
invocations and two processes; it must be invoked by `make qa`; **the skip path must itself be
tested**; and the gate must record the number of DOM tests **executed**, not collected.

---

## 0. The headline

```
$ make dom
18 passed, 1321 deselected in 3.51s
```

**Eighteen DOM tests executed.** Before this release the number was zero, and Phase 0 §2.3 showed
what zero costs: an `app.js` no JavaScript engine can parse left all 1302 tests green.

If that line had read `18 skipped`, this release would have failed. §4 is why it cannot read that
without saying so.

---

## 1. What was built

| File | Lines | What it is |
|---|---:|---|
| `tests/domharness/dom.mjs` | 405 | the DOM: nodes, events with bubbling, `classList`, `dataset`, a bounded selector engine, form-control `value` semantics, and `innerHTML` as a real parse |
| `tests/domharness/html.mjs` | 135 | a small, strict HTML parser — for `index.html`, and to back `innerHTML` |
| `tests/domharness/env.mjs` | 265 | the sandbox: `node:vm` context, the four declared substitutions, `settle()` |
| `tests/domharness/run.mjs` | 309 | the scenarios, one JSON object per invocation |
| `tests/domharness/selftest.mjs` | 227 | the DOM's own conformance suite |
| `tests/domdriver.py` | 178 | availability, invocation, and the proof-of-execution rule |
| `tests/uifixtures.py` | 148 | **real server responses**, captured per role |

**Stdlib-only Node. No `npm install`, no `package.json`, no `node_modules`, no lockfile, no network.**
`test_the_harness_tree_holds_no_installed_dependency` asserts every `import` in the harness resolves
to `node:*` or to a sibling file, and nothing else. ADR #167 has the argument.

## 2. It executes `ui/app.js`, and proves it

`node:vm` evaluates the file in a fresh context per run. All 52 `function` declarations become
reachable properties of that context — `renderSituations`, `applyUpdate`, `renderDetail`,
`prunePanels`, `esc` — which is what lets a test drive the gestures directly rather than through a
simulated browser.

**The proof rule.** Every scenario returns `proof.escaped`: the output of *`app.js`'s own `esc()`*
called inside the sandbox after evaluation.

```
app.js's esc('<a href="x">')  ->  &lt;a href=&quot;x&quot;&gt;
```

`domdriver.run_scenario` **raises** if that string is absent or wrong. A harness that stubbed
everything and ran nothing cannot produce it. This is the anti-vacuity rule as code, and it is
itself tested — `test_a_scenario_that_did_not_execute_app_js_is_refused_rather_than_returned`, which
carries no `dom` marker precisely because it must hold on a machine with no Node at all.

## 3. Determinism, across two invocations and two processes

```
$ python -c "… run_scenario('selfTest') twice …"
selfTest identical across two processes: True
```

`test_two_runs_in_two_processes_produce_identical_results` compares `json.dumps(..., sort_keys=True)`
of two separate `node` invocations of the same scenario.

Every source of drift is **pinned rather than tolerated**:

| Source | Treatment |
|---|---|
| wall clock | `Date.now()` fixed at `1_700_000_000_000` |
| locale / timezone in rendered dates | `toLocaleString` and friends replaced with ISO-derived output; subprocess runs under `TZ=UTC`, `LC_ALL=C` |
| polling and SSE reconnection | `setInterval` / `setTimeout` register and **never fire** |
| network | recording doubles; no socket, no port, no server |
| ambient environment | the subprocess gets `PATH`, `TZ`, `LC_ALL` and nothing else |

```
$ node tests/domharness/run.mjs environment
{"node":"v22.22.2","platform":"linux","tz":null}
```

`tz` is `null` there because that invocation was a bare shell command; through `domdriver` it is
`"UTC"`, which `test_the_detected_runtime_is_reportable_for_the_gate` asserts. The difference is the
point — the pinning is done by the driver, not assumed from the environment.

**What this does not prove**: determinism across Node *majors*. Two majors could in principle order
object keys differently. That is why the detected version is recorded rather than assumed, and why
ADR #166 registers a floor with a prohibition on version-specific APIs rather than a pin.

## 4. The skip path, driven — the most important section here

**A green suite over zero executed DOM tests is worse than no harness, because it reads like
coverage.** Four tests run *everywhere*, Node or no Node, and they exist entirely to make that
outcome impossible to reach quietly.

| Test | Drives | Asserts |
|---|---|---|
| `…_reports_a_reason_naming_the_requirement_when_node_is_absent` | `availability(path="")` | not `ok`; the reason names **Node.js**, the floor, and that it is a **TEST dependency** |
| `…_refuses_a_node_below_the_floor` | a stand-in reporting `v18.20.4` | not `ok`; the **version is named** in the refusal |
| `…_accepts_the_floor_itself` | the same stand-in reporting `v22.0.0` | `ok` — so the refusal above is about the version, not about the mechanism |
| `…_node_absent_is_a_skip_and_never_a_silent_pass` | the mark itself | it is a `skipif` with exactly one condition and a **non-empty reason** |

### 4.1 The skip path was broken, and its own test found it

`availability()` was first written as:

```python
exe = node or shutil.which("node", path=path or os.environ.get("PATH", ""))
```

`path=""` is falsy, so it fell through to the ambient `PATH` — and the unavailable branch became
**unreachable from a test**. The first run of the test above failed with
`assert True is False … Availability(ok=True, reason='Node v22.22.2')`.

That is F51's class in miniature: a guard whose scope silently widens. It was found by the very
test whose purpose is to drive that branch, which is the argument for writing skip-path tests at
all. The repair distinguishes "not provided" (`None`) from "search nowhere" (`""`), and the
docstring records why.

## 5. Wired into `make qa`

The harness tests are ordinary pytest files, so `make qa` → `test` → pytest collects them like any
others. What could still go wrong is the *reporting*, so `make dom` exists as a named command:

```make
dom:
	$(PYTHON) -m pytest -q -m dom -p no:cacheprovider
```

The `dom` marker is registered in `pyproject.toml` with its reason. On a machine with Node this
prints `N passed`; without, `N skipped`. **That difference is the whole point, and no gate may quote
a collected count.**

## 6. The instrument's own conformance suite

```
$ node tests/domharness/run.mjs selfTest
passed 17 failed 0
```

A hand-written DOM is a fresh way to measure nothing. `selftest.mjs` asserts the semantics the
captured invariants actually depend on — `append` **moves** an already-parented node, `removeChild`
**detaches** without destroying listeners, a cleared-then-reappended node keeps its identity and its
handlers, `classList.toggle` honours its force argument, the pruning selector
`.panel[data-panel="audit"]` resolves, `select.value` defaults to the first option.

**It found a real defect in the instrument.** `an unrecognised selector throws rather than matching
nothing` failed: `querySelectorAll` validated each step *inside* the walk, so when the first step
matched nothing the loop body never ran and `div > span` returned `[]` instead of raising. A guard
that stops guarding once its input is empty — F51 again, in the harness this time. The repair
validates every step before walking.

## 7. What the harness does not do, recorded before anything green is reported

* **No layout, of any kind.** `getBoundingClientRect()` returns zeroes. No CSS, no cascade, no
  paint, no focus model. Nothing here can characterise anything visual.
* **d3 is a recording double** (ADR #167), so `updateGraph` and `loadTimeline` — two of the largest
  render paths in the file — execute against a stub. The double **throws** on any d3 API it does not
  implement rather than returning `undefined`; it caught `sim.force("link").links(…)` during
  construction, which a lenient double would have swallowed and left `updateGraph` silently
  half-executed.
* **It is not a browser and not jsdom.** It is a bounded implementation whose fidelity rests on §6
  and on every invariant having been demonstrated **red** under an injected defect
  (`v0.12.0-guard-demonstrations.md`) — not on any claim made in a docstring.
