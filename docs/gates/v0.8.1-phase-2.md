# v0.8.1 — Gate 2: F44

## The change

One file, `src/netcorenoc/store/retention.py`. Two statements changed:

```diff
-            await self.conn.execute(
-                f"DELETE FROM feedback WHERE situation_id IN ({marks})",
-                gone,
-            )
-            await self.conn.execute(
-                f"DELETE FROM situation WHERE id IN ({marks})",
-                gone,
-            )
+            # No `DELETE FROM feedback` here. See the docstring: that line was F44.
+            cur = await self.conn.execute(
+                f"DELETE FROM situation WHERE id IN ({marks}) "
+                "AND id NOT IN (SELECT situation_id FROM feedback) RETURNING id",
+                gone,
+            )
+            counts["situations"] = len(list(await cur.fetchall()))
```

`situation_alarm` and `link` are still deleted for **every** aged situation, labelled or not, and
the cleared alarms behind them are still collected by the statement that follows. Only the one
`situation` row is retained, and only when a label points at it.

`counts["situations"]` now reports what was **collected** rather than what was **eligible**. A
labelled situation that was retained must not be reported as pruned; the sweep's count is a
statement about the sweep.

The docstring carries the reasoning, so the next reader of `prune()` learns why an obvious-looking
cascade is deliberately absent rather than re-adding it.

## Every reader of `feedback.situation_id`, enumerated and shown safe

`grep -rn 'FROM feedback\|INTO feedback\|UPDATE feedback\|JOIN feedback' src/netcorenoc/` returns
27 statements. Exactly **three** read `situation_id`; the other 24 read `verdict`, `principal_ref`,
`member_count`, `created_at`, `coverage`, `capture_provenance`, `acquisition_channel`,
`client_*`, `scope_*` or `situation_opened_at`, none of which depend on the situation existing.

| Reader | Statement | Why it is safe |
|---|---|---|
| `bias.py:120` | `SELECT COUNT(DISTINCT COALESCE(s.merged_into, f.situation_id)) FROM feedback f LEFT JOIN situation s ON s.id = f.situation_id` | **`LEFT JOIN`** — a missing situation yields `NULL` for `s.merged_into` and `COALESCE` falls through to `f.situation_id`. Correct before and after. |
| `bias.py:164` | `SELECT COUNT(DISTINCT situation_id) FROM feedback` | Reads the column; joins nothing. |
| `store/retention.py:63` | `... AND id NOT IN (SELECT situation_id FROM feedback)` | The new statement. Reads the column to decide retention; no join. |
| `store/feedback.py:37` | `SELECT 1 FROM situation WHERE id=?` | Write path, at **label time**, before the insert. The situation necessarily exists then — this is the 404 check, not a read of a stored reference. |

Additionally, `feedback_member` carries `alarm_id` with **no** `REFERENCES` clause
(`0008_feedback_dataset.sql:235`), so the bag survives the collection of the alarms it names — which
is what makes retaining only the `situation` row sufficient.

Note that after this release `feedback.situation_id` is **still not** a dangling reference: the
restricting foreign key remains, and DECISIONS #109 keeps it satisfied by retention rather than by
weakening the constraint. The brief anticipated a dangle; the schema does not allow one, and the
constraint is left doing its job.

## Assertions changed in existing tests, with justification

One, in `tests/test_store.py::test_prune_bounds_growth`:

```diff
     s_old = await store.create_situation(ts=100.0)
-    await store.add_feedback(s_old, "confirm", ts=100.0)
     await store.close_situation(s_old, ts=200.0)
```

**Justification.** The test labelled its aged situation and then asserted `counts["situations"] == 1`
and `situation_detail(s_old) is None` — that is, it asserted that a human verdict's situation is
collected, which is precisely the behaviour F44 says is wrong. The test's actual subject is bounded
growth, and it still tests exactly that, on an unlabelled situation. The labelled case is not
dropped: it moves to `test_f44_*`, which asserts the **opposite** outcome. No assertion was weakened
— one fixture line moved so that the two behaviours are tested where they belong.
