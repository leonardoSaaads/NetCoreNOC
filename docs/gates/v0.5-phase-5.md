## Gate 5 criteria

- **Full `make qa` green.** `ruff` + `ruff format --check`, `mypy --strict` (65 source files),
  `vulture`, `pytest` **328 passed** with **95.02 % coverage** (≥ 85 %), and `make eval`
  **byte-identical** to the phase-0 reference. `make security` (bandit + pip-audit) clean — no
  known vulnerabilities.
- **Every F15+ finding has a passing test.** F15/F16/F18 → `tests/test_deploy.py`; F17 and the new
  served path → `tests/test_security_txt.py`; F19 → `tests/test_workflows.py`; F12/F13 and the
  vendored licence → `tests/test_supply_chain.py`.
- **The SHA-pin lint passes.** `tests/test_workflows.py` asserts every active `uses:` is a 40-char
  commit SHA, every workflow declares `permissions:`, and no active publishing step exists.
- **`make release-check` passes.** `pyproject.toml`, `src/netcorenoc/__init__.py`, and the
  CHANGELOG heading all read **0.5.0**.
- **Quickstart via `docker compose up`.** `docker compose config` validates (Compose v5.1.1); the
  Docker daemon is unavailable in the build sandbox, so the image build / `compose up` is the
  maintainer's reproducible step — the wheel the image `pip install`s was verified (Phases 2–4) to
  ship the full UI, migrations, `security.txt`, and `d3.LICENSE` with the d3 checksum intact. This
  matches the delivery model (no gate depends on a pipeline, daemon, or account).
- **Upgrade from a live v0.4.0 DB verified.** A database was created by **actual v0.4.0 code** (a
  git worktree at the v0.4.0 commit, installed in its own venv: 3 audit rows + a device + a class,
  `schema_version=4`, chain OK). Opened under **v0.5.0**:
  - `schema_version` stays 4 (= latest) — **no migration ran**;
  - data intact (3 audit rows, device `10.0.0.9`, the class);
  - `python -m netcorenoc audit verify` reports **chain OK with the identical final hash**
    (`e26ec519…`) — tamper-evidence preserved across the version boundary;
  - the legacy `OPTICORR_DB` / `OPTICORR_TRAP_PORT` aliases **still warn-and-work**, the warning
    now naming **v0.6.0** (DECISIONS #39).

## Release

- Version bumped to **0.5.0** across the three sources (release-check green).
- Tag `v0.5.0` applied to the release commit.
- The build report (`docs/releases/BUILD-REPORT-0.5.md`) records what changed, the layout diff,
  the security review, the v0.6.0 groundwork, decisions #39–#42, the deferred ROADMAP items, and
  the honest caveats (single-node compose is not HA; `CAP_NET_BIND_SERVICE` is a deliberate trade;
  deployment hardening is asserted, image-built by the maintainer; the `OPTICORR_*` window
  extension prolongs a legacy path).

## Summary of the release

v0.5.0 makes NetCoreNOC legible (docs index + repo map), installable (`docker compose up`), and
contributable (scaffolding + disclosure policy), and specifies v0.6.0 — **without changing the
running correlator at all**. 45 new tests (structure/link, security.txt, workflow-hygiene,
deployment-hardening) lock in the new organization surfaces; the engine, schema, API, UI, and eval
outputs are byte-for-byte v0.4.0. Zero new runtime dependencies; one dev-only (`build`).
