# v0.12.0 — Gate 1: scope and decisions

**Gate 1 asks one thing: does the scope name what is *not* being done, and why?** A scope that lists
only inclusions is a wish list; the exclusions are where a release either holds its shape or loses
it.

Artefacts: [`../scope/SCOPE-0.12.0.md`](../scope/SCOPE-0.12.0.md) and seven decisions,
[`../adr/DECISIONS.md`](../adr/DECISIONS.md) **#166–#172**, continuing from #165 and renumbering
nothing.

---

## 1. The exclusions, and the reason each one is a refusal rather than an oversight

`SCOPE-0.12.0.md` §2 is the table. What follows is why the four that could plausibly have gone the
other way did not.

### 1.1 Not one byte of `ui/`

The release exists because the UI is untested. The obvious next move — while the harness is fresh
and the file is open — is to fix something in it. **Every such fix would be untestable by the very
instrument being built**, because a characterisation test written against a UI the test itself
modified characterises nothing.

It is asserted rather than intended:
`tests/test_build_step.py::test_not_one_byte_of_the_shipped_ui_changed` pins all four files by
SHA-256 and three of them by byte count.

The harness did find something (§3 below). It is a ROADMAP line.

### 1.2 No jsdom, no Playwright, no npm — ADR #167

This is the exclusion that most needed arguing, because (b) and (c) are what any other project would
do. The argument is short: **both require `npm install`**, and principle 6 is *"a static UI with no
build step and no npm"*. Introducing a `package.json` in order to build the guard against
`package.json` is incoherent, and a harness that needs a network fetch to run is a harness that
**skips** — which Part XI names as the most likely way this release fails.

The cost of the alternative is stated in the ADR rather than hidden: a hand-written DOM is a fresh
way to measure nothing, and the answer is `selftest.mjs` plus a red demonstration for every
invariant — not a claim in a docstring.

### 1.3 No framework vendored — ADR #171

v0.12.0 **chooses**; v0.13.0 vendors. The recommendation is Preact + htm, and the decisive reason is
recorded as a security one rather than an ergonomic one: a component that declares the capability it
requires makes the capability guard **structural**, and Phase 0 measured exactly how weak the
textual form is.

Preact + htm over Lit on one ground that is about this project specifically: **htm needs no compile
step**, whereas Lit's ergonomic form is decorators plus TypeScript — a build step wearing a
different hat.

### 1.4 Archetypes deferred, the draft retagged — ADR #170

Not dropped, and the distinction matters. The draft's own §0 opens with the arithmetic that defers
it: v0.11.0's gate refused with `asserting_bags = 0` against a floor of 50, and per-archetype
weights split an already-insufficient corpus `k` ways. Deleting a document whose analysis is correct
would discard the reasoning and invite someone to redo it worse.

**The mechanical consequences, all of them, in one commit** — because a half-finished supersession
is what `tests/test_documentation.py` exists to catch (and it did catch this one mid-edit):

| Artefact | Before | After |
|---|---|---|
| release table | 6 rows, v0.8.0–v0.13.0 | 8 rows, v0.8.0–v0.15.0 |
| `ARCHETYPES-0.12-DRAFT.md` | claim v0.12.0, 6 element tags | claim **v0.15.0**, 6 element tags |
| `SCORER-PLUGINS-0.13-DRAFT.md` | claim v0.13.0, 6 element tags | claim **v0.14.0**, 6 element tags |
| `docs/README.md` | 2 `v0.13.0: planned` | 2 **`v0.14.0: planned`** |
| `test_documentation.py` membership pin | `== 6` | **`== 8`**, with the reason inline |

```
$ .venv/bin/python -m pytest -q --no-header tests/test_documentation.py tests/test_structure.py
99 passed in 0.85s
```

**The guard fired mid-edit, which is the evidence that it is real.** With the table resequenced and
the drafts not yet retagged, `test_the_release_table_parses` failed with
`expected v0.8.0…v0.13.0, parsed [… 'v0.14.0', 'v0.15.0' …]`. The membership pin is not decoration:
moving it is a deliberate line in a diff with an ADR beside it, which is what it has just been.

## 2. The two documents whose filenames now misstate their release

`ARCHETYPES-0.12-DRAFT.md` governs v0.15.0. `ROADMAP-0.8-TO-0.13.md` governs to v0.15.0. Neither was
renamed.

The convention elsewhere is filename-equals-target (DECISIONS #93 renamed nothing but resequenced in
place, and the file was *already* called `-0.13-`). The reason for not renaming here is specific:
both paths are cited by name across `gates/`, `security/` and `releases/`, which are **records and
are never rewritten to agree with a later decision** — that is `test_documentation.py`'s own
`HISTORICAL_DIRS`. A rename would leave those citations pointing at nothing.

So the cost is paid in the other currency: each document's **own header** now states what it
governs, and the rename is a ROADMAP line rather than a silent follow-up. ADR #170 records the
alternative that was considered and why it was not taken.

## 3. What the harness found, and why it is not in this release

Anti-overengineering rule 9: *no fix inside a move* — *"including anything the harness reveals about
the current UI, which is the most likely place this rule is tested."* It was tested immediately.

**The panel loaders have no capability check of their own.** Driving `renderPanel("audit")` directly
as a viewer — what a deep link or a client-side router would do — issues **no request**, but the
mechanism is not a capability check: `prunePanels` has removed the container, so `clear(null)`
throws a `TypeError` before `api(...)` is reached.

The outcome is correct. The mechanism is incidental. And v0.13.0 introduces routing, which is
exactly when an accidental defence stops being available.

Three things happened to it, and a fix to `ui/app.js` was not one of them:

1. a ROADMAP line under *Found while building v0.12.0*;
2. a constraint in `../architecture/UI-0.13-DRAFT.md` §11;
3. **a test that asserts the behaviour and names the mechanism in its own docstring** —
   `test_a_panel_reached_without_its_capability_still_issues_no_request` asserts both that no
   request is issued *and* that every loader threw, so if a later change made a loader return
   normally the test fails and the docstring stops being able to mislead anyone.

Item 3 is the part worth noting. The honest options were "record it and move on" or "record it and
make the recording load-bearing". The second costs nothing extra and means the note cannot rot.
