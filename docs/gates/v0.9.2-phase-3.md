# v0.9.2 — Gate 3: reconciliation and interpretability

The write path now derives every quantity about the evidence from the server's own bag. Five steps,
and the gate's three conditions are the three things that must **not** have changed.

---

## 1. The five steps

| Step | What landed | Where |
|---|---|---|
| **S1** | the reconciliation at write time, reusing the resolved scope | `labels.py::_assertion`, `api/perimeter.py::hidden_member_ids`, `api/routes_operate.py::label_context` |
| **S2** | the non-vacuous property test; `0010`'s comment corrected | `tests/test_evidence_boundary.py` §1, `migrations/0010_partial_split.sql` (comment only) |
| **S3** | the scope-of-marking record, `NULL` for pre-`0011` rows | `labels.py::LabelScope.hidden_members`, `labels.py::_assertion` |
| **S4** | store-layer and schema-layer enforcement | `store/feedback.py::_check_reconciled`, migration `0011`'s two `CHECK`s |
| **S5** | the maintenance drift check — reports, audits nothing, never corrects | `store/feedback.py::reconciliation_drift`, `capture.py::verify_evidence` |

### The one expression that matters

```python
reported = len(exclusion.alarm_ids)
marked = exclusion.marked_positions(bag)
excluded_count = reported or None  # tier 1 — unchanged, byte for byte
excluded_reconciled = len(marked) if reported else None  # tier 2
```

`excluded_reconciled` is **exactly `len(Exclusion.marked_positions(bag))`** — the same value
`learn.penalize` has always resolved. The report and the learner now read one expression, so they
agree by construction rather than by a coincidence somebody has to maintain. Asserted directly by
`test_the_reconciled_count_is_exactly_what_penalize_uses`.

### One read, not two

`Perimeter.redacted_member_count` became `Perimeter.hidden_member_ids`, returning the set rather
than its size (ADR #137). `label_context` calls it once and derives both scope facts from it, so
`scope_redacted_members` and `excluded_reconciled_out_of_scope` cannot come from two snapshots that
disagree. The unrestricted short-circuit is unchanged: an appliance with no scope policy returns an
empty set without touching the database.

### Where S5's call site is, and why it is not in `engine.py`

`Engine.maintenance` may not gain a line — `engine.py` is `COHESION_EXEMPT` at a ceiling equal to
its exact size, and this release does not touch it. `capture.prune` is the one method that pass
already calls on the dataset, on the `PRUNE_EVERY_TICKS` cadence the verification wants, inside the
lock it must hold. `prune`'s docstring now says it is the maintenance-time dataset pass — *two
bounds, then one verification* — rather than leaving the second job to be discovered.

**The drift check writes no audit row** (ADR #138). The catalog is frozen and this release adds no
action to it; the operator warning is the alert and `dataset bias` is the durable record, because it
re-derives the count from the child tables on every run rather than holding it in one process's
memory.

## 4. Tier 3, and the difference between zero and unknown

| Situation | `scope_redacted_members` | `excluded_reconciled_out_of_scope` |
|---|---|---|
| unrestricted scope | 0 | **0** — nothing was hidden, so no mark could be blind |
| restricted, all marks visible | 3 | **0** — a real zero, and a strong statement |
| restricted, one mark on a hidden member | 3 | **1** |
| restricted, every reconciled mark hidden | 4 | **4** |
| **no scope resolved at all** | `NULL` | **`NULL`** — unknown, and never 0 |

The last row is the fabrication guard at the level of one cell
(`test_a_label_with_no_resolved_scope_records_unknown_not_zero`): a verdict recorded through a path
that resolved no scope cannot say whether the marks were observable, and writing `0` would be
inventing an observation — the same error as backfilling the column, one row at a time.

`test_the_hidden_set_and_the_hidden_count_come_from_one_read` asserts the structural consequence of
ADR #137: the blind count can never exceed the redacted count, because the blind marks are a subset
of the hidden members **by construction**.

## 5. Enforcement at four layers

| Layer | Mechanism | Test |
|---|---|---|
| request model | bounded at `MAX_CLIENT_MEMBERS`, deliberately **not** validating | `tests/test_partial_split.py` §4 |
| domain | `_assertion` computes the intersection; it never accepts a count | §3 above |
| store | `_check_reconciled` raises before the `UPDATE` | `test_the_store_layer_refuses_a_reconciled_count_that_is_not_one` |
| schema | two `CHECK` constraints, enforced on `INSERT` and `UPDATE` | `docs/gates/v0.9.2-phase-2.md` §2 |
| maintenance | `reconciliation_drift` recomputes and reports | §6 below |

A violation should be **unreachable** and is still **enforced**, so one that reaches the database is
unambiguous evidence of a bug in a layer above. The store-layer refusal is safe because every caller
sits inside `record_label`'s `try`: a violation degrades **capture**, losing the annotation and never
the operator's verdict, the response, its status or its timing.

---

## 6. The drift check reports and does not correct

`test_a_corrupted_row_is_reported_by_maintenance_and_not_corrected` corrupts a row directly in the
database — the only way to reach that state, since every write path computes the count — and then:

* **control**: a healthy corpus reports no drift and raises no warning;
* the sweep finds `stored=5, recomputed=2`;
* the operator warning says **`NOTHING HAS BEEN CORRECTED`**;
* **and the row still reads 5**, which is the assertion that makes the test about the *decision*
  rather than about the query.

Two more hold the fail-safe: a verification that raises degrades capture and never the maintenance
pass behind it, and a disabled capture verifies nothing.

---

## 7. Retention, on one clock

`test_the_reconciled_count_survives_a_prune_pass_and_the_scope_record_with_it`. `TS`, the verdict at
`TS + 10 s`, the prune at `TS + 20 days` with a 7-day retention. After the pass:

* `alarm` is empty — asserted, so the pass demonstrably collected something;
* **no marked id resolves to an NE any more** — the input tier 3 would have needed for a later join
  is gone, which is exactly why it was computed eagerly;
* the label row is **identical** before and after, both derived quantities included;
* `reconciliation_drift()` is still empty, so tier 2 remains *recomputable* from surviving evidence
  — which is what makes the backfill derivation rather than invention.
