### 3.2 What v0.7.5 hands v0.8.0 — new §0

Records that v0.7.5 delivers **a click the operator meant**, and that this is a precondition for the
dataset and **not** a substitute for the membership fingerprint. The table separating the two is
deliberate: v0.7.5 fixed *the operator's click reaching the card they were reading* and *the
operator being told the card is held*; it did **not** address *which membership the verdict was
about*, which is §2.2 and belongs to v0.8.0. Nobody should read v0.7.5 as having solved label
provenance.

One consequence recorded that the build prompt did not ask for and that follows from its own
reasoning: `feedback` rows written **before** v0.7.5 were acquired over the defective path, so an
unknowable fraction of them are clicks the operator did not mean. If they are carried into the
dataset the bias report must **count them separately** — they are the one population whose noise is
known to be non-random, and averaging them with later rows hides exactly that.

### 3.3 The columns question — left open, deliberately — new §6a

Group A (must extend the `feedback` write path: membership fingerprint, scope fingerprint, label
latency) and Group B (must be new tables: one row per evaluated pair, one row per alarm observation)
are settled, because their cardinality settles them. **Group C is stated as four open questions for
v0.8.0's own Phase 0** — synchronous versus queued pair writes, per-trap versus per-activation
observations, fingerprint as columns versus a child table, and retention per sink.

Each depends on a measurement that release will take. *"Ambiguity about a v0.8.0 design decision
resolves to the v0.8.0 build decides"*, and saying so **is** the deliverable — a specification that
pre-empts a measurement is one that will be wrong in a way nobody re-checks.
