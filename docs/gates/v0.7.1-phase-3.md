## 2. Two design corrections made during implementation, and why

Recorded here rather than quietly absorbed, because both changed what was built from what was
specified.

**The zero-match selector warning became a static "can never match" check.** The build prompt asked
`scope_policy_errors()` to warn on a selector matching **zero** NEs. Built that way, it rejected
`203.0.113.0/24` on an appliance that has not yet discovered a device in that range — and
`scope_policy_errors()` results become a **400**, so it blocked a legitimate forward-looking policy.
That directly contradicts DECISIONS #57, where selectors are resolved against the live inventory on
every request *precisely because* NetCoreNOC discovers NEs continuously. The check is therefore
static: a selector whose literal characters cannot appear in an address (`core-*`, `POP-SUL`) can
match nothing now or ever, which is exactly the dead label glob the migration aid exists to catch.
No false positives on CIDRs or on address globs like `10.0.*`, and no inventory read — so
`scope_policy_errors()` keeps its v0.7.0 signature. Appended to DECISIONS #66.

**`situation_in_scope()` owns the unrestricted short-circuit.** The first cut had each handler check
`if not scope.unrestricted:` before calling the helper, which left the helper's own guard
unreachable and put the decision in two places. The helper now returns before touching the database
when the scope is unrestricted, so an appliance with no policy still pays nothing and there is one
place the question is answered.

## 3. `add_feedback` returns a `FeedbackResult`, and three call sites adapted

`store.add_feedback` returned a bare `bool` ("the situation exists"). F36 needs two facts that must
not be conflated: whether the situation **exists** (a 404 if not) and whether this
`(situation, verdict)` was **newly inserted** (only a genuine insert may apply a learning effect).
It now returns a `NamedTuple`, matching the project's idiom for contract types (DECISIONS #52).

Three existing assertions read the old contract and were adapted — mechanically, asserting the same
facts through the new shape, not weakened:

| Test | Before | After |
|---|---|---|
| `test_store.py::test_feedback_requires_existing_situation` | `assert not await store.add_feedback(999, …)` | `== (False, False)`, plus new assertions that a repeat is `(True, False)` and a correction is `(True, True)` |
| `test_scenarios.py::test_confirm_feedback_reinforces` | `assert await engine.apply_feedback(…)` | `assert (await engine.apply_feedback(…)).exists` |
| `test_scenarios.py::test_split_feedback_penalizes` | same | same |

**A `NamedTuple` is always truthy, so the old `assert not …` form would have silently passed.** It
did not: both call sites failed loudly, which is why they are listed here. Every remaining caller is
new code that reads `.exists` / `.inserted` explicitly.

## 4. The F37 test repairs — the one assertion exception, justified

The project rule is "the change is the path only; never an assertion". F37 is an explicit exception
(DECISIONS #70) because the *status code for a nonexistent target* changed. Each test's **intent**
is preserved exactly:

| Test | Its actual subject | Repair |
|---|---|---|
| `test_abuse.py::test_csrf_valid_cookie_mutation_succeeds` | the CSRF gate | given a real device; still asserts `200` |
| `test_abuse.py::test_bearer_token_mutation_needs_no_csrf_header` | bearer tokens bypass CSRF | given a real device; still asserts `200` |
| `test_perf.py::test_ingestion_lossless_with_concurrent_authed_audited_api` | API latency under ingest load | device seeded **before** the loop; still asserts `200` |

Two predicted repairs turned out not to be needed, which is worth recording because Phase 0 flagged
them: `test_rbac.py::test_authorization_matrix` asserts `status not in (401, 403)` for an authorized
role, and 404 satisfies that — correctly, since the matrix tests authorization, not existence; and
`test_audit.py` drives the fixture first, so its device exists.

`test_perf.py` was **passing** before the seed was added. It was repaired anyway because whether
device 1 exists at the first loop iteration is a race against the engine, and the F37 check turned
that race into a flake risk that this release introduced.

Two more assertions changed, both the direct behaviour change of F35 and covered by DECISIONS #66:
`test_scope_selector_forms` cases `core-*` and `lab-*` now expect `set()` — a label glob selects
nothing. A new `10.0.*` case was added alongside them so the surviving address-glob form stays
covered.
