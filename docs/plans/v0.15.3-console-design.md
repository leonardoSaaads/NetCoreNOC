# v0.15.3 — the console, designed

<!-- release-claim: v0.15.3 = console-design -->

**Measurements and open questions. Not a design.** Rewritten after v0.15.2, which repaired what was
*broken* in the console and deliberately chose nothing about what it *looks like* (decision #223).
Every number below was taken on the v0.15.2 tree, most of them in a browser at two widths as three
roles, and several of them contradict what this file said before.

## 3. The four questions v0.15.3 has to answer

### 3.1 Is there a type scale, and what is it?

Measured: five sizes — `--fs-xs: 11px`, `sm: 12`, `md: 13`, `lg: 16`, `xl: 21` — and the ratios
between them are 1.09, 1.08, 1.23, 1.31. That is not a scale; it is five numbers that were each
chosen for one thing. `--fs-md` also changes to 14 px under `data-density="comfortable"`, so the
gap to `--fs-lg` closes to 1.14 in one of the two densities and nothing else moves with it.

**The question is not "which scale":** it is whether the density switch scales the *whole* ramp or
one step of it, because today it does the second and the result is a different set of relationships
in each density.

### 3.2 Are the seventeen glyphs a family?

`◎ ◉ ⬡ ▤ ▢ ≡ ✓ ▦ ⚖ ◍ ⚿ ⚙ ∿ ⛨ ⚑ ⛓ ◐` plus `◈` (the brand mark), `▥` (density), `◑ ◒` (theme) and
`« »`. Decision #221 kept them and said why: they render, they are `aria-hidden` beside a text
label in every one of their call sites, and replacing seventeen glyphs with seventeen hand-drawn
paths was the whole visual budget of a repair release.

They are still **not a family**: they come from four Unicode blocks and render at whatever weight
the user's font stack decides. #221's own reading is that inline SVG in one shared module is the
right answer; what moved was the *when*, not the *what*. The open question is the one a designer
answers: what does a NetCoreNOC icon look like, at 16 px, in both themes.

### 3.3 How much prose belongs in a screen?

Words of explanatory English a screen **renders** — the `hint` prop and `class="hint"` paragraphs,
comments excluded, counted the same way for every view so the figures are comparable:

| screen | words |
|---|---|
| `views/overview.js` | 125 |
| `views/promotion.js` | 119 |
| `views/model.js` | 110 |
| `views/facts.js` | 95 |
| **all seventeen views** | **1 383** |

*(The earlier figure in `v0.15.2-console.md` §5 — "`settings.js` alone carries about 146 words" —
was counted by an unstated method and does not reproduce; `settings.js` is not in the top four by
this one. State the method with the number, or the next release cannot tell whether prose grew.)*

Some of it is load-bearing and this project is right to be proud of it: an empty state that says
what will fill the screen is the product's first sentence, and a hint that says *"a rate with no
window is a number nobody can act on"* is why the window is printed. Some of it is a paragraph
where a link would do. **A design that deletes all of it would be worse than the current state**,
which is why this is a question and not a defect.

### 3.4 What does a NOC wall look like?

Every measurement in this repository was taken at 1440x900 and 390x844. The product's own
description is a dark console for an operator at 3 a.m., and the palette says so — *"dark is the
default because a NOC wall is dark"*. Nothing has ever been looked at on one: not at 2560 px, not
at 4 m, not at the angle a wall-mounted screen is actually seen from. That is the largest untested
claim in the console.

## 4. What is still true and still unowned

* **The graph is not keyboard-operable** and has no screen-reader equivalent beyond its label. It
  says so on screen. Everything it shows is on Entities as text.
* **No screen-reader testing has ever been performed**, and no contrast measurement. v0.15.2's live
  pass was one browser on one OS.
* **The graph is the one screen no test executes** — the DOM harness substitutes a recording double
  for d3. F77 is what that cost: three of four nodes off the canvas, invisible to a green suite.
  A design release that changes the graph should decide whether that stays acceptable.
* **`/api/stats` has no CPU, memory or uptime**, so no screen can show them. Adding them is a route
  change with a declaration and a capability, and #222 chose not to.

## 5. The one thing this document asks v0.15.3 to do first

**Look at the product on the hardware it is for.** Every defect v0.15.2 fixed in the console was
found by opening it, and none of them by reading it — a panel empty on seventeen screens, a label
clipped 51 px past the edge, a node three times the collision radius, a spinner that did not spin.
The suite was green through all of it, twice, at 1576 tests.
